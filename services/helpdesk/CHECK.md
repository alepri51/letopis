# Helpdesk — проверка в браузере (chrome-devtools-mcp)

Стенд: `docker compose -f services/compose.yaml up --build`, сервис — http://127.0.0.1:8083 (демо с нуля — `FRESH=1`).
Проверка проходит автономно через chrome-devtools-mcp; пароли, коды из писем и коды TOTP вводятся в поля формы.
Код TOTP считается из секрета, который показывает страница «Безопасность»: `totpCode(секрет)` из `letopis`.

| № | Шаг | Ожидаемо |
|---|---|---|
| 1 | Вход: `boss@sever.ru` и неверный пароль | «Неверный логин или пароль» |

Интерфейс — React и блоки shadcnblocks (`web/`), сервер — JSON API и `/mcp`. Сценарий `node scenario.mjs` проходит
то же через HTTP и настоящий клиент MCP.

Последний прогон — 30.10.2026, локальный сервис на 8093: «Под капотом» шагов 10 и 15 (взять заявку, ответ клиенту,
внутренняя заметка; обращение руководителя от имени клиента) проверено в Chrome (CLI chrome-devtools-mcp,
`--isolated`) с вводом паролей и текстов; сценарий — 49 из 49. Позже в тот же день, тот же сервис на 8093 (тестовая
база 15433), Chrome (CLI, `--isolated`, две вкладки в своих контекстах, вход агента и руководителя с вводом логина и
пароля): шаг 19 — сессия агента до 15:28, вход `SERVICE`, «агент видит открытых заявок: 6»; агент — `fetch` со
страницы с токеном и `credentials: 'omit'`: `letopis_write` перевёл HD-2 в «ждёт клиента» (версия 2); «Под капотом» —
«Сессия для ИИ-агента» (`sessionFor`, `switch`, `credentials()` → `PASSWORD`) и «MCP агента: tools/call letopis_write»
с версией `Ticket` HD-2 (изменено `status`) и сигналом `Ticket`; в «Истории» HD-2 версия 2 — Ирина Агентова без
исполнителя, `mcp: letopis_write` (версия 1 — клиент, исполнитель «сервис helpdesk»); вторая сессия: «Проверить»,
«Погасить», «Проверить» — «401: сессия погашена…»; токен первой — 200 до «Погасить» и 401 после, список сессий пуст.
Руководитель, работая от имени агента, получил «Сначала вернитесь к себе…» (409). Найдено и исправлено: запись
помощника через MCP не попадала в «Под капотом» — поток ответа дочитывался после конца действия; в Chrome («реши
HD-1» вводом в поле, «Разрешить») теперь видны версия `Ticket` HD-1 и сигнал `Ticket`. Шаг 20 — в консоли только два
намеренных 401, в сети — 409 у руководителя, без 5xx. После правки предела — третьей вкладкой: три сессии в списке,
четвёртая — «Уже 3 действующие сессии агента…» (409, единственная запись в консоли), «Погасить» у всех трёх — список
пуст, новая сессия снова выдаётся. Сценарий — 59 из 59, два прогона подряд.

Прогон 29.10.2026, локальный сервис на 8093: шаги 1–17 и 20 пройдены в Chrome через chrome-devtools-mcp
(его CLI с `--isolated`: общий профиль MCP занимала другая сессия) с вводом паролей, кода из демо-почты и кода TOTP;
ключ интеграции проверен `curl` по примеру из окна ключа. Найдено и исправлено в ходе проверки: роль в письме
приглашения была по-английски, окно заявки закрывалось при отказе в удалении, у помощника сроки были в UTC,
причина «от имени» читалась с ошибкой согласования, страница входа писала в консоль ответ 401 от `/api/me`
(то же — у салона и кошелька). После ревью безопасности — шаг 18 в контейнере 8083. Сценарий — 47 из 47.
