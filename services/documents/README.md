# Документы с аудитом — сервис-пример letopis

Договоры с полной историей: каждая правка — новая версия с автором и причиной. Что показывает сервис:

- черновик подписывают — он становится договором. Ключ и класс строки в letopis неизменны, а класс входит в id (v5),
  поэтому договор — новый объект: одна транзакция `db.begin()` создаёт `Contract` с данными черновика и удаляет
  `Draft`. Лента версий договора собирает версии обоих id — id черновика даёт `db.idOf('Draft', { number })`;
- документ можно открыть на любой момент ползунком (`asOf`);
- удаление — с предпросмотром: `delete()` без подтверждения ничего не удаляет, а показывает, что удалится. Удалённое
  попадает в корзину (`withDeleted()`): оттуда его можно вернуть (`restore`) с прежним id. Подписанного черновика в
  корзине нет: он не удалён, а стал договором. Его `restore` и новый черновик с номером договора дали бы два документа
  с одним номером — сервис отвечает 409 и 422;
- журнал хранит каждую версию целиком;
- архив старых договоров залит при подготовке дома первой заливкой с историей — мастер-ключом, командой
  `letopis load --initial --with-history --agent "перенос архива"`: у каждого договора четыре версии из прежней системы
  со своими датами 2025 года;
- загрузка (`letopis load`) и обслуживание (`letopis maintain`) — инструменты мастер-ключа: страница «Обслуживание»
  показывает команды, а сервису с одним пропуском они недоступны.

Интерфейс собран из блоков **shadcnblocks** (`login1`, `navbar1`, `stats8`, `changelog1`) и компонентов shadcn/ui.
Описание со схемами — http://127.0.0.1:8080/services/documents.

Панель «Под капотом» показывает, что сделало действие: цепочки letopis и запросы к базе (`onQuery`), версии, которые
оно записало (из журнала `log`: класс, номер документа, номер версии `rev`, вид операции `op`, причина, изменённые
поля), и сигналы об изменении классов, в которые оно записало (`flushSignals()`; только имя класса). У подписания там
видны версия `create` нового договора и надгробие черновика — версия `delete`: объекта нет, история есть.
Код панели общий для четырёх сервисов — `services/shared/`.

Демо-входы (юридическая фирма «Право и Дело» — квартира дома `v2.documents`): юрист `lawyer@pravo.ru` /
`Pravo-2026!`, руководитель `head@pravo.ru` / `Head-2026!`.

## Модель, дом, матрица и вход

`src/models.mjs`: контрагент `Party` и семейство документов `Doc` с потомками `Draft` (черновик) и `Contract`
(договор).

- **Дом** строит мастер-ключ — строка подключения администратора PostgreSQL — один раз: `src/setup.mjs` вызывает
  `setup(ADMIN_DSN, 'documents', { models })`. Модель — общие классы дома: их пишет консьерж, повтор меняет только то,
  что изменилось. `setup()` отдаёт **пропуск** — строку, в которой дом и ключ консьержа; повтор отдаёт тот же пропуск.
  Затем подготовка по этому пропуску заводит квартиру фирмы (`db.createTenant`; повтор отвечает `exists`) и, пока в ней
  нет документов, заливает архив (`src/archive.mjs`) командой `letopis load` мастер-ключом: в только что построенный
  дом — первой заливкой (`--initial`: одна транзакция, индексы и триггеры — после загрузки), с историей
  (`--with-history`: строка — версия со своими `$rev` и `$at`) и исполнителем «перенос архива» (`--agent`). Автор версий
  загрузки — System. Квартира заведена сейчас — засев демо: консьерж зовёт руководителя (роль `owner`) и юриста (роль
  `staff`), ссылки получает почтальон-заглушка (`services/shared/postman.mjs`), и подготовка принимает приглашения за
  демо-сотрудников с известными паролями (`db.accept(token, { password, name })`, помощник `seedResident`). Это засев
  демо-данных, а не регистрация. `FRESH=1` — демо с нуля: подготовка сносит дом (`demolish`) и строит его заново,
  прежний пропуск гаснет.
- **Сервис знает только пропуск** (`LETOPIS_PASS`): `connect(pass, { postman })` — консьерж. При старте он никого не
  зовёт. Людей фирмы — id аккаунта, имя, роли — сервис берёт из `me.acl.people()` консьержа в квартире: по ним он
  подписывает авторов версий в истории и называет должность; email вошедшего — `db.contactOf(аккаунт)`.
- **Матрица** квартиры: роли `owner` всё разрешает правило хозяина от `createTenant`; роли `staff` чтение, правку и
  удаление документов и контрагентов даёт правило `db.in(фирма).acl.grant({ role: 'staff', … })`. Его пишет консьерж
  при каждом старте: повтор строк не заводит, а снять или поменять правило консьержа юрист не может. Без него юристу не
  было бы видно ничего: правило по умолчанию дома — «нельзя».
- **Вход** — ключом сотрудника: `db.open({ email, password })`. Токен сессии — в cookie (`HttpOnly`), каждый
  запрос открывает корень квартиры по нему (`db.resume(token)`), поэтому перезапуск сервиса вход не сбрасывает.
  «Выйти» — `me.close()`: сессия гаснет в базе.
- **Демо-черновики** сервис пишет при первом запуске, пока черновиков нет, — от имени людей фирмы
  (`db.as(аккаунт, фирма)`): автор — человек, исполнитель (`agent`) — сервис.

## Запуск в Docker

```sh
docker compose -f services/compose.yaml up --build documents   # http://127.0.0.1:8084
```

Вместе с сервисом поднимутся база `pg` и шаг подготовки `documents-setup`: он строит дом мастер-ключом и кладёт
пропуск в том `passes`, откуда его берёт сервис.

## Запуск руками, без Docker

1. База: `docker compose -f services/compose.yaml up -d pg` или своя — мастер-ключ в `ADMIN_DSN`.
2. `services/documents/run-local.sh` — соберёт библиотеку, поставит зависимости, соберёт интерфейс, подготовит дом и
   запустит сервис с одним пропуском (`FRESH=1` — дом с нуля). В PowerShell — те же шаги:
   ```powershell
   cd lib; npm ci; npm run build; cd ..\services\documents
   npm install; cd web; npm ci; npm run build; cd ..
   $env:ADMIN_DSN = 'postgres://postgres:guide@127.0.0.1:15440/letopis'
   $env:LETOPIS_PASS = (node src/setup.mjs) -replace '^LETOPIS_PASS=', ''   # дом и пропуск
   Remove-Item Env:ADMIN_DSN                                                 # сервису мастер-ключ не нужен
   node src/server.mjs
   ```
3. Откройте http://127.0.0.1:8084 (порт задаёт `PORT`). Интерфейс с горячей перезагрузкой: `cd web && npm run dev`,
   порт 5184.

Переменные сервиса: `LETOPIS_PASS` — пропуск, `PORT` (8084), `HOST` (127.0.0.1). Подготовки (`src/setup.mjs`):
`ADMIN_DSN` — мастер-ключ, `HOUSE` — имя дома (по умолчанию `documents`), `FRESH=1` — дом с нуля.

## Проверки

- `ADMIN_DSN=… node services/documents/scenario.mjs` — «день работы» через JSON API: вход ключом, архив первой
  заливки (15 объектов, 51 версия, даты 2025 года) и черновики демо, черновик, конфликт версии, подписание (договор —
  новый объект, черновик удалён той же транзакцией), лента версий обоих id, машина времени — и на архивном договоре,
  отказ вернуть подписанный черновик, корзина и восстановление, сессия, которой сервис не знал (`db.resume`), и выход.
  Дом свой (`documents_scenario`, имя — `HOUSE`): сценарий строит его заново (с заливкой архива) и в конце сносит.
- `services/documents/CHECK.md` — проверка в браузере по шагам.
