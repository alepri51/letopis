# Салон записи — проверка в браузере (chrome-devtools-mcp)

Стенд поднимает `docker compose -f services/compose.yaml up --build`, салон открывается на http://127.0.0.1:8081.
Проверка — на свежем стенде: `docker compose -f services/compose.yaml down -v`, затем `up --build` (том базы один на все
сервисы — данные прошлых прогонов меняют ожидаемое).
Проверка идёт без участия человека, через chrome-devtools-mcp. Email и пароли вводятся в поля формы.
Сессия по cookie — токен letopis: перезапуск сервиса (`docker compose -f services/compose.yaml restart salon`) вход не
сбрасывает (шаг 16).

| № | Шаг | Ожидаемо |
|---|---|---|
| 1 | Открыть `/login`, ввести `admin@lokony.ru` и неверный пароль, «Войти» | сообщение «Неверный email или пароль», страница входа остаётся |
| 2 | Ввести `admin@lokony.ru` / `Lokony-2026!`, «Войти» | расписание «Локонов»: мастера Анна и Олег; в меню — «Расписание», «Прайс», «Отчёт дня» и «Живое обновление включено»; cookie `sid` — `HttpOnly` |
| 3 | Открыть вторую вкладку с тем же адресом | то же расписание |
| 4 | В первой вкладке: «Записать» у свободного слота, в диалоге выбрать услугу, ввести имя и телефон клиента, «Записать» | уведомление «… записан(а) на …», ячейка стала зелёной. «Под капотом»: `db.begin`, `lock`, `create`, `commit` и запросы к базе; версии `Customer` и `booking` (`rev`, `create`, причина «бронь с сайта», изменённые поля и концы `Staff →`, `Item →`…); сигналы `booking` и `Customer` |
| 5 | Во второй вкладке, без перезагрузки | бронь появилась сама (подписка → SSE) |
| 6 | Из второй вкладки отправить запросом со страницы бронь на тот же слот (`POST /api/book`) — так поступила бы вкладка, которая ещё не узнала о брони | ответ 409 «Этот слот уже занят — его только что забронировали.», новой брони нет |
| 7 | «Перенести» у брони: в диалоге выбрать час (если нужно — и другого мастера), «Перенести» | уведомление «…: бронь перенесена на …»; бронь на новом месте, прежний слот свободен, в списке «Отменённые в этот день» её нет; во второй вкладке бронь переехала сама. «Под капотом»: `db.begin`, `lock` (при переносе к другому мастеру — «обоих, в порядке id»), `create` новой брони, `delete` прежней, `commit`; две версии `booking` с причиной «перенос брони» — `create` с новым временем и `delete` с прежним; сигнал `booking` |
| 8 | Отправить запросом со страницы перенос брони на час, где у мастера уже есть бронь (`POST /api/bookings/:id/move`): диалог занятых часов не предлагает | ответ 409 «Этот слот уже занят — перенести туда нельзя.», бронь осталась на месте |
| 9 | «История» у перенесённой брони | версии одного id — новой брони: последняя — `create` с новым временем и причиной «перенос брони»; версий прежнего слота в ней нет (у него своя история, последняя версия — `delete` «перенос брони») |
| 10 | «Отменить» у брони | бронь перешла в список «Отменённые в этот день» |
| 11 | «История» у отменённой брони | последние версии: `create` («бронь с сайта» или «перенос брони»), затем `delete` («отмена клиентом») |
| 12 | «Вернуть» | бронь снова в расписании, в списке отменённых её нет |
| 13 | «Прайс»: ввести цену услуги, «Сохранить»; затем «Сохранить» ещё раз с той же ценой | уведомление «…: цена создана» (если цена уже была — «…: цена заменена»), у цены — значок версии `v…`; повтор — «…: цена та же — новой версии нет». «Под капотом»: `upsert` и `$upsert`, версия `price` «базовая: … ₽» с причиной «правка прайса», сигнал `price`; у повтора версий нет |
| 14 | «Прайс списком»: поправить цены в списке (строка — «услуга; цена»), «Загрузить списком» | уведомление «Прайс загружен: новых …, обновлено …, без изменений …», в таблице новые цены. «Под капотом»: `db.begin`, `upsert` каждой услуги, `tr.commit()`, отчёт загрузки, версии `price`, сигнал `price` |
| 15 | Добавить в список строку с услугой не из каталога («Массаж спины; 3000»), «Загрузить списком» | «Прайс не загружен: строка N: услуги «Массаж спины» нет в каталоге салона», цены прежние |
| 16 | Перезапустить сервис (`docker compose -f services/compose.yaml restart salon`), затем обновить вкладку | расписание «Локонов» без нового входа: сервис открыл сессию по cookie (`db.resume`); подписка снова «Живое обновление включено» |
| 17 | «Отчёт дня», затем ввести в поле «День» другой день | брони по мастерам и итог «Всего за …» — столько же, сколько броней в расписании; у другого дня — свои цифры. «Под капотом»: запись «Отчёт дня …» и запрос `rows` по классу `booking` |
| 18 | Выйти, войти `admin@lastochka.ru` / `Lastochka-2026!` | расписание «Ласточки»: броней «Локонов» не видно; на экране «Прайс» — только услуги «Ласточки». Вторая вкладка (шаг 3) после выхода сама перезагрузилась (сервис закрыл поток событий вместе с сессией): в ней страница входа или расписание «Ласточки» с шапкой «Ласточки» — не данные «Ласточки» под шапкой «Локонов» |
| 19 | Консоль обеих вкладок | в консоли — только намеренные отказы шагов 1 (401), 6 и 8 (409) и 15 (422), других ошибок и предупреждений нет; в сети нет ответов 5xx |

Интерфейс — React и shadcn/ui (`web/`), сервис — JSON API. Сценарий `node scenario.mjs` проверяет то же через API
(вход ключом, истёкший токен, сессию, которой сервис не знал, и выход — тоже).

Прогона в браузере на нынешней версии ещё не было: сценарий `scenario.mjs` пройден целиком на PostgreSQL 18 (свой дом,
в конце снесён).
