# Примеры letopis

Исполняемые примеры документации. Каждый файл `<глава>/<NN>-<имя>.ts` — самостоятельный скрипт: его можно
запустить сам по себе, а раннер прогоняет все примеры и пишет снимки их вывода. Сайт `guide/` примеры и снимки
только читает: встраивает в страницы и запускает в песочнице. Файлы здесь написаны через обёртку `example()` и запускаются раннером; программу, которую можно скопировать в свой проект как есть, берите со страницы сайта — там тот же код без обёртки.

## Что где

| Путь | Что это |
|---|---|
| `<глава>/<NN>-<имя>.ts` | пример: `export default example({ title, models, steps })`; id примера — `<глава>/<NN>-<имя>` |
| `hello/01-hello.ts` | «Hello, world!» — дом, квартира, жилец и первый объект в одном шаге |
| `_shared/` | общие помощники примеров: `example.ts` (каркас шагов), `postman.ts` (почтальон-заглушка: ящик `mail`, `postman`, `lastLetter`, `inviteAndAccept`), `shop.ts` (модель магазина), `race.ts`, `proxy.ts`, `cli.ts`, `cli-npx.ts`, `diagram.ts` |
| `_runner/` | раннер: `prepare.ts` (подготовка дома), `runner.ts` (прогон и снимок), `program.ts` (самостоятельная программа отдельным процессом), `direct.ts` (запуск одного файла), `sandbox.ts` (песочница сайта), `reader-errors.ts` (ошибка программы так, как её видит читатель), `db.ts` (база и дома) |
| `_snapshots/<глава>/<NN>-<имя>.json` | снимок прогона с метками вместо uuid, времени и токенов — его сверяет `--check` |
| `_snapshots/<глава>/<NN>-<имя>.real.json` | тот же прогон с настоящими значениями — только для показа |
| `run.ts` | прогон всех примеров или по фильтру, запись и сверка снимков |

letopis подключён как `file:../lib`, а `tsconfig.json` направляет `letopis`, `letopis/model` и `letopis/mcp` в исходники
`../lib/src` — сборка библиотеки не нужна, примеры всегда идут на текущем коде.

## Подготовка

```sh
cd examples
npm install
```

Нужен PostgreSQL 18. Мастер-ключ (строка подключения администратора) — `ENTITY_DSN`, по умолчанию
`postgres://postgres:test@localhost:15433/letopis`: если база по ней не отвечает, раннер сам поднимает контейнер
`letopis-pg18` (нужен Docker).

## Что получает шаг

Шаг примера — функция `run(ctx)`; что в `ctx`, описано в `_shared/example.ts`:

| Поле | Что это |
|---|---|
| `ADMIN_DSN` | мастер-ключ |
| `name`, `schema` | имя дома примера и его схема `v2.<имя>` |
| `pass` | пропуск консьержа — его отдал `setup()` |
| `db` | консьерж: `connect(pass, { postman })` — заводит квартиры, зовёт жильцов, впускает по ключам; письма отдаёт почтальону-заглушке |
| `me` | Анна, owner квартиры «Ромашка»: корень квартиры, от него идут цепочки `me.Класс(…)` |
| `annaKey` | ключ Анны: `{ email, password }` — контакт (он же имя для входа) и пароль от «Ромашки» |
| `admin` | SQL мастер-ключом (postgres.js) — для примеров про саму базу |
| `connect` | ещё один консьерж; раннер закроет его сам |
| `warnings` | собрать предупреждения `console.warn` |

Подготовка по умолчанию: `setup(ADMIN_DSN, name, { models })` с моделями примера (свойство `models`), консьерж с
почтальоном-заглушкой (`_shared/postman.ts`), квартира «Ромашка», приглашение Анны с ролью `owner` (письмо со ссылкой
ложится в ящик почтальона) и его принятие — `db.accept(token, { password, name })`. Письма со ссылками и кодами шаги
берут из того же ящика: `lastLetter(адрес, 'invite' | 'code' | 'contact')`; «позвать и принять» одной строкой —
`inviteAndAccept(db, кто_зовёт, контакт, роли, { password, name })`. У примеров с `setup: 'none'` дома нет — его строит
сам пример (глава об установке); `pass`, `db` и `me` тогда не заданы.

## Запустить один пример

Из каталога `examples/` (так tsx берёт `tsconfig.json`):

```sh
npx tsx hello/01-hello.ts
npx tsx first/01-rental.ts
```

Скрипт готовит дом так же, как раннер, выполняет шаги подряд и печатает результат каждого. Дом
`x_<глава>_<NN>_<имя>` остаётся после прогона, чтобы заглянуть в таблицы (схема `v2.x_…`), и строится заново при
следующем запуске. Код выхода 1 — шаг упал не так, как задумано.

Скрипт для своего проекта, без каркаса `example()`, — на странице сайта: это тот же код с явными `setup()`,
`connect(pass, { postman })`, `createTenant()`, `invite()` и `accept(token)`; почтальон-заглушка и другие помощники
`_shared/`, которые пример берёт, вставлены в него целиком. Кнопка «Копировать» — и программа запускается в пустой
папке с пакетом из npm.

## Раннер и снимки

```sh
npm run snapshots                 # все примеры: прогон и запись снимков в _snapshots/
npm run snapshots -- basics/01    # только примеры, чей путь содержит «basics/01»
npm run check                     # свежий прогон обязан совпасть с записанными снимками
npm run typecheck                 # проверка типов примеров, помощников и раннера
```

Каждый пример идёт в своём доме `g_<глава>_<NN>_<имя>`, который раннер сносит в конце (`demolish`). После каждого
шага снимаются строки `entity`, новые записи `log` и, по запросу примера, `secret`. Кроме шагов, пример запускается и
как самостоятельная программа — тот текст, что на странице (`_runner/program.ts`), в доме `example_<глава>_<NN>_<имя>`:
её вывод — поле `output` снимка. Ошибку, которая дошла до верха программы, печатает `_runner/reader-errors.ts` (и в
песочнице сайта тоже): код, текст, ключ, подсказка, причина и строка программы — без стека библиотеки и локальных
путей. Расхождение при `check` — изменилось поведение библиотеки, пример или его текст:
снимки перезаписывают `npm run snapshots` и смотрят разницу в git.

## Как сайт находит примеры

Страница встраивает пример по id: `<Example id="first/01-rental" />` — плеер берёт снимок
`examples/_snapshots/first/01-rental.json`, исходник `examples/first/01-rental.ts` и самостоятельный вариант
скрипта; `<TimeTravel id="…" />` — тот же снимок. Песочница плеера отправляет исходник на сервер сайта
(`guide/server.mjs`), а тот запускает `_runner/sandbox.ts`
с рабочим каталогом `examples/`: присланный код кладётся во временный `examples/.sandbox-<случайное>/` (в
`.gitignore`, удаляется после прогона) и строит свой дом сам.
