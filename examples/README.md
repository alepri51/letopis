# Примеры letopis

Исполняемые примеры документации. Каждый файл `<глава>/<NN>-<имя>.ts` — самостоятельный скрипт: его можно
запустить сам по себе, а раннер прогоняет все примеры и пишет снимки их вывода. Сайт `guide/` примеры и снимки
только читает: встраивает в страницы и запускает в песочнице.

## Что где

| Путь | Что это |
|---|---|
| `<глава>/<NN>-<имя>.ts` | пример: `export default example({ title, steps })`; id примера — `<глава>/<NN>-<имя>` |
| `hello/01-hello.ts` | «Hello, world!» — вся letopis в одном шаге |
| `_shared/` | общие помощники примеров: `example.ts` (каркас шагов), `shop.ts` (модель магазина), `race.ts`, `proxy.ts`, `cli.ts`, `diagram.ts` |
| `_runner/` | раннер: `runner.ts` (прогон и снимок), `direct.ts` (запуск одного файла), `sandbox.ts` (песочница сайта), `db.ts` (база) |
| `_snapshots/<глава>/<NN>-<имя>.json` | снимок прогона с метками вместо uuid и времени — его сверяет `--check` |
| `_snapshots/<глава>/<NN>-<имя>.real.json` | тот же прогон с настоящими значениями — только для показа |
| `run.ts` | прогон всех примеров или по фильтру, запись и сверка снимков |

letopis подключён как `file:../lib`, а `tsconfig.json` направляет `letopis`, `letopis/model` и `letopis/mcp` в исходники
`../lib/src` — сборка библиотеки не нужна, примеры всегда идут на текущем коде.

## Подготовка

```sh
cd examples
npm install
```

Нужен PostgreSQL 18. Строка администратора — `ENTITY_DSN`, по умолчанию
`postgres://postgres:test@localhost:15433/letopis`: если база по ней не отвечает, раннер сам поднимает контейнер
`letopis-pg18` (нужен Docker). Роль приложения — `ENTITY_APP_DSN`; если не задана, раннер заводит роль
`letopis_test_app` сам.

## Запустить один пример

Из каталога `examples/` (так tsx берёт `tsconfig.json`):

```sh
npx tsx hello/01-hello.ts
npx tsx first/01-rental.ts
```

Скрипт готовит схему так же, как раннер — установка с арендатором «Ромашка» и пользователем Анной, сервис по ключу,
работа от имени Анны (у примеров с `setup: 'none'` — пустая схема, её ставит сам пример), — выполняет шаги подряд и
печатает результат каждого. Схема `v2.x_<глава>_<NN>_<имя>` остаётся после прогона, чтобы заглянуть в таблицы, и
пересоздаётся при следующем запуске. Код выхода 1 — шаг упал не так, как задумано.

Скрипт для своего проекта, без каркаса `example()` и помощников `_shared/`, — на странице сайта, кнопка «Весь код
примера»: тот же код с явными `up()`, `connect()` и `svc.as()`.

## Раннер и снимки

```sh
npm run snapshots                 # все примеры: прогон и запись снимков в _snapshots/
npm run snapshots -- basics/01    # только примеры, чей путь содержит «basics/01»
npm run check                     # свежий прогон обязан совпасть с записанными снимками
npm run typecheck                 # проверка типов примеров, помощников и раннера
```

Каждый пример идёт в своей схеме `v2.g_<глава>_<NN>_<имя>`, которую раннер удаляет в конце. После каждого шага
снимаются строки `entity`, новые записи `log` и, по запросу примера, `secret`. Расхождение при `check` — изменилось
поведение библиотеки, пример или его текст: снимки перезаписывают `npm run snapshots` и смотрят разницу в git.

## Как сайт находит примеры

Страница встраивает пример по id: `<Example id="first/01-rental" />` — плеер берёт снимок
`examples/_snapshots/first/01-rental.json`, исходник `examples/first/01-rental.ts` и самостоятельный вариант
скрипта; `<TimeTravel id="…" />` — тот же снимок. Песочница плеера отправляет исходник на сервер сайта
(`guide/server.mjs`), а тот запускает `_runner/sandbox.ts`
с рабочим каталогом `examples/`: присланный код кладётся во временный `examples/.sandbox-<случайное>/` (в
`.gitignore`, удаляется после прогона) и идёт в свежей схеме.
