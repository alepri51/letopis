# M-DERIVED — агрегаты в базе (синхронно, триггером) и проекторы из журнала (асинхронно)

**Инварианты и грабли**
- Производный класс (`derivedBy`) описывает только администратор (право `letopis.projector`), его строки пишет только `derived_apply`: проектор пишет туда итоги по всем строкам источников (/security-review после точки Б). Целью и источником агрегата он не бывает.
- Агрегат считают функции владельца по всем строкам источника без прав чтения, поэтому строки входят в него только с ведома тех, кто читает их все без условий: описать агрегат — с таким правом на семейство `of`; новый источник проверяется по READ заводящего (`agg_source_admit`) и описавшего (`agg_author_admit`: автор версии `Class`, с которой описание стало нынешним, объём — как при описании; решение владельца 28.10). Источник описывают раньше цели; класс `of` арендатора не удаляется, пока его называет агрегат.
- Итог новой цели оператора (вставка, `restore`, смена класса) пишется в ту же версию — в `entity` и в уже записанную строку `log`. Функция владельца, которая сама пишет журнал, пишет его до вставки (`sys_create`, загрузчик) или из перечитанной строки (`restore`, `sys_update`).
- Цикл агрегатов — `invalid_class` (`agg_cycle`); цепочку (сумма агрегатного поля) считает каскад: `sys_update` итога снова будит `entity_total_au`.
- Писатели источника держат разделяемую блокировку семейства, смена агрегата и `rebuild_aggregates` — исключительные семейств цели и источников (`agg_lock_sources`): иначе вклад, зафиксированный во время пересчёта, потерялся бы (гонка №18). Цели блокируются по id — горячая цель становится очередью, около 150 операций/с (`docs/checkpoint-1.2.md`).
- Проектор пишет группу арендатора под точкой сохранения: ошибка его данных (`LetopisError`, SQLSTATE `LT`, `22`, `54`) выводит только его (`failed`) до `rebuild({ tenant })`; исключение `handle`, выход `out` за границы и сбой окружения откатывают пачку целиком (ревью №2, Н1). 55P03 после `lockTimeout` — проход пропущен, курсор стоит; с `lockRetries` (по умолчанию 0, решение владельца 28.10) арендатор выбывает с кодом 55P03. Участник — арендатор, у которого все классы `into` помечены `derivedBy` (и он в `tenants`, если список задан); ярус `all` и журнал источников — тоже по арендатору.
- Чекпоинт хранит состав участников (`meta.tenants`: полная перестройка, `startTenant`; в `step` — известные нынешние). Участник не из списка — вступил после проекции: `step` пропускает его строки, `tenantWork` начинает ему перестройку пачками (план 2.0, 7.4 №5); выбывший из участников из списка уходит и, вернувшись, снова новичок; чекпоинт без поля — известен нынешний состав. Состав перечитывается по сигналу `Class`, а без LISTEN (`env.onSignal` нет) — в начале `run()` и не реже раза в 5 с (`due()`, 7.4 №6); тесты — `watch-contract`.
- Атомарная перестройка держит горизонт кластера (подписки и проекторы всех процессов ждут её конца); перестройка пачками сразу удаляет производные строки, и до конца данные неполные (`rebuilding`). Решение точки Б: первый `run()` и `onExpired: 'rebuild'` — пачками, `rebuild()` без опций — атомарно; начатую перестройку арендатора пачками продвигает любой `run()`.
- `run({ once: true })` догоняет всё, что зафиксировано до вызова (агентский прогон, решение владельца 02.11): граница — `xmax` снимка на входе (`snapXmax`); проход, перед которым горизонт (`pg_snapshot_xmin(pg_current_snapshot())`) уже прошёл границу, и пустой — `caughtUp: true`; иначе ожидание горизонта (`untilHorizon`, опрос раз в 50 мс, метка запроса `/* letopis projector once: wait */` — по ней тест видит ожидание) до `wait` мс (5000; 0 — без ожидания) и ещё проход. `busy` (блокировка проектора занята) — сразу, `caughtUp: false`, как прежде `skipped`. Горизонт общий для кластера: чужие транзакции любой базы тоже задерживают `once` (до `wait`). Тест — `projector`, «этап 3, п. 9: run({ once: true })…».
- Отметка выбывшего (`meta.failed`) хранит рядом с `message` ключ каталога `key` и `params` (`failure()`, ключ ошибки базы или `out` — из `LetopisError`); `status()` и отказ `rebuild({ tenant, chunked })` отдают записанный текст. Новая отметка — через `failure()`.
- `ProjectorEnv.ready` (план 2.0, 7.9 №3): проектор от корня с `connect({ admin })` до первой работы `run()` ждёт проверки роли администраторского пула; отказ — исключение `run()`, флаг `running` не ставится.
- `purge` и `trimHistory` ждут проектор источника (`projector_pending`): брошенный проектор держит их, пока у арендатора есть его производные классы.

**Что ещё менять вместе**
- Новая функция в `88-derived.sql` → список `do $$` в конце её раздела (владелец, `revoke … from public`; иначе `roles` «права по каталогу»); `security definer` (сейчас только `trg_entity_total_*`) — ещё негативный тест `roles` №4; смена сигнатуры — `drop function if exists` прежней (образец `derived_clear(text)`), иначе `upgrade` найдёт лишнюю перегрузку.
- Смысл или сигнатура `agg_*` → grep `agg_` по `lib/sql` и `lib/src`: крючки в `40-class.sql`, `60-write.sql`, `90-time.sql`, `95-seed.system.sql`, `load.ts`. Запись итога новой цели или `agg_hold_*` → `move_row` (`acc`), `reset` (`off`), `restore`, `sys_update`, `sys_create`, загрузчик.
- Правило объёма агрегата (классы System и арендатора) → grep `'@SYSTEM@'::uuid` по `88-derived.sql`, `class_admit` и `trg_entity_ad` (`60-write.sql`); тесты `aggregate` («ревью коммита этапа 4б», «7.5 №20»), атака №57.
- Новая проверка источника → вызовы в `trg_entity_ai`, `trg_entity_au`, `class_evolve` (образец `46114ef`).
- Новая опция `ProjectorOptions` → проверка в конструкторе, README «Проекторы» и «Справочник API → Проектор», тест `projector` (образец `c8205d3`).
- Формат чекпоинта (`enc`, `meta.from`) → `projector_unread` (`90-time.sql`); `NAME` = шаблон `derivedBy` в `40-class.sql`.

**Состояние и побочки**
- `secret` вида `PROJECTOR` (аккаунт System, `ident` — имя): `meta.cursor` «tx:seq~снимок», `at`, `version`, `state`, `rebuild`, `chunks`, `failed`, `resync`, `retenant`, `since`, `from`. Строка-замок `LOCK` «схема:projector:имя» (`lock_try`) — на каждую пачку: занята — `skipped`, у `rebuild()` — `projector_busy`.
- Производные строки — автор System, агент `letopis projector <имя>`; версия цели агрегата — с автором и причиной операции-источника; `rebuildAggregates` — причина `rebuildAggregates`, версия только у исправленных.

**Неимпортные связи**
- `watch_read(…, p_leaving = true)` (`90-time.sql`) — только у проектора: уход строки из `from` сменой класса без смены id становится изменением `delete` с `$deleted`, вход — `before` = null (ревью №3, №4); подписке уход отдаёт `watch_leaving`.

- `lib/sql/88-derived.sql:derived_apply` — запись результатов проектора
