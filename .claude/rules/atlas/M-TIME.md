# M-TIME — история, подписка, кэш, сигналы, обслуживание

**Инварианты и грабли**
- `maintain()` удаляет коды всех видов, которые выпускает `auth_issue_otp`: шаблон вида `^OTP(_[A-Z0-9]{1,27})?$` в `lib/sql/90-time.sql` и в `lib/sql/80-auth.sql` один — меняешь один, меняй оба.
- У id с записью в журнале номер 1 всегда занят: версии id не стираются, а воскрешение продолжает номер от последней записи журнала — на уникальности `log_id_rev` держится `existing: 'error'` загрузчика. Служебных записей в журнале нет: каждая строка — версия объекта. Журнал теряет версии только при удалении аккаунта (`account_purge` стирает журнал его арендатора).
- Последнюю запись журнала id берут `for update` все, кто продолжает историю: `last_version_visible` (restore) и `trg_entity_bi` (`lib/sql/60-write.sql`). Новая операция над историей id — под той же блокировкой.
- «Администратор» (`admin_role`) и роль под RLS (`targets_bad`) в функциях владельца определяются только по `session_role()` — роли SET ROLE, иначе роли входа. Там `current_user` — владелец, `session_user` — роль входа, и привилегированный вход с `SET ROLE` на роль приложения сошёл бы за администратора (ревью коммита 1734d21; тест `engine-attacks` «№56»).
- Сигнал — только подсказка: NOTIFY в канал схемы может послать любая роль базы, а данных он не несёт. По нему лишь будят подписку (`wakes`), сбрасывают кэш (`ResultCache.apply`) и пропуска прав, перечитывают ключ и реестр не чаще заданного (`throttle`, `bucket` в `lib/src/index.ts`); карты счётчиков кэша ограничены (`bump`). Счётчик сессии заводит только снимок запроса (`ResultCache.watchSession`), сигнал `session:<тег>` меняет лишь заведённые и не удаляет их: иначе гашения чужих сессий (вход и выход пользователей сервиса) копили бы по записи на тег в каждом подключении — 0,7–0,9 МБ/ч на подключение в долгом прогоне (план 2.0, 7.7; находка soak).
- `maintain()`: один исполнитель — строка-замок `lock_try('@SCHEMA_NAME@:maintain')` (`lib/sql/60-write.sql`) в транзакции обслуживания, а не advisory-блокировка: её ключ может занять посторонняя роль (ревью безопасности №3, №2). Обслуживание — одна транзакция (сессии, коды, строки-замки удалённых семейств), поэтому работает и за PgBouncer в режиме транзакций. Замок занят — база отвечает `null`, библиотека — `skipped: true`. Журнал `maintain()` не трогает.

**Что ещё менять вместе**
- Новая функция владельца: перечень `alter function … owner` в конце `lib/sql/90-time.sql` (и `grant execute`, если её зовёт приложение), `lib/test/roles.test.ts` («№4» — негативный тест, белый список функций приложения); образец a25b432.
- Формат нагрузки сигнала: `signal()`, `signal_raw()`, `signal_token()` (`lib/sql/60-write.sql`), `Signals.parse` и токены, `wakes`, `ResultCache.apply`, `onSignal` в `lib/src/index.ts`, тесты `signals` и `security-final`. `lib/src/signals.ts:NAME` = шаблон имени метасхемы Class (`lib/sql/40-class.sql`): на нём держится однозначный разбор `класс@токен`.
- Запись журнала, которая не версия объекта, → исключение во всех запросах к журналу (M-QUERY).
- `maintain()` (без параметров): сессии, коды и строки-замки семейств, чьего корня нет (строки `Class` с именем корня у арендатора семейства — разбор имени `family_name`; `skip locked`, строка семейства — только вместе со шлюзом или без шлюза: исключительная берёт шлюз первым; план 2.0, 7.7 №8).
- Подписка: короткие повторы (до 40) — только после сигнала (`Subscription.burst`); тик таймера `pollMs` — один запрос (план 2.0, 7.4 №1). Курсор — `tx:seq[~снимок]`, он не устаревает. Живые подписки подключения — `Shared.subs` (`track`, `WatchCtx.onClose`): `close()` подключения закрывает их (7.4 №8). `take()` перед ожиданием будильника проверяет `closed`: подписку, закрытую во время запроса журнала или паузы (будильник тогда ещё не выставлен), иначе ждал бы вечный `await` — `for await` не кончался (тест `watch-contract` «close() подписки, пока идёт её запрос…»; находка обхода сервисов — поток SSE после выхода).
- Подписка читает журнал одной функцией `watch_read` (окно, горизонт и снимок — её; `Subscription.fetch`). Событий ухода строки из классов подписки нет: класс строки неизменен (M-ENGINE).

**Состояние и побочки**
- Строка KEY (`secret`, id = System) — общая. `material` — секрет пропусков прав (`acl_token`) и ключа сигналов (`signal_key`). В `meta`: `v` (`acl_bump`), `signals` (сид); пишут только слиянием (`||`).

**Неимпортные связи**
- `lib/src/index.ts` зовёт по имени `signal_mode()`, `signal_key()` (`fetchKey`) и `class_stamp()` (режим none, раз в 5 с); после переподключения слушателя процессы перечитывают ключ сигналов и реестр и чистят кэш.
