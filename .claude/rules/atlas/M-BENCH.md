# M-BENCH — замеры точки А и бенч против 0.21 (этапы 1, 7)

**Инварианты и грабли**
- Скрипты — через tsx (`cd lib && npx tsx bench/<имя>.mjs`): импортируют исходники `src/*.ts`; масштаб — `BENCH_SCALE` (0.1 — в десять раз меньше); итог — `bench/results/<имя>.json` (`save` в `_core.mjs`). Серии точки А (`core-*`, `chain-read`, `acl-cost`) — своя схема `v2.b_<имя>`, сводка — `docs/checkpoint-a.md`.
- 0.21 — пакет `letopis-0` на контейнере `letopis-timescale` (порт 15432, `LETOPIS_021_DSN`); `up()` 0.21 сам поднимает контейнер. 1.0 — `letopis-pg18` (порт 15433), поднимает обвязка тестов.
- Полигоны (этап 7): `salon-data.mjs` — дословный `makeRows` 0.21 и перевод строк в загрузку 1.0 на демо-домене (`toLoad10`: роли `Parent`, `Item`, `Part`; совпавшие старты записей мастера сдвигаются на минуты; явный null опускается); `seed-021.mjs` — засевка 0.21 сырыми вставками, как скрипты 0.21; `polygons.mjs` — 1.0 загрузчиком в арендаторах (правило «можно всё»), порциями ~100 тыс. строк по границам объектов (`loadChunks`: цели раньше ссылающихся — порядок генератора), клиенты tenants — по 50 тыс.; сверка объектов и версий по классам с генератором 0.21 (§7.9 №7.7).
- `import-salon.mjs` (`npm run test:import-salon`) — §7.9 №7.6: засевка 0.21, `up({ fresh })` 1.0, импорт с `--keyless booking` (полигон 0.21 писался мимо v5), сверка объектов и версий по классам и `verify()`, код 1 при расхождении. Импорт держит источник в памяти целиком (полный полигон — ~980 тыс. строк): при нехватке памяти процесс снимается.
- `compare.bench.mjs` — §7.9 №7.8: те же полигоны в обеих версиях, p50 после прогрева; таблица — `results/compare.md` (в README §14). В 0.21 нет `reclass`; там полигон salon — у System без изоляции (`enforceAccount: false`).
- Строки полигонов не держать между замерами (только число и время): память.
- `BENCH_REUSE=1` — бенч на уже засеянных полигонах (скорость загрузки — из `results/polygons.json` и прошлого `compare.json`); схемы старой ревизии — `up({ schema, upgrade: true })` перед замером.
