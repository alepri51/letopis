# M-QUERY — поиск id под RLS (find_*) и построитель чтения

**Инварианты и грабли**
- Под RLS индексы GIN приложению недоступны (`@>` не leakproof). Шаг из двух частей: функции владельца `find_ids()`, `find_hop()`, `find_deep()` ищут id по индексам без RLS и сами применяют видимость `row_visible()` — копию условия политик `entity_select`/`log_select` (`50-acl.sql`); строки читаются по первичному ключу под RLS. Менять видимость — в обоих местах; расхождение ловит `find-ids-parity`.
- `find_hop`/`find_deep` пробуют `entity_ends` на каждый id через `lateral (… offset 0)`, а класс, видимость, data и роли проверяют после пробы. Без `offset 0` подзапрос поднимается в общий план, и планировщик по плохой оценке меняет пробы на перебор таблицы; пересечение пробы с индексами (class, tenant) или data перебирает весь класс (замер `bench/chain-read.mjs`).
- Узлы читаются через `lateral` по списку id (`entityByIds`), версии журнала — по паре (id, rev): так планировщик видит число строк и не переходит на перебор.
- Без возвратов к узлам (pivot) последний узел уже содержит ровно сущности полных путей — rows, ids, count, агрегаты и versions читают его без соединения путей; paths и цепочки с pivot соединяют `n0 ⋈ p1 ⋈ n1 …`.
- Значения — только параметрами (списки — одним массивом), неиспользованный параметр PostgreSQL не примет — параметры поиска ленивые. Текст запроса зависит только от формы цепочки → подготовленный оператор postgres.js (`prepare: true`).
- Переход: шаг-роль — своим концом (`resolveHop`); иначе концами всех классов обоих семейств без ограничения ролей — допустимость гарантирует целостность ссылок. Надгробие в журнале всегда `op = 'delete'` (по нему asOf и withDeleted отличают удалённый id).
- Время в ответе — UTC: `runTx` выставляет `TimeZone` на транзакцию; `asOf` и курсор по `at` передаются `::text::timestamptz` (Date в postgres.js режет микросекунды).
