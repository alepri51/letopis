# Первые 15 минут: один процесс

От пустой базы до первых данных — четыре шага в одном процессе Node (так устроено малое приложение; веб-сервис, где дом строит скрипт развёртывания, а сервис работает пропуском, — [«Старт с нуля»](../start/)):

Четыре слова, без которых шаги не прочитать. **Дом** — ваше приложение в базе: схема с таблицами и вашей моделью. **Пропуск** — строка, по которой приложение подключается к дому. **Консьерж** — приложение, подключённое по пропуску: он заводит квартиры и впускает в них людей. **Квартира** — данные одной компании: другим квартирам они не видны. Этого хватит, чтобы пройти страницу; подробно, с рисунком и остальными словами, — [«Дом, пропуск, консьерж»](../house/), её можно прочитать сразу после.

1. `setup(ADMIN_DSN, 'имя', { models })` мастер-ключом — дом: схема с таблицами, системными классами и вашей моделью; ответ — **пропуск** консьержа;
2. `connect(pass, { postman })` — **консьерж**: он заводит **квартиру** (`createTenant`) и зовёт в неё жильца **приглашением** (`invite`). Письмо со ссылкой получает **почтальон** — функция приложения, которая доставляет письма; в примере это заглушка, она складывает письма в ящик `mail`;
3. `accept(token, { password })` — жилец принимает приглашение по токену из ссылки и сразу получает корень квартиры;
4. цепочки от корня квартиры — запись и чтение данных; завтра жилец входит своим контактом и паролем — `open(ключ)`.

Потом — [удаление и возврат](#удалить-и-вернуть-только-по-expect) так, как их делают в настоящем приложении, и [прокат целиком](#прокат-целиком-ключ-удаление-и-возврат-одним-фрагментом) одним фрагментом. Хотите сначала понять, как letopis устроен, — глава [«Что такое letopis»](../basics/what-is); кто такие дом, консьерж, квартира, жилец и ключ — страница [«Дом, пропуск, консьерж»](../house/); как устроены приглашения — [«Приглашения и почтальон»](../invites/).

## Что нужно

- Node 22 или новее;
- PostgreSQL 18 и мастер-ключ — строка подключения роли-установщика: суперпользователь или роль с `CREATEROLE` и правом `CREATE` на базе ([какие права нужны](../install/)). Нет своей базы — запустите PostgreSQL 18 в Docker и дождитесь готовности (репозиторий не нужен). Порт и имя контейнера заданы переменными:
  ```sh
  PORT=15440
  NAME=pg18
  docker run -d --name $NAME -e POSTGRES_PASSWORD=guide -e POSTGRES_DB=letopis -p 127.0.0.1:$PORT:5432 postgres:18
  until docker exec $NAME pg_isready -h 127.0.0.1 -U postgres -d letopis; do sleep 1; done
  export ADMIN_DSN=postgres://postgres:guide@127.0.0.1:$PORT/letopis
  ```
  PowerShell:
  ```powershell
  $PORT = 15440
  $NAME = 'pg18'
  docker run -d --name $NAME -e POSTGRES_PASSWORD=guide -e POSTGRES_DB=letopis -p "127.0.0.1:${PORT}:5432" postgres:18
  do { Start-Sleep 1; docker exec $NAME pg_isready -h 127.0.0.1 -U postgres -d letopis } until ($LASTEXITCODE -eq 0)
  $env:ADMIN_DSN = "postgres://postgres:guide@127.0.0.1:${PORT}/letopis"
  ```
  Другой порт или имя — смените их в `docker run` и в `ADMIN_DSN`: с переменными выше достаточно поменять `PORT` и `NAME`. Пароль `guide` стоит в двух местах — в `POSTGRES_PASSWORD=guide` команды `docker run` и в строке `ADMIN_DSN`: меняете — меняйте в обоих. Без `ADMIN_DSN` скрипт идёт в базу по умолчанию — `postgres://postgres:guide@127.0.0.1:15440/letopis`. Остановить — `docker stop pg18`, запустить снова — `docker start pg18`.
- пакеты — в пустой папке проекта (`type=module` нужен для `await` на верхнем уровне; `tsx` запускает TypeScript):
  ```sh
  npm init -y && npm pkg set type=module && npm i letopis@4 zod && npm i -D tsx
  ```
- запуск примера: скопируйте скрипт кнопкой «Копировать», сохраните под именем над ним (здесь — `first-15.ts`) и запустите в том же окне терминала, где задан `ADMIN_DSN`:
  ```sh
  npx tsx first-15.ts
  ```
  В новом окне — со строкой: `ADMIN_DSN=postgres://postgres:guide@127.0.0.1:15440/letopis npx tsx first-15.ts`, в PowerShell — `$env:ADMIN_DSN = 'postgres://postgres:guide@127.0.0.1:15440/letopis'; npx tsx first-15.ts`. Вывод сравните с блоком «Ожидаемый вывод» под скриптом.

## Сводка значений {#сводка-значений}

Какие строки, ключи и токены встречаются в примерах, откуда они берутся и кому нужны.

| Значение | Откуда берётся | Кому нужно | Где хранить |
|---|---|---|---|
| `ADMIN_DSN` — **мастер-ключ**: строка подключения администратора PostgreSQL | задаёте вы: роль-установщик — суперпользователь или роль с `CREATEROLE` и правом `CREATE` на базе ([какие права нужны](../install/)) | тому, кто строит, достраивает и сносит дом: `setup()`, `demolish()`, команды `letopis sync`, `load`, `maintain` | только у скрипта развёртывания и обслуживания (CI, отдельный процесс); веб-сервису он не нужен — кроме малого приложения «одним процессом», как на этой странице |
| `pass` — **пропуск** консьержа: строка подключения его роли с домом и ключом | `setup()` → `r.pass`; повторный `setup()` отдаёт тот же, `setup(…, { rotate: true })` — новый (старый гаснет сразу) | веб-сервису: `connect(pass)` — консьерж, одно подключение на процесс | секрет: переменная окружения (например, `LETOPIS_PASS`) или хранилище секретов; пропуск лежит и в самой базе — значит, и в её резервных копиях |
| **контакт** — почта, телефон, Telegram человека; он же имя для входа | задаёт тот, кто зовёт: `me.invite({ email }, роли)` | почтальону — куда доставить письмо; жильцу — чем входить: `db.open({ email, password })` | не секрет; один контакт — один аккаунт на весь дом |
| токен **приглашения** — 48 знаков в ссылке из письма | `me.invite(контакт, роли)` отдаёт его почтальону: `message.token`; в ответе `invite` токена нет. Одноразовый, со сроком | человеку, которого зовут: страница по ссылке вызывает `db.invitation(token)` и `db.accept(token)` | только в письме; в базе — хэш |
| код входа — 6 цифр | `db.requestCode(контакт)` отдаёт его почтальону: `message.code`; живёт 10 минут | жильцу без пароля: `db.open({ email, code })` | только в письме; в базе — хэш |
| **ключ** жильца: пароль, ключ API, ключ и секрет, внешний вход | пароль — в `accept(token, { password })` или позже `me.keys.setPassword`, остальные — `me.keys.*`; каждый открывает одну квартиру | жильцу: `db.open(ключ)` — вход | у самого человека (пароль) или в его программе (ключ API); в базе — только хэш |
| `token` — токен сессии жильца | `open()` и `accept()` → корень квартиры, его `token` | `db.resume(token)` — следующий запрос того же жильца | секрет жильца: cookie (httpOnly); гасит `close()` |
| квартира — имя и id | `db.createTenant('Ромашка')` → `{ id, name }`; список — `db.tenants()` | консьержу: `db.in(квартира)`, `db.as(аккаунт, квартира)`, `db.open({ …контакт, code, tenant })`; команде `letopis load --tenant` | не секрет: имя уникально в доме |

**Имя дома.** `setup(ADMIN_DSN, 'myapp')` строит схему `v2.myapp` — с точкой внутри имени, поэтому в своём SQL её пишут в кавычках: `select * from "v2.myapp".entity`. Полное имя — `r.schema` и `db.schema`.

**Почему веб-сервису не нужен мастер-ключ.** Администратор PostgreSQL обходит правила доступа (RLS): под ним база не проверяет права, и видны данные всех квартир. Консьерж — отдельная роль базы без этих прав: пропуск открывает ему только дверь дома (квартиры, приглашения, вход по ключам), а данные квартиры читает и пишет корень жильца — и каждый его запрос база проверяет сама: ошибка в коде приложения не откроет чужие данные. Малое приложение из одного процесса может держать и мастер-ключ, как программа на этой странице, — цена: взломанный процесс получит и его. Большому приложению подойдёт путь из [«Старта с нуля»](../start/): дом строит скрипт развёртывания, сервис работает пропуском.

## Удалить и вернуть: только по expect

Удаление в letopis — два шага, и второй всегда со сверкой: удаляется **ровно то, что человек видел**.

Фрагменты ниже взяты из программы проката — она целиком стоит [в следующем разделе](#прокат-целиком-ключ-удаление-и-возврат-одним-фрагментом). `Member` в них — участник клуба, `member` — его строка, `OpenLoan` — открытая выдача вещи участнику: она удаляется вместе с участником (каскад).

```ts
const preview = await me.Member(member).delete().rows()       // 1. ничего не удаляет: что удалится ($action, $depth)
// 2. показать preview пользователю; он нажал «Удалить»
const gone = await me.Member(member)
  .delete({ confirm: true, expect: preview, reason: 'удаление участника (op-17)' }).rows()   // 3. ровно показанное
```

- **Без `expect` подтверждение не пройдёт.** `delete({ confirm: true })` — отказ `invalid_query` (ключ `write.confirm_without_expect`), ничего не удалено: между показом и нажатием в каскад могла добавиться строка, и она ушла бы без спроса.
- **Изменилось — `conflict`.** Если состав удаления за это время поменялся, ничего не удаляется, а новый предпросмотр — в `err.detail.preview`: покажите его и подтверждайте уже с ним.
- **Ответ — надгробия.** `gone` — цель и весь каскад с `id` и `rev`. Сохраните его: по нему удаление и возвращают.

```ts
await me.Member(member).restore({ expect: gone.filter((r) => r.class === 'Member') }).rows()   // сам участник
const loans = gone.filter((r) => r.class === 'OpenLoan')                       // его выдачи из того же удаления
const back = await me.OpenLoan(loans.map((r) => r.id)).restore({ expect: loans, partial: true }).rows()
const lost = back.filter((r) => r.$action === 'skip')                          // не вернулись — причина в r.$why
```

- **Без `expect` возврат не пройдёт.** `restore()` — отказ `invalid_query` (ключ `write.restore_without_expect`): последний снимок объекта может быть уже чужим — вещь после удаления выдавали другому.
- **`partial: true`** — вернуть то, что можно; остальное приходит строками-пропусками `$action: 'skip'` с причиной `$why`.
- Осознанно, без сверки — `delete({ confirm: true, all: true })` и `restore({ all: true })`. В приложении для людей так не делают.

Подробно — [«Удаление и восстановление»](../delete/), рецепт для веб-сервиса «предпросмотр → подтверждение → отмена» — там же.

## Прокат целиком: ключ, удаление и возврат одним фрагментом

Клуб выдаёт вещи участникам. Пример ниже держит все три правила, на которых спотыкаются в первый день, — скопируйте его кнопкой «Копировать» и запустите на своей базе.

<Example id="first/01-rental" />

Что в нём и зачем:

1. **Одна открытая выдача на вещь — ключом.** Открытая выдача — отдельная связь с ключом только из вещи: `link('OpenLoan', { … }, { ends: { Item: one(Item), Member: one(Member).onDelete('cascade') }, key: ['Item'] })`. id выдачи вычисляется из вещи, поэтому вторая выдача той же вещи — отказ `exists` при любом числе процессов. Проверка «есть ли выдача» в коде этого не удержит: два запроса проверят одновременно и оба выдадут. Вернули вещь — удаляют эту строку; следующая выдача продолжает её историю.
2. **Удаление — по `expect`.** Предпросмотр показывают человеку, подтверждение идёт с ним: удаляется ровно показанное, а не то, что успело добавиться.
3. **Возврат — по надгробиям этого удаления, с `partial`.** Участника удалили — его выдача ушла каскадом; вещь тем временем выдали другому. Возврат по надгробиям удаления (`restore({ expect, partial: true })`) вернёт участника, но не оживит его выдачу поверх чужой: она придёт пропуском `reissued`, а если вещь успели и вернуть — `changed`.
4. **`$why` — в текст для человека:**

| `$why` | Что случилось | Что сказать |
|---|---|---|
| `changed` | после удаления строку пересоздавали, правили или удалили снова — вещь выдавали другому | «выдача не вернулась: вещь после удаления выдавали другому» |
| `reissued` | id занят живой строкой с тем же ключом — вещь сейчас у другого | «вещь сейчас выдана другому» |
| `restored` | строку уже вернули | «уже возвращено» |

::: details Как превратить ошибку letopis в текст для человека
По `err.code` программа решает, что делать, по `err.key` — что именно случилось; `err.message` — для журнала, а не для пользователя.

```ts
import { LetopisError } from 'letopis'

function say(e: unknown): string {
  if (!(e instanceof LetopisError)) throw e
  switch (e.code) {
    case 'exists': return 'такая запись уже есть'                       // ключ занят: вещь уже выдана
    case 'conflict': return 'данные изменились — посмотрите ещё раз'    // устарел предпросмотр или версия
    case 'target_not_found': return 'не найдено: объект удалили или он вам не виден'
    case 'invalid_data': return 'проверьте введённые данные'            // подробности — e.issues
    case 'acl_denied': return 'недостаточно прав'
    case 'auth_failed': return 'войдите заново'                         // ключ или токен не подошёл
    case 'no_session': return 'войдите заново'                          // сессия погашена или истекла
    default: throw e                                                    // ошибка в коде — в журнал, не пользователю
  }
}
```

Все коды и ключи — страница [«Ошибки: все коды и ключи»](../errors/codes).
:::

## Десять главных нюансов

Ловушки, на которых чаще всего спотыкаются в первый день, — по порядку шагов выше. У каждого — живой пример. Все нюансы по темам — на странице [«Все нюансы»](../nuances/).

<!-- nuances:top -->
1. setup() отдаёт пропуск консьержа: повторный вызов — тот же пропуск, setup(…, { rotate: true }) — новый, а прежний сразу перестаёт работать (connect по нему — auth_failed). В пропуске — пароль роли консьержа: храните его как секрет; он же лежит в базе и попадает в резервные копии. [Пример](../install/#ex-install-06-rotate-demolish)
2. syncModels без apply — сухой прогон: ничего не пишет, отвечает, что будет создано и изменено. [Пример](../models/#ex-models-01-shop-model)
3. Классы, записанные syncModels в корне квартиры, принадлежат ей: другая квартира не видит даже класса (invalid_class). Общие для всех квартир классы — setup(…, { models }) или letopis sync. [Пример](../access/#ex-access-01-residents)
4. Значения поля-ключа модели берутся как есть: email в разном регистре даёт разные id объекта. Это про ключ класса; контакт приглашения и входа сравнивается без учёта регистра. [Пример](../models/#ex-models-02-keys-and-ids)
5. У цепочки нет метода then: await me.Класс(…) отдаёт саму цепочку и ничего не читает — запрос выполняет терминал (rows, first, count…). [Пример](../write/#ex-write-06-link-verbs)
6. upsert заменяет данные целиком: поля, которых нет в объекте, пропадают; затирает параллельные приращения. [Пример](../write/#ex-write-01-create-update-upsert)
7. update без найденных строк возвращает пустой список без ошибки — проверяйте длину ответа. Фильтр по данным при гонке перепроверяется под блокировкой: из двух одновременных правок одной строки пройдёт одна, вторая получит пустой ответ. Правило «одна открытая запись на объект» так не удержать — его держит ключ; «прочитал — посчитал — записал» — forUpdate() в me.begin() или { rev }. [Пример](../write/#ex-write-01-create-update-upsert)
8. delete() без { confirm: true } ничего не удаляет — возвращает предпросмотр: что удалится и с каким действием ($action). [Пример](../basics/what-is#ex-basics-01-first-object)
9. Права включены всегда: без подходящего правила действует правило по умолчанию — на свежем доме «нельзя» (setup({ defaultRule: 'allow' }) переключает). createTenant даёт роли owner «можно всё» и право выдавать любые роли с весом 100 000 — правила жильцов (вес до 999) его не перекроют. [Пример](../access/#ex-access-01-residents)
10. Корень с погашенной или истёкшей сессией на любой вызов отвечает no_session — например, после me.leave(), me.closeAll(), смены пароля или отзыва ключа. ::: details Транзакция me.begin() — форма вызова (к нюансу 7)
`begin()` открывает транзакцию, закрывают её `tr.commit()` или `tr.rollback()`; ошибка — откатить и пробросить. Функцию `begin()` не принимает: `me.begin(async (tr) => …)` — отказ `invalid_query` ([пример](../errors/#ex-errors-01-api-errors)).

Продолжение программы `first-15.ts` выше (`me` — корень квартиры Анны, модель товара `Product` — из неё): «прочитал — посчитал — записал» — поднять цену товара на `percent` процентов так, чтобы одновременная правка той же строки не потерялась.

```ts
async function raisePrice(sku: string, percent: number) {
  const tr = await me.begin({ reason: 'наценка' })
  try {
    const p = await tr.Product({ sku }).forUpdate().first()          // строка заблокирована до конца транзакции
    if (!p) {
      await tr.rollback()
      return null                                                    // такого товара нет
    }
    const price = Math.round(Number(p.data.price) * (1 + percent / 100))
    const [row] = await tr.Product(p).update({ price }).rows()
    await tr.commit()
    return row
  } catch (e) {
    await tr.rollback()   // после commit() или rollback() ничего не делает
    throw e
  }
}

console.log((await raisePrice('M-1', 10))?.data)                     // { sku: 'M-1', price: 440, title: 'Кружка' }
```
:::
