# Первые 15 минут

От пустой базы до первых данных — четыре шага в одном процессе Node:

1. `up({ tenant, login })` от администратора базы — схема, арендатор с первым пользователем и роль приложения;
2. `connect({ dsn: r.login.dsn, admin, token })` — приложение подключается этой ролью от имени пользователя;
3. модель на `letopis/model` и `syncModels` — описания классов в базе;
4. цепочки — запись и чтение данных.

Хотите сначала понять, как letopis устроен, — начните с главы [«Что такое letopis»](../basics/what-is).

## Что нужно

- Node 22 или новее;
- PostgreSQL 18 и роль администратора (суперпользователь или `CREATEROLE`). Нет своей базы — запустите ту, на которой работают примеры этого сайта:
  ```sh
  docker compose -f services/compose.yaml up -d pg     # PostgreSQL 18 на 127.0.0.1:15440
  ```
- пакеты:
  ```sh
  npm install letopis zod
  ```

## Один процесс — для малых приложений

С `admin` администраторские вызовы — `syncModels`, `load`, `verify`, `maintain`, проекторы и `rebuildAggregates` — идут вторым пулом с той же сессией, а цепочки — всегда ролью приложения под правами базы. Цена — пароль администратора в процессе приложения: взломанный процесс получит и его. Большому приложению подойдёт путь из [«Старта с нуля»](../start/): веб-приложение подключается по ключу сервиса без пароля администратора, а администраторская работа идёт в отдельном процессе.
