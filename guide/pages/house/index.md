# Дом, пропуск, консьерж

## Зачем

В одной базе letopis хранит данные многих людей и компаний. Чтобы они не смешались, нужно знать три вещи: чьи это данные, кто сейчас работает и что ему можно. letopis отвечает на это словами жилого дома. Слов немного, и дальше весь сайт говорит только ими.

Эта страница — про слова, без установки и без подробностей. Прочитайте её до главы [«Установка и подключение»](../install/).

## Дом на одном рисунке

```text
мастер-ключ            строка администратора PostgreSQL: строит и сносит дом
└─ дом                 ваше приложение в базе: таблицы, проверки, общие классы
   ├─ пропуск          строка, по которой приложение подключается к дому; секрет
   ├─ консьерж         приложение, подключённое по пропуску: держит дверь
   ├─ квартира «Ромашка»      данные одной компании
   │  ├─ прописка      Анна — роль owner
   │  ├─ прописка      Олег — роль staff
   │  ├─ матрица       правила квартиры: кому что можно
   │  └─ данные        товары, заказы — строки только этой квартиры
   ├─ квартира «Василёк»      данные другой компании; «Ромашке» не видны
   └─ аккаунты         люди, по одному на весь дом: Анна, Олег, Борис
      ├─ контакт       почта или телефон: он же имя для входа
      └─ ключи         способы войти: пароль, код из письма, ключ API
```

## Слова по порядку

1. **Мастер-ключ** — строка подключения администратора PostgreSQL. Им строят дом и сносят его. В приложение его не кладут: под ним видны данные всех квартир.
2. **Дом** — ваше приложение в базе: схема `v2.<имя>` с тремя таблицами, проверками и общими классами. Дом строит `setup()`.
3. **Пропуск** — строка, которую отдаёт `setup()`. По ней приложение подключается к дому. Это секрет приложения: храните его как пароль.
4. **Консьерж** — приложение, подключённое по пропуску: `const db = await connect(pass, { postman })`. Своих данных у консьержа нет. Он держит дверь: заводит квартиры, зовёт в них людей и впускает их по ключам.
5. **Квартира** — «чьи данные»: компания, магазин, клуб. Строки одной квартиры другим квартирам не видны — за этим следит сама база.
6. **Аккаунт** — человек. Аккаунт один на весь дом, даже если человек живёт в нескольких квартирах. У аккаунта есть имя: его видят соседи по квартире.
7. **Контакт** — почта, телефон или Telegram человека. У аккаунта один контакт, и он же — **имя для входа**.
8. **Приглашение** — так человека зовут в квартиру. **Письмо** со **ссылкой** ему доставляет **почтальон** — функция вашего приложения. Библиотека сама ничего не отправляет.
9. **Прописка** — запись «этот аккаунт живёт в этой квартире». Прописку даёт только принятое приглашение.
10. **Роль** — метка прописки (`owner`, `staff`). Сама роль ничего не разрешает: права ей выдаёт матрица.
11. **Ключ** — способ войти: пароль, код из письма, ключ API. Пароль и ключ API открывают одну квартиру. Код из письма доказывает контакт: после него человек выбирает квартиру из своих.
12. **Жилец** — аккаунт, вошедший ключом. Он получает **корень квартиры** — объект, от которого идут все запросы: `me.Product().rows()`.
13. **Матрица** — правила квартиры: кому что можно. Правила выдают ролям, а не людям. Когда к строке подходит несколько правил, побеждает правило с большим **счётом**.

## Как человек попадает в квартиру

Регистрации нет: в квартиру попадают только по приглашению.

```text
 жилец или консьерж            почтальон                  человек
 ──────────────────            ─────────                  ───────
 invite(контакт, роли) ──────▶ письмо со ссылкой ───────▶ открыл ссылку
                                                          нажал «Принять»
                               db.accept(token) ◀──────── 
                               аккаунт + прописка ──────▶ человек в квартире
```

Весь путь по шагам, почтальон и края — на странице [«Приглашения и почтальон»](../invites/).

## Кто что может

| Кто | Чем входит | Может | Не может |
|---|---|---|---|
| тот, кто развёртывает приложение | мастер-ключ | построить, достроить и снести дом, записать общие классы, загрузить много данных, запустить обслуживание | — поэтому мастер-ключ не кладут в веб-приложение |
| консьерж (`db`) | пропуск | заводить и удалять квартиры, звать людей, впускать по ключам, удалить аккаунт (`db.deleteAccount`), чистить просроченное (`db.maintain`); в квартире — работать самому (`db.in`) или с правами жильца (`db.as`) | работать с данными без квартиры, править ключи жильцов |
| жилец (`me`) | ключ | работать с данными своей квартиры по матрице, звать людей с ролями, которые ему можно выдавать, править свои ключи, контакт и имя, выйти, выписаться, удалить свой аккаунт | войти в квартиру, где он не прописан, прописать человека без приглашения |

## Как это выглядит в коде

Четыре шага — четыре участника. `models` — описания классов из главы [«Модели»](../models/).

```ts
import { setup, connect, type Letter } from 'letopis'

// 1. Мастер-ключом — один раз, при развёртывании: построить дом и получить пропуск
const { pass } = await setup(process.env.ADMIN_DSN!, 'shop', { models })

// 2. Приложение подключается пропуском: db — консьерж. Почтальон здесь учебный: запоминает письма
const mail: Letter[] = []
const db = await connect(pass, { postman: async (letter) => { mail.push(letter) } })
await db.createTenant('Ромашка')                                        // квартира

// 3. Консьерж зовёт Анну; почтальон получает письмо с токеном; Анна принимает приглашение
await (await db.in('Ромашка')).invite({ email: 'anna@romashka.ru' }, ['owner'])
const letter = mail.at(-1)!.message                                     // в приложении токен приходит из ссылки
const anna = await db.accept(letter.kind === 'invite' ? letter.token : '', { password: 'Ромашка-2026!', name: 'Анна' })

// 4. Завтра Анна входит ключом: me — корень квартиры жильца
const me = await db.open({ email: 'anna@romashka.ru', password: 'Ромашка-2026!' })
const products = await me.Product().rows()                              // запрос идёт с правами Анны
```

Контакт `{ email: 'anna@romashka.ru' }` — это и адрес для письма, и имя для входа.

## Три правила

- **Мастер-ключ — только для развёртывания.** Веб-приложению хватает пропуска. Под пропуском база проверяет каждый запрос сама.
- **Пропуск — секрет.** Держите его в переменной окружения или в хранилище секретов, не в репозитории. Утёк — выдайте новый: `setup(…, { rotate: true })`.
- **Консьерж — не жилец.** Он может зайти в квартиру сам (`await db.in('Ромашка')`) или от имени жильца (`await db.as(аккаунт, 'Ромашка')`), но ключей и прописки у него нет. Подробно — рецепт [«Фоновые задачи консьержа»](../recipes/background).
