# Глоссарий

На страницах сайта первое упоминание каждого термина подчёркнуто пунктиром: наведите на него указатель (или перейдите к нему клавишей Tab) — появится определение из этой таблицы.

Одно понятие — одно слово. Колонка «По-английски» — те же понятия в английском README пакета (`lib/README.en.md`). Синонимы, которых сайт не пишет, и чем их заменить — в словаре `guide/coverage/terms.ts`; сверку страниц и примеров со словарём делает `guide/scripts/check-terms.ts`. Как связаны аккаунт, арендатор, членство, роль и сессия — на [карте понятий](../concepts/).

| Термин | По-английски | Что это | Где подробнее |
|---|---|---|---|
| объект (`entity`) | object (`entity`) | одна запись данных: класс, данные, концы, номер версии; в таблице `entity` у каждого объекта одна строка — его текущее состояние | [что такое letopis](../basics/what-is) |
| журнал (`log`) | journal (`log`) | все версии всех объектов: кто, когда, что и почему | [история и время](../history/) |
| секреты (`secret`) | secrets (`secret`) | пароли, ключи, коды, сессии — только хэшами | [вход](../auth/) |
| класс | class | описание вида объектов: поля, ключ, концы, политика истории; сам хранится строкой `Class` | [модели](../models/) |
| hub, link | hub, link | виды классов в `letopis/model`: `hub()` — обычные объекты (магазин, товар), `link()` — класс-связка объектов со своими данными (строка заказа) | [модели](../models/) |
| алиас | alias | второе имя класса; им тоже можно назвать шаг цепочки | [модели](../models/) |
| System | System | системный арендатор с общими для всех классами установки; на его объекты могут ссылаться все арендаторы | [модели](../models/) |
| ключ, v5-id | key, v5 id | поля и концы, однозначно задающие объект; id вычисляется из арендатора, класса и значений ключа (UUID v5 — id, полученный хэшированием этих значений), поэтому второй такой же объект база не создаст | [модели](../models/) |
| конец | end | именованный указатель объекта на другой объект; имя конца — роль (`Shop`, `Party`); бывает одиночным и множественным (список целей) | [модели](../models/) |
| цель | target | объект, на который ведёт конец; в записи и удалении — объект, который выбрал шаг цепочки | [модели](../models/) |
| ключ API, ключ сервиса | API key, service key | секрет, с которым сервис или интеграция входит в letopis: `connect({ apiKey })`; выдаётся один раз | [установка](../install/) |
| версия структуры | structure version | номер устройства таблиц letopis в имени схемы — `v2.` в `v2.shop`; `up()` и `connect()` подставляют его сами | [установка](../install/) |
| агрегаты по полю, итоги чтения | read aggregates | `sum`, `avg`, `min`, `max`, `countBy` — итоги по строкам последнего шага, их считает база при чтении (не путать с агрегатным полем) | [чтение](../read/) |
| цепочка | chain | запрос шагами: `db.Shop(фильтр).Product().rows()` | [чтение](../read/) |
| шаг | step | звено цепочки: класс (или роль конца) с необязательным фильтром; каждый следующий шаг переходит по концам | [чтение](../read/) |
| терминал | terminal | завершающий вызов цепочки — `rows`, `first`, `ids`, `count`…; только он отправляет запрос в базу | [запись](../write/) |
| глагол | verb | шаг записи в цепочке: `create`, `update`, `upsert`, `delete`, `restore`, `purge`, `reclass`, `rekey`, `anonymize` | [запись](../write/) |
| батч | batch | `db.batch(имя)`: копит планы записи и выполняет их одной транзакцией | [запись](../write/) |
| фасад | facade | объект, через который работают с базой: `db`, `db.as(…)`, `db.begin()`; у каждого своя очередь батча | [запись](../write/) |
| версия (`rev`) | version (`rev`) | номер версии объекта; правка с `{ rev }` не затрёт чужую | [запись](../write/) |
| причина (`reason`) | reason | зачем сделана правка — пишется в журнал рядом с версией | [история и время](../history/) |
| предпросмотр удаления | delete preview | `delete()` без `{ confirm: true }` ничего не удаляет, а показывает, что удалится | [удаление](../delete/) |
| надгробие | tombstone | версия `delete`: объекта нет, история есть — `restore` вернёт его с прежним id | [удаление](../delete/) |
| действие при удалении (`onDelete`) | delete action (`onDelete`) | что делать со строками, чьи концы ведут на удаляемую цель; задаётся у конца в модели: `cascade` — удалить их вместе с целью, `restrict` — запретить удаление, пока такие концы есть (по умолчанию), `unset` — очистить конец (только у необязательных концов и списков) | [удаление](../delete/) |
| аккаунт | account | пользователь, сервис или организация — строка класса `Account` в System; каждый аккаунт — сам себе арендатор | [карта понятий](../concepts/) |
| арендатор | tenant | владелец данных: компания, салон — аккаунт, в чьих данных идёт работа; чужие строки отсекает база (RLS) | [права](../access/) |
| RLS | RLS (Row-Level Security) | Row-Level Security — политики PostgreSQL, которые прямо в базе скрывают чужие и запрещённые строки | [права](../access/) |
| личный арендатор | own tenant | у каждого аккаунта — свой: сам аккаунт; свежая сессия работает в нём | [вход](../auth/#сессии-и-арендаторы) |
| членство (`member`) | membership (`member`) | связь «пользователь — арендатор» с ролями: даёт работать в чужом арендаторе | [права](../access/) |
| роль | role | роль в членстве (`owner`, `staff`, `admin` в System) — на неё выдают права; имя конца (`Shop`) — тоже роль; роль приложения — роль PostgreSQL, под которой подключается приложение | [карта понятий](../concepts/#роль-три-значения) |
| правило (`rule`), ресурс (`Resource`) | rule, resource | `Resource` описывает «кто» (группу людей) или «что» (действие над классом, эндпоинт); `rule` связывает их и говорит, можно или нельзя и с каким весом; проверяет база | [права](../access/) |
| сессия | session | вход пользователя или сервиса; токен у клиента, хэш — в `secret`; помнит аккаунт и арендатора, в котором идёт работа | [вход](../auth/) |
| TOTP, OTP | TOTP, OTP | второй фактор и вход по коду: TOTP — код из приложения-аутентификатора, OTP — одноразовый код, который сервис присылает письмом или СМС | [вход](../auth/) |
| работа от имени | acting on behalf (impersonation) | `db.as(аккаунт)`: сервис действует с правами пользователя, журнал помнит исполнителя (`agent`) | [карта понятий](../concepts/) |
| политика хранения, ярусы | retention policy, tiers | сколько версий хранить: свежие — все, старше — по одной на день, неделю, месяц, год | [история и время](../history/#хранение-по-ярусам) |
| прореживание | thinning | удаление лишних по политике версий — делает `maintain()` | [история и время](../history/) |
| срез на момент | point-in-time read (`asOf`) | `asOf(момент)` — данные такими, какими были тогда | [история и время](../history/) |
| реестр классов | class registry | описания классов, которые подключение держит в памяти; обновляется сам по сигналу, сразу — `db.refresh()` | [история и время](../history/) |
| подписка, курсор | subscription, cursor | `watch()` отдаёт изменения по порядку журнала; курсор — откуда продолжить | [подписка](../watch/) |
| сигнал | signal | короткое уведомление базы (PostgreSQL `NOTIFY`) «данные изменились» — будит подписки и сбрасывает кэш | [подписка](../watch/) |
| SSE | SSE (Server-Sent Events) | Server-Sent Events — поток событий от сервера в браузер; так сервисы-примеры передают события подписки | [подписка](../watch/) |
| кэш результатов | result cache | повтор того же запроса — без похода в базу, пока данные не изменились | [подписка](../watch/) |
| агрегат | aggregate field | поле, которое считает база: сумма или счёт строк другого класса | [агрегаты](../derived/) |
| проектор | projector | процесс, который по журналу пишет производный класс (выписку, отчёт) | [агрегаты](../derived/) |
| первая заливка | initial load | `load(…, { initial: true })` — быстрая загрузка в пустую схему | [загрузка](../load/) |
| цепочка хэшей | hash chain | хэш каждой версии включает хэш предыдущей; `verify()` находит правки в обход библиотеки | [эксплуатация](../ops/) |
| установка | installation | letopis в одной схеме базы (`v2.<имя>`): таблицы, триггеры и политики доступа, которые ставит `up()` | [установка](../install/) |
| стенд | test installation | тестовая установка, не рабочая: в ней можно сбрасывать данные (`allowReset`) | [эксплуатация](../ops/) |
| сид (`seeds`) | seed | готовый набор классов, который ставит `up()`: `'booking'` — модель салона | [установка](../install/) |
| ревизия схемы, штамп движка | engine revision, engine stamp | ревизия — версия SQL-части letopis; `up()` пишет её, версию пакета и хэш SQL в комментарий схемы (штамп), а `connect()` сверяет штамп с пакетом | [установка](../install/) |
| `allowReset` | `allowReset` | флаг установки для тестовых баз: разрешает `reset` и `maintain({ now })` | [эксплуатация](../ops/) |
| MCP | MCP (Model Context Protocol) | протокол для ИИ-агентов: letopis даёт им инструменты с правами пользователя | [MCP](../mcp/) |
