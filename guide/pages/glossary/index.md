# Глоссарий

На страницах сайта первое упоминание каждого термина подчёркнуто пунктиром: наведите на него указатель (или перейдите к нему клавишей Tab) — появится определение из этой таблицы.

Одно понятие — одно слово: на всех страницах сайта понятие называется так, как в этой таблице. Термины — по алфавиту, сначала русские, затем латинские. Как связаны дом, консьерж, квартира, аккаунт, ключ, прописка и роль — на [карте понятий](../concepts/).

| Термин | Что это | Где подробнее |
|---|---|---|
| агрегаты по полю, итоги чтения | `sum`, `avg`, `min`, `max`, `countBy` — итоги по строкам последнего шага, их считает база при чтении | [чтение](../read/) |
| аккаунт | человек — строка класса `Account` в System, один на весь дом: появляется, когда человек принимает приглашение (`db.accept`); у аккаунта один контакт — он же имя для входа; в квартирах у него прописки, в каждой квартире — свои ключи | [карта понятий](../concepts/) |
| алиас | второе имя класса; им тоже можно назвать шаг цепочки | [модели](../models/) |
| батч | `me.batch(имя)`: копит планы записи и выполняет их одной транзакцией | [запись](../write/) |
| версия (`rev`) | номер версии объекта; правка с `{ rev }` не затрёт чужую | [запись](../write/) |
| версия структуры | номер устройства таблиц letopis в имени схемы дома — `v2.` в `v2.shop`; `setup()` и пропуск подставляют его сами | [установка](../install/) |
| глагол | шаг записи в цепочке: `create`, `update`, `upsert`, `delete`, `restore` | [запись](../write/) |
| действие при удалении (`onDelete`) | что делать со строками, чьи концы ведут на удаляемую цель; задаётся у конца в модели: `cascade` — удалить их вместе с целью, `restrict` — запретить удаление, пока такие концы есть (по умолчанию), `unset` — очистить конец (только у необязательных концов и списков) | [удаление](../delete/) |
| дом | приложение в базе: схема `v2.<имя>` с таблицами, триггерами и политиками доступа letopis, общими классами, квартирами и матрицей; строит и достраивает `setup(мастер-ключ, имя)`, сносит `demolish(мастер-ключ, имя)` | [дом, пропуск, консьерж](../house/) |
| жилец | аккаунт, который вошёл в квартиру: `db.open(ключ)` или `db.accept(token)` даёт корень квартиры `me` с его правами | [вход](../auth/) |
| журнал (`log`) | все версии всех объектов: кто, когда, что и почему | [история и время](../history/) |
| квартира | компания, салон, команда — отдельные данные внутри дома: строка `Account` в System с уникальным именем; заводит `db.createTenant(имя)`; чужие строки отсекает база (RLS) | [права](../access/) |
| класс | описание вида объектов: поля, ключ класса, концы, ведёт ли журнал (`history`); сам хранится строкой `Class` | [модели](../models/) |
| ключ | способ входа аккаунта: пароль (с TOTP), ключ API, ключ и секрет, внешний вход — каждый открывает ровно одну квартиру; пароль можно задать уже при `db.accept`, остальные ключи жилец заводит сам (`me.keys`); вход кодом (`db.requestCode`) доказывает контакт, а квартиру выбирают при входе | [вход](../auth/) |
| ключ API | вид ключа для программ и ИИ-агентов — строка `lts_…`: вход `db.open({ apiKey })`, агент — `letopis mcp --api-key`; выдаёт `me.keys.issueApiKey()`, показывает один раз | [вход](../auth/) |
| ключ класса, v5-id | поля и концы, однозначно задающие объект; id вычисляется из квартиры, класса и значений ключа класса (UUID v5 — id, полученный хэшированием этих значений), поэтому второй такой же объект база не создаст | [модели](../models/) |
| конец, имя конца | именованный указатель объекта на другой объект; имя конца (`Shop`, `Party`) — шаг с этим именем переходит по концу, после глагола `.Конец.set(…)` задаёт его; бывает одиночным и множественным (список целей) | [модели](../models/) |
| консьерж | приложение в доме: роль базы и аккаунт-служба с ключом, их заводит `setup()`; подключается пропуском — `const db = await connect(pass, { postman })` — и держит дверь: вход по ключам и кодам, приглашения, квартиры, обслуживание `db.maintain()`; в квартиру входит `db.in(квартира)` с полным доступом или `db.as(аккаунт, квартира)` с правами жильца | [дом, пропуск, консьерж](../house/) |
| контакт | почта, телефон, Telegram и т. п. — `{ email }`, `{ phone }`, `{ telegram }` или `{ kind, address }`: на него зовут и шлют коды; у аккаунта контакт один, он же имя для входа; один контакт — один аккаунт во всём доме, регистр букв не важен; сменить — `me.changeContact()` с кодом, который почтальон доставит на новый контакт | [приглашения](../invites/) |
| корень квартиры | объект цепочек одной квартиры — `me` (тип в коде — `Room`): `me.Класс(фильтр)`, `me.sql`, `me.begin()`, `me.acl`; жильцу его дают `db.open`, `db.resume`, `db.accept`, консьержу — `db.in`, `db.as`; у каждого корня и у транзакции `me.begin()` своя очередь батча | [чтение](../read/) |
| кэш результатов | повтор того же запроса — без похода в базу, пока данные не изменились | [подписка](../watch/) |
| мастер-ключ | строка подключения администратора PostgreSQL: ею строят и сносят дом (`setup`, `demolish`) и запускают служебные команды `letopis sync`, `types`, `load`, `maintain`; в приложение её не кладут | [установка](../install/) |
| матрица | права квартиры: правила System и квартиры; для каждой строки, каждого действия API и каждой роли побеждает подходящее правило с наибольшим счётом; ничья «можно» против «нельзя» — строка не видна, а `me.acl.check` и запись спорящего правила отвечают `acl_ambiguous`; подходящих нет — правило по умолчанию (на свежем доме — «нельзя»; ролей оно не выдаёт никогда) | [права](../access/) |
| надгробие | версия `delete`: объекта нет, история есть — `restore({ expect: [надгробие] })` вернёт его с прежним id | [удаление](../delete/) |
| объект (`entity`) | одна запись данных: класс, данные, концы, номер версии; в таблице `entity` у каждого объекта одна строка — его текущее состояние | [что такое letopis](../basics/what-is) |
| первая заливка | `letopis load --initial` — быстрая загрузка в пустой дом одной транзакцией | [загрузка](../load/) |
| письмо | то, что библиотека передаёт почтальону: `{ to, message }` — кому (контакт `{ kind, address }`) и что: `kind: 'invite'` — токен ссылки приглашения, `'code'` — код входа, `'contact'` — код смены контакта | [приглашения](../invites/) |
| подписка, курсор | `me.watch()` отдаёт изменения по порядку журнала; курсор — откуда продолжить | [подписка](../watch/) |
| почтальон | функция приложения `postman({ to, message })` из `connect(pass, { postman })`: только доставляет письма — ссылку приглашения и коды — почтой, СМС или как угодно; токены и коды придумывает, хранит и проверяет библиотека, а сама ничего не шлёт; без почтальона `invite`, `requestCode` и `changeContact` отвечают `no_postman`, а ошибка почтальона отменяет операцию (`postman_failed`) | [приглашения](../invites/) |
| правило (`rule`), ресурс (`Resource`) | строки матрицы: ресурс — маска «кто» (роли, категории аккаунта) или «что» (класс с условием на строки, действие API, роль, которую можно выдать); правило связывает их — можно или нельзя и с каким весом; меняет правило тот, кто его завёл, или консьерж | [права](../access/) |
| предпросмотр удаления | `delete()` без `{ confirm: true }` ничего не удаляет, а показывает, что удалится; его же передают в `expect` подтверждения | [удаление](../delete/) |
| приглашение | ссылка со сроком (по умолчанию 7 суток), которой зовут человека в квартиру: `me.invite(контакт, роли)` → `{ id, expiresAt }`, а ссылку с токеном получает только почтальон; посмотреть — `db.invitation(token)`, принять — `db.accept(token, { password? })`: человек получает аккаунт (или его аккаунт — новую прописку) с ролями приглашения | [приглашения](../invites/) |
| причина (`reason`) | зачем сделана правка — пишется в журнал рядом с версией | [история и время](../history/) |
| прописка (`member`) | аккаунт в квартире с ролями — строка `member`; заводит её только приглашение, роли меняют правка `member` или `me.acl.roles()` (если матрица разрешает выдать и снять эти роли), выписка — `.delete()` или `me.leave()`: ключи этой квартиры гаснут | [права](../access/) |
| пропуск | строка подключения консьержа, в ней дом и ключ консьержа: её отдаёт `setup()` (повтор — тот же пропуск, `rotate` — новый, прежний сразу перестаёт работать); приложение хранит её как секрет | [дом, пропуск, консьерж](../house/) |
| работа от имени | `db.as(аккаунт, квартира)`: консьерж работает в квартире с правами прописанного жильца | [карта понятий](../concepts/) |
| ревизия движка, штамп движка | ревизия — версия SQL-части letopis; `setup()` пишет её, версию пакета и хэш SQL в комментарий схемы (штамп), а `connect()` сверяет штамп с пакетом; дом другой ревизии не обновляется — его сносят `demolish()` и строят заново | [установка](../install/) |
| реестр классов | описания классов, которые корень квартиры держит в памяти; обновляется сам по сигналу, сразу — `me.refresh()` | [эксплуатация](../ops/) |
| роль, метка прописки | имя в прописке (`owner`, `staff`); сама роль ничего не разрешает — права ей даёт только матрица: `me.acl.grant({ role: 'staff', read: … })`; выдать роль (позвать с ней, вписать в прописку) можно, только если правило разрешает это звавшему — `me.acl.grant({ role: 'manager', assign: 'staff' })` | [права](../access/) |
| секреты (`secret`) | таблица контактов, ключей, кодов, приглашений, сессий и пропуска консьержа; пароли, коды и токены хранятся хэшами | [вход](../auth/) |
| сессия | вход по ключу, коду или приглашению: токен у клиента (`me.token`), хэш — в `secret`; помнит аккаунт и квартиру; продолжить работу по токену — `db.resume(токен)` | [вход](../auth/) |
| сигнал | короткое уведомление базы (PostgreSQL `NOTIFY`) «данные изменились» — будит подписки и сбрасывает кэш | [подписка](../watch/) |
| сид (`seeds`) | готовый набор классов, который ставит `setup()`: `'booking'` — модель салона | [установка](../install/) |
| срез на момент | `asOf(момент)` — данные такими, какими были тогда | [история и время](../history/) |
| стенд | тестовая установка, не рабочая: например, сервисы-примеры и сайт с песочницей в Docker | [песочница](../sandbox) |
| строгий режим | проверки до обращения к базе: `update()` и `delete({ confirm: true, expect })` без условий (все строки — `{ all: true }`), `delete({ confirm: true })` без `expect` и `restore()` без `expect`, неизвестная опция, `after()` перед счётом — отказ | [модели](../models/inside#строгии-режим) |
| счёт | сила правила для строки, действия или роли: число ключей маски «кто» + 1 за класс, действие или роль + число полей условия + 1 у запрета + вес правила; побеждает наибольший | [права](../access/) |
| терминал | завершающий вызов цепочки — `rows`, `first`, `ids`, `count`…; только он отправляет запрос в базу | [чтение](../read/) |
| цель | объект, на который ведёт конец; в записи и удалении — объект, который выбрал шаг цепочки | [модели](../models/) |
| цепочка | запрос шагами: `me.Shop(фильтр).Product().rows()` | [чтение](../read/) |
| шаг | звено цепочки: класс (или имя конца) с необязательным фильтром; каждый следующий шаг переходит по концам | [чтение](../read/) |
| hub, link | виды классов в `letopis/model`: `hub()` — обычные объекты (магазин, товар), `link()` — класс-связка объектов со своими данными (строка заказа) | [модели](../models/) |
| MCP | протокол для ИИ-агентов: letopis даёт им инструменты с правами жильца | [MCP](../mcp/) |
| RLS | Row-Level Security — политики PostgreSQL, которые прямо в базе скрывают чужие и запрещённые строки | [права](../access/) |
| SSE | Server-Sent Events — поток событий от сервера в браузер; так сервисы-примеры передают события подписки | [подписка](../watch/) |
| System | общая часть дома: аккаунты, квартиры, общие классы (модели `setup({ models })`) и правила по умолчанию; на её объекты могут ссылаться все квартиры | [модели](../models/) |
| TOTP, OTP | TOTP — второй фактор ключа-пароля: код из приложения-аутентификатора (`me.keys.enrollTotp()`, вход — `db.open({ phone, password, totp })`); OTP — одноразовый код для входа: `db.requestCode(контакт)`, код доставляет почтальон, вход — `db.open({ phone, code, tenant? })` | [вход](../auth/) |
