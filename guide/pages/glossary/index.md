# Глоссарий

На страницах сайта первое упоминание каждого термина подчёркнуто пунктиром: наведите на него указатель (или перейдите к нему клавишей Tab) — появится определение из этой таблицы.

| Термин | Что это | Где подробнее |
|---|---|---|
| объект, сущность (`entity`) | одна запись данных: класс, данные, ссылки, номер версии; в таблице `entity` у каждого объекта одна строка — его текущее состояние | [что такое letopis](../basics/what-is) |
| журнал (`log`) | все версии всех объектов: кто, когда, что и почему | [история и время](../history/) |
| секреты (`secret`) | пароли, ключи, коды, сессии — только хэшами | [вход](../auth/) |
| класс | описание вида объектов: поля, ключ, ссылки, политика истории; сам хранится строкой `Class` | [модели](../models/) |
| hub, link | виды классов в `letopis/model`: `hub()` — обычные объекты (магазин, товар), `link()` — класс-связка объектов со своими данными (строка заказа) | [модели](../models/) |
| алиас | второе имя класса; им тоже можно назвать шаг цепочки | [модели](../models/) |
| System | системный арендатор с общими для всех классами установки; на его объекты могут ссылаться все арендаторы | [модели](../models/) |
| ключ, v5-id | поля и концы, однозначно задающие объект; id вычисляется из арендатора, класса и значений ключа (UUID v5 — id, полученный хэшированием этих значений), поэтому второй такой же объект база не создаст | [модели](../models/) |
| конец (end), ссылка | именованная ссылка объекта на другой объект; имя конца — роль (`Shop`, `Party`); бывает одиночной и множественной (список) | [модели](../models/) |
| цель | объект, на который ведёт ссылка; в записи и удалении — объект, который выбрал шаг цепочки | [модели](../models/) |
| цепочка | запрос шагами: `db.Shop(фильтр).Product().rows()` | [чтение](../read/) |
| шаг | звено цепочки: класс (или роль ссылки) с необязательным фильтром; каждый следующий шаг переходит по ссылкам | [чтение](../read/) |
| терминал | завершающий вызов цепочки — `rows`, `first`, `ids`, `count`…; только он отправляет запрос в базу | [запись](../write/) |
| глагол | шаг записи в цепочке: `create`, `update`, `upsert`, `delete`, `restore`, `purge`, `reclass`, `rekey`, `anonymize` | [запись](../write/) |
| батч | `db.batch(имя)`: копит планы записи и выполняет их одной транзакцией | [запись](../write/) |
| фасад | объект, через который работают с базой: `db`, `db.as(…)`, `db.begin()`; у каждого своя очередь батча | [запись](../write/) |
| версия (`rev`) | номер версии объекта; правка с `{ rev }` не затрёт чужую | [запись](../write/) |
| причина (`reason`) | зачем сделана правка — пишется в журнал рядом с версией | [история и время](../history/) |
| предпросмотр удаления | `delete()` без `{ confirm: true }` ничего не удаляет, а показывает, что удалится | [удаление](../delete/) |
| надгробие | версия `delete`: объекта нет, история есть — `restore` вернёт его с прежним id | [удаление](../delete/) |
| действие при удалении (`onDelete`) | что делать со строками, которые ссылаются на удаляемую цель; задаётся у конца в модели: `cascade` — удалить их вместе с целью, `restrict` — запретить удаление, пока ссылки есть (по умолчанию), `unset` — снять ссылку (только у необязательных концов и списков) | [удаление](../delete/) |
| арендатор | владелец данных: компания, салон; чужие строки отсекает база (RLS) | [права](../access/) |
| RLS | Row-Level Security — политики PostgreSQL, которые прямо в базе скрывают чужие и запрещённые строки | [права](../access/) |
| личный арендатор | у каждой учётной записи — свой; свежая сессия работает в нём | [вход](../auth/#сессии-и-арендаторы) |
| членство (`member`) | учётная запись в чужом арендаторе с ролями | [права](../access/) |
| правило (`rule`), ресурс (`Resource`) | `Resource` описывает «кто» (группу людей) или «что» (действие над классом, эндпоинт); `rule` связывает их и говорит, можно или нельзя и с каким весом; проверяет база | [права](../access/) |
| сессия | вход пользователя или сервиса; токен у клиента, хэш — в `secret` | [вход](../auth/) |
| TOTP, OTP | второй фактор и вход по коду: TOTP — код из приложения-аутентификатора, OTP — одноразовый код, который сервис присылает письмом или СМС | [вход](../auth/) |
| работа от имени | `db.as(аккаунт)`: сервис действует с правами пользователя, журнал помнит исполнителя (`agent`) | [права](../access/) |
| политика хранения, ярусы | сколько версий хранить: свежие — все, старше — по одной на день, неделю, месяц, год | [история и время](../history/#хранение-по-ярусам) |
| прореживание | удаление лишних по политике версий — делает `maintain()` | [история и время](../history/) |
| срез на момент | `asOf(момент)` — данные такими, какими были тогда | [история и время](../history/) |
| реестр классов | описания классов, которые подключение держит в памяти; обновляется сам по сигналу, сразу — `db.refresh()` | [история и время](../history/) |
| подписка, курсор | `watch()` отдаёт изменения по порядку журнала; курсор — откуда продолжить | [подписка](../watch/) |
| сигнал | короткое уведомление базы (PostgreSQL `NOTIFY`) «данные изменились» — будит подписки и сбрасывает кэш | [подписка](../watch/) |
| SSE | Server-Sent Events — поток событий от сервера в браузер; так сервисы-примеры передают события подписки | [подписка](../watch/) |
| кэш результатов | повтор того же запроса — без похода в базу, пока данные не изменились | [подписка](../watch/) |
| агрегат | поле, которое считает база: сумма или счёт строк другого класса | [агрегаты](../derived/) |
| проектор | процесс, который по журналу пишет производный класс (выписку, отчёт) | [агрегаты](../derived/) |
| первая заливка | `load(…, { initial: true })` — быстрая загрузка в пустую схему | [загрузка](../load/) |
| цепочка хэшей | хэш каждой версии включает хэш предыдущей; `verify()` находит правки в обход библиотеки | [эксплуатация](../ops/) |
| установка | letopis в одной схеме базы (`v2.<имя>`): таблицы, триггеры и политики доступа, которые ставит `up()` | [установка](../install/) |
| стенд | тестовая установка, не рабочая: в ней можно сбрасывать данные (`allowReset`) | [эксплуатация](../ops/) |
| сид (`seeds`) | готовый набор классов, который ставит `up()`: `'booking'` — модель салона | [установка](../install/) |
| ревизия схемы, штамп движка | ревизия — версия SQL-части letopis; `up()` пишет её, версию пакета и хэш SQL в комментарий схемы (штамп), а `connect()` сверяет штамп с пакетом | [установка](../install/) |
| `allowReset` | флаг установки для тестовых баз: разрешает `reset` и `maintain({ now })` | [эксплуатация](../ops/) |
| MCP | протокол для ИИ-агентов: letopis даёт им инструменты с правами пользователя | [MCP](../mcp/) |
