# Глоссарий

На страницах сайта первое упоминание каждого термина подчёркнуто пунктиром: наведите на него указатель (или перейдите к нему клавишей Tab) — появится определение из этой таблицы.

Одно понятие — одно слово. Синонимы, которых сайт не пишет, и чем их заменить — в словаре `guide/coverage/terms.ts`; сверку страниц и примеров со словарём делает `guide/scripts/check-terms.ts`. Как связаны аккаунт, арендатор, членство, роль и сессия — на [карте понятий](../concepts/).

| Термин | Что это | Где подробнее |
|---|---|---|
| объект (`entity`) | одна запись данных: класс, данные, концы, номер версии; в таблице `entity` у каждого объекта одна строка — его текущее состояние | [что такое letopis](../basics/what-is) |
| журнал (`log`) | все версии всех объектов: кто, когда, что и почему | [история и время](../history/) |
| секреты (`secret`) | пароли, ключи, коды, сессии — только хэшами | [вход](../auth/) |
| класс | описание вида объектов: поля, ключ, концы, ведёт ли журнал (`history`); сам хранится строкой `Class` | [модели](../models/) |
| hub, link | виды классов в `letopis/model`: `hub()` — обычные объекты (магазин, товар), `link()` — класс-связка объектов со своими данными (строка заказа) | [модели](../models/) |
| алиас | второе имя класса; им тоже можно назвать шаг цепочки | [модели](../models/) |
| System | системный арендатор с общими для всех классами установки; на его объекты могут ссылаться все арендаторы | [модели](../models/) |
| ключ, v5-id | поля и концы, однозначно задающие объект; id вычисляется из арендатора, класса и значений ключа (UUID v5 — id, полученный хэшированием этих значений), поэтому второй такой же объект база не создаст | [модели](../models/) |
| конец | именованный указатель объекта на другой объект; имя конца — роль (`Shop`, `Party`); бывает одиночным и множественным (список целей) | [модели](../models/) |
| цель | объект, на который ведёт конец; в записи и удалении — объект, который выбрал шаг цепочки | [модели](../models/) |
| ключ API, ключ сервиса | секрет, с которым сервис или интеграция входит в letopis: `connect({ apiKey })`; выдаётся один раз | [установка](../install/) |
| версия структуры | номер устройства таблиц letopis в имени схемы — `v2.` в `v2.shop`; `up()` и `connect()` подставляют его сами | [установка](../install/) |
| агрегаты по полю, итоги чтения | `sum`, `avg`, `min`, `max`, `countBy` — итоги по строкам последнего шага, их считает база при чтении | [чтение](../read/) |
| цепочка | запрос шагами: `db.Shop(фильтр).Product().rows()` | [чтение](../read/) |
| шаг | звено цепочки: класс (или роль конца) с необязательным фильтром; каждый следующий шаг переходит по концам | [чтение](../read/) |
| терминал | завершающий вызов цепочки — `rows`, `first`, `ids`, `count`…; только он отправляет запрос в базу | [запись](../write/) |
| глагол | шаг записи в цепочке: `create`, `update`, `upsert`, `delete`, `restore` | [запись](../write/) |
| батч | `db.batch(имя)`: копит планы записи и выполняет их одной транзакцией | [запись](../write/) |
| фасад | объект, через который работают с базой: `db`, `db.as(…)`, `db.begin()`; у каждого своя очередь батча | [запись](../write/) |
| строгий режим | проверки до обращения к базе: `update()` и `delete({ confirm: true, expect })` без условий (все строки — `{ all: true }`), `delete({ confirm: true })` без `expect` и `restore()` без `expect`, неизвестная опция, `after()` перед счётом — отказ; строгие типы цепочек при `connect({ models })`, без них — `loose(db)` | [модели](../models/#строгии-режим) |
| версия (`rev`) | номер версии объекта; правка с `{ rev }` не затрёт чужую | [запись](../write/) |
| причина (`reason`) | зачем сделана правка — пишется в журнал рядом с версией | [история и время](../history/) |
| предпросмотр удаления | `delete()` без `{ confirm: true }` ничего не удаляет, а показывает, что удалится; его же передают в `expect` подтверждения | [удаление](../delete/) |
| надгробие | версия `delete`: объекта нет, история есть — `restore({ expect: [надгробие] })` вернёт его с прежним id | [удаление](../delete/) |
| действие при удалении (`onDelete`) | что делать со строками, чьи концы ведут на удаляемую цель; задаётся у конца в модели: `cascade` — удалить их вместе с целью, `restrict` — запретить удаление, пока такие концы есть (по умолчанию), `unset` — очистить конец (только у необязательных концов и списков) | [удаление](../delete/) |
| аккаунт | пользователь, сервис или организация — строка класса `Account` в System; каждый аккаунт — сам себе арендатор | [карта понятий](../concepts/) |
| арендатор | владелец данных: компания, салон — аккаунт, в чьих данных идёт работа; чужие строки отсекает база (RLS) | [права](../access/) |
| RLS | Row-Level Security — политики PostgreSQL, которые прямо в базе скрывают чужие и запрещённые строки | [права](../access/) |
| личный арендатор | у каждого аккаунта — свой: сам аккаунт; свежая сессия работает в нём | [вход](../auth/#сессии-и-арендаторы) |
| членство (`member`) | связь «пользователь — арендатор» с ролями: даёт работать в чужом арендаторе | [права](../access/) |
| роль | роль в членстве (`owner`, `staff`, `admin` в System) — на неё выдают права; имя конца (`Shop`) — тоже роль; роль приложения — роль PostgreSQL, под которой подключается приложение | [карта понятий](../concepts/#роль-три-значения) |
| правило (`rule`), ресурс (`Resource`) | `Resource` описывает «кто» (группу людей) или «что» (действие над классом, эндпоинт); `rule` связывает их и говорит, можно или нельзя и с каким весом; проверяет база | [права](../access/) |
| сессия | вход пользователя или сервиса; токен у клиента, хэш — в `secret`; помнит аккаунт и арендатора, в котором идёт работа | [вход](../auth/) |
| TOTP, OTP | второй фактор и вход по коду: TOTP — код из приложения-аутентификатора, OTP — одноразовый код, который сервис присылает письмом или СМС | [вход](../auth/) |
| работа от имени | `db.as(аккаунт)`: сервис действует с правами пользователя, журнал помнит исполнителя (`agent`) | [карта понятий](../concepts/) |
| срез на момент | `asOf(момент)` — данные такими, какими были тогда | [история и время](../history/) |
| реестр классов | описания классов, которые подключение держит в памяти; обновляется сам по сигналу, сразу — `db.refresh()` | [эксплуатация](../ops/#свои-sql-реестр-кэш-и-сигналы) |
| подписка, курсор | `watch()` отдаёт изменения по порядку журнала; курсор — откуда продолжить | [подписка](../watch/) |
| сигнал | короткое уведомление базы (PostgreSQL `NOTIFY`) «данные изменились» — будит подписки и сбрасывает кэш | [подписка](../watch/) |
| SSE | Server-Sent Events — поток событий от сервера в браузер; так сервисы-примеры передают события подписки | [подписка](../watch/) |
| кэш результатов | повтор того же запроса — без похода в базу, пока данные не изменились | [подписка](../watch/) |
| первая заливка | `load(…, { initial: true })` — быстрая загрузка в пустую схему | [загрузка](../load/) |
| установка | letopis в одной схеме базы (`v2.<имя>`): таблицы, триггеры и политики доступа, которые ставит `up()` | [установка](../install/) |
| стенд | тестовая установка, не рабочая: например, сервисы-примеры и сайт с песочницей в Docker | [песочница](../sandbox) |
| сид (`seeds`) | готовый набор классов, который ставит `up()`: `'booking'` — модель салона | [установка](../install/) |
| ревизия схемы, штамп движка | ревизия — версия SQL-части letopis; `up()` пишет её, версию пакета и хэш SQL в комментарий схемы (штамп), а `connect()` сверяет штамп с пакетом | [установка](../install/) |
| MCP | протокол для ИИ-агентов: letopis даёт им инструменты с правами пользователя | [MCP](../mcp/) |
