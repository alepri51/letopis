# Песочница

Песочница — это способ поменять код любого примера прямо на странице и сразу запустить его на настоящей базе, ничего не устанавливая у себя. Под программой каждого примера есть кнопка «Изменить код и запустить». Она открывает редактор с той же программой, что показана на странице, кнопка «Запустить на базе» её выполняет.

Песочница работает только на локальном сервере сайта — том, что вы запускаете у себя (ниже, «Как включить»). На опубликованном сайте кнопка «Запустить на базе» не сработает.

Как идёт прогон:

1. программа запускается отдельным процессом, как если бы вы запустили её у себя командой `npx tsx`;
2. она сама ставит свою схему в базе с нуля (`up({ fresh: true })`) и выполняет шаги по порядку;
3. всё, что она напечатала, появляется под редактором в блоке «Что напечатала программа», рядом — код выхода и время прогона. Код выхода 0 — программа дошла до конца без ошибок.

Кнопка «Вернуть исходный код» возвращает программу в исходный вид.

::: danger Песочница выполняет код на вашей машине
Присланный код исполняется как есть, с доступом к базе. Поэтому:

- сервер сайта слушает только 127.0.0.1; в Docker порт тоже открыт только на 127.0.0.1;
- код принимается только со страниц самого сайта (проверяются заголовки `Host` и `Origin`), и только в виде JSON. Чужая страница, открытая в том же браузере, отправить его не сможет;
- прогоны идут по очереди, по одному: пока выполняется чужой, ваш ждёт, а под кнопкой видно место в очереди. В очереди не больше 10 прогонов, следующему сервер откажет. Каждый прогон — не дольше 2 минут, потом программа останавливается.

Не открывайте порт сайта наружу и не включайте песочницу на общем сервере.
:::

## Как включить

### Весь стенд в Docker

```sh
docker compose -f services/compose.yaml up -d --build
```

Сайт с песочницей — <http://127.0.0.1:8080> (порт меняет переменная `GUIDE_PORT`, имя стенда — `-p`: [«Сервисы-примеры»](./services/#run)), база — контейнер `pg` стенда. Выключить песочницу: `SANDBOX: '0'` у сервиса `guide` в `services/compose.yaml`.

### Без Docker

Нужны Node 22 или новее и запущенный PostgreSQL 18 с ролью суперпользователя. По умолчанию песочница берёт базу `postgres://postgres:test@localhost:15433/letopis`. Другую базу задаёт `ENTITY_DSN`, например базу из рецепта [«Как запустить пример»](./#run) на главной. Сервер сайта со включённой песочницей (`npm run sandbox`, внутри — `SANDBOX=1`) слушает только 127.0.0.1.

Bash:

```sh
cd lib && npm ci && cd ../guide && npm ci
npm run build                                  # статическая сборка сайта
npm run sandbox                                # сайт и песочница: http://127.0.0.1:8080
ENTITY_DSN=postgres://postgres:guide@127.0.0.1:15440/letopis npm run sandbox   # своя база
```

PowerShell:

```powershell
cd lib; npm ci; cd ../guide; npm ci
npm run build
npm run sandbox
$env:ENTITY_DSN = 'postgres://postgres:guide@127.0.0.1:15440/letopis'; npm run sandbox
```

Программа подключается к базе как приложение через роль `example_app`: её заводит сама программа вызовом `up({ login })` и получает от него строку подключения.

Если вы правите сам сайт: dev-сервер `npm run dev` (порт 5173) отправляет запросы песочницы на `npm run sandbox` (порт 8080). Держите запущенными оба.

## Что можно писать

В редакторе — обычный скрипт на TypeScript, тот же, что вы скопировали бы со страницы и запустили у себя:

- импортировать можно `letopis`, `letopis/model`, `letopis/mcp`, `zod` и `postgres`;
- строка подключения к базе — `process.env.ADMIN_DSN`: песочница подставляет туда свою базу;
- всё, что программа напечатала (`console.log`, `console.error`, текст ошибки), появится под редактором.

Последняя строка программы — `process.exit(0)`: открытые подключения держат процесс, поэтому программа завершает его явно. Свой код дописывайте перед этой строкой.
