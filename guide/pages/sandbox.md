# Песочница

Любой пример на этом сайте можно изменить и запустить на живой базе. Над плеером примера есть ссылка «Изменить код и запустить». Она открывает исходник примера в редакторе, кнопка «Запустить на базе» прогоняет его.

Прогон идёт так же, как запись снимков для сайта:

1. свежая схема;
2. установка с арендатором «Ромашка» и пользователем Анной;
3. шаги по очереди, после каждого — данные таблиц.

Результат появляется в том же плеере с пометкой «Ваш прогон в песочнице». Кнопка «Показать записанный снимок» возвращает исходный. Схема прогона удаляется сразу после него.

::: danger Песочница выполняет код на вашей машине
Присланный код исполняется как есть, с доступом к базе стенда. Поэтому:

- сервер сайта слушает только 127.0.0.1; в Docker порт тоже открыт только на 127.0.0.1;
- код принимается только со страниц самого сайта (проверяются заголовки `Host` и `Origin`), и только в виде JSON. Чужая страница, открытая в том же браузере, отправить его не сможет;
- одновременно идёт один прогон, не дольше 2 минут.

Не открывайте порт сайта наружу и не включайте песочницу на общем сервере.
:::

## Как включить

### Весь стенд в Docker

```sh
docker compose -f services/compose.yaml up -d --build
```

Сайт с песочницей — <http://127.0.0.1:8080>, база — контейнер `pg` стенда. Выключить песочницу: `SANDBOX: '0'` у сервиса `guide` в `services/compose.yaml`.

### Без Docker

Нужны Node 22 или новее и PostgreSQL 18 с ролью суперпользователя. Песочница по умолчанию работает на тестовой базе библиотеки: 127.0.0.1:15433, контейнер `letopis-pg18`. Если есть Docker, контейнер поднимается сам. Другую базу задаёт `ENTITY_DSN`.

Bash:

```sh
cd lib && npm ci && cd ../guide && npm ci
npm run build                                  # статическая сборка сайта
npm run sandbox                                # сайт и песочница: http://127.0.0.1:8080
ENTITY_DSN=postgres://postgres:ПАРОЛЬ@localhost:5432/letopis npm run sandbox   # своя база
```

PowerShell:

```powershell
cd lib; npm ci; cd ../guide; npm ci
npm run build
npm run sandbox
$env:ENTITY_DSN = 'postgres://postgres:ПАРОЛЬ@localhost:5432/letopis'; npm run sandbox
```

В выбранной базе прогон заводит роль `letopis_test_app` с паролем `test` — так работают и тесты библиотеки. Через эту роль примеры подключаются как приложение.

Если вы правите сам сайт: dev-сервер `npm run dev` (порт 5173) отправляет запросы песочницы на `npm run sandbox` (порт 8080). Держите запущенными оба.

## Что можно писать

Исходник — тот же файл, что у всех примеров сайта: `example({ title, steps })`. Каждый шаг — `{ title, text?, run(ctx), expect? }`. В `ctx`:

| Поле | Что это |
|---|---|
| `db` | Анна в арендаторе «Ромашка»: обычная работа пользователя |
| `svc` | сервис приложения, вошёл по ключу |
| `up` | результат установки: ключ сервиса, арендатор, пользователь |
| `admin` | сырой SQL от суперпользователя (postgres.js) |
| `connect(опции)` | ещё одно подключение; раннер закроет его сам |
| `dsn`, `user`, `schema` | строки подключения, логин и пароль Анны, имя схемы прогона |

Импортировать можно `letopis`, `letopis/model`, `letopis/mcp`, `zod` и помощников сайта из `../../kit/`. Например, `seedShop` — модель и данные магазина из главы о модели.

Шаг с `expect: { error: 'код' }` обязан упасть с этим кодом. Если шаг упал не так, как обещает пример, плеер всё равно покажет прогон, а над ним появятся «Замечания прогона». Так же сверка снимков ловит изменения поведения библиотеки.
