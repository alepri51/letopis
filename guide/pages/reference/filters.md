# Операторы фильтров

Операторы ставятся значением поля в фильтре шага цепочки: `db.Product({ price: gt(100) })`. Все — из основного пакета: `import { gt, or } from 'letopis'`.

**Что здесь:** [Операторы фильтров](#операторы-фильтров). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Операторы фильтров

Оператор ставится значением поля в фильтре шага, простое значение — равенство. Колонка MCP — ключи JSON-фильтра инструмента `letopis_query`; `$or` ставится вместо всего фильтра.

| TypeScript | MCP | Смысл |
|---|---|---|
| `ne(v)` | `{ "$ne": v }` | Не равно. Подходят и строки без поля или с `null`; `ne(null)` — строки, где у поля есть значение |
| `gt(v)` | `{ "$gt": v }` | Больше. Сравнение — по типу поля из описания класса (числа — как числа, даты — как даты), поле без описания — как текст; строки без поля не подходят |
| `gte(v)` | `{ "$gte": v }` | Больше или равно; сравнение — как у `gt` |
| `lt(v)` | `{ "$lt": v }` | Меньше; сравнение — как у `gt` |
| `lte(v)` | `{ "$lte": v }` | Меньше или равно; сравнение — как у `gt` |
| `between(a, b)` | `{ "$between": [a, b] }` | От `a` до `b` включительно; сравнение — как у `gt`. Если `a` больше `b`, не подходит ничего |
| `inList([v, …])` | `{ "$in": [v, …] }` | Одно из значений списка. Пустой список не находит ничего; `null` в списке не находит строк без значения — для них `isNull` |
| `like(s)` | `{ "$like": "s" }` | Текст по шаблону с учётом регистра: `%` — любые символы, в том числе ни одного, `_` — ровно один; буквальные `%` и `_` — с обратной косой чертой |
| `ilike(s)` | `{ "$ilike": "s" }` | Как `like`, но без учёта регистра |
| `starts(s)` | `{ "$starts": "s" }` | Текст начинается с `s`, с учётом регистра. Это `like(s + '%')`: `%` и `_` внутри `s` не экранируются и работают как в шаблоне |
| `ends(s)` | `{ "$ends": "s" }` | Текст заканчивается на `s`, с учётом регистра. Это `like('%' + s)`: `%` и `_` внутри `s` не экранируются и работают как в шаблоне |
| `has(v)` | `{ "$has": v }` | Поле-массив содержит элемент `v`. Тип важен: `has(5)` найдёт число 5, но не строку `'5'` |
| `hasAny([v, …])` | `{ "$hasAny": [v, …] }` | Поле-массив содержит хотя бы один элемент списка. Находит только строковые элементы; пустой список не находит ничего |
| `hasAll([v, …])` | `{ "$hasAll": [v, …] }` | Поле-массив содержит все элементы списка, в любом порядке. Тип важен, как у `has`; пустой список подходит любой строке, даже без поля |
| `exists(b = true)` | `{ "$exists": b }` | Поле есть в данных (`true`, по умолчанию) или его нет (`false`); значение не важно — поле с `null` тоже есть |
| `isNull()` | `{ "$isNull": true }` | В поле `null` или поля нет совсем; отличить одно от другого помогает `exists` |
| `not(x)` | `{ "$not": x }` | Отрицание: `x` — оператор (`not(gte(1000))` — меньше 1000 или поля нет) или простое значение — тогда это «не равно», как `ne` |
| `or(f1, f2, …)` | `{ "$or": [f1, f2, …] }` | Хотя бы один из фильтров. Ставится вместо всего фильтра шага, а не значением поля; условия внутри одного фильтра соединяются через «и» |

### ne() {#export-ne}

```ts
ne(v: Scalar): Op
```

**Импорт:** `import { ne } from 'letopis'`

Не равно: `db.Order({ status: ne('cancelled') })`. Подходят и строки, где поля нет или в нём `null`, а `ne(null)` — строки, где у поля есть значение.

Значение приводится к типу поля из описания класса.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `v` | `Scalar` | обязательный | Значение для сравнения: строка, число, логическое значение или `null`. |

**Возвращает:** `Op` ([Op](./types-chain#type-op)) — Оператор фильтра: его ставят значением поля в фильтре шага.

### like() {#export-like}

### hasAll() {#export-hasall}


### or() {#export-or}

```ts
or<F extends object>(...filters: NoInfer<F>[]): OrOp<F>
```

**Импорт:** `import { or } from 'letopis'`

Хотя бы один из фильтров: `db.Product(or({ sku: 'K-1' }, { price: lt(500) }))` — товар K-1 или дешевле 500. Ставится вместо всего фильтра шага, а не значением поля; условия внутри одного фильтра соединяются через «и». В шаге подключения с моделями (`TypedDb`) фильтры внутри — поля и роли класса шага: тип им даёт шаг. Та же фабрика, что в реестре операторов (ops.ts), — другой у неё только тип.

На месте значения поля `or(…)` даёт `invalid_query` при выполнении цепочки — как и любой другой оператор вместо всего фильтра. `or()` без фильтров не находит ничего.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `...filters` | `NoInfer<F>[]` | обязательный | Фильтры шага: объекты полей, как в `db.Класс({ … })`, со значениями и операторами. |

**Возвращает:** `OrOp<F>` — Оператор фильтра: его ставят вместо всего фильтра шага.

### isOp() {#export-isop}

```ts
isOp(v: unknown): v is Op
```

**Импорт:** `import { isOp } from 'letopis'`

Проверяет, оператор ли перед вами: результат `gt()`, `like()`, `or()` и других функций этого раздела. Оператор помечен особым символом, поэтому его нельзя получить из JSON: фильтр, пришедший по сети, остаётся обычными данными и сравнивается на равенство. Оператор, созданный другой копией пакета в том же процессе, тоже узнаётся.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `v` | `unknown` | обязательный | Любое значение. |

**Возвращает:** `v is Op` — `true`, если `v` — оператор фильтра, иначе `false`.
