# Проекторы и агрегаты

Производные данные: проектор строит строки производных классов из журнала изменений, агрегаты считает сама база. Проектор и ремонт агрегатов работают только на администраторском подключении.

## Проектор

### db.projector() {#db-projector}

```ts
projector(name: string, opts: ProjectorOptions): Projector
```

Проектор из журнала: строит строки производных классов (`derivedBy: имя`) из изменений классов `from`; `run()` — догнать журнал и следовать за ним, `rebuild()` — перестроить с текущего состояния. Только на администраторском подключении (иначе `admin_required`).

Производный класс — класс с опцией `derivedBy`: его строки пишет только проектор с этим именем, и все такие строки вместе — проекция. Участник — арендатор, у которого все классы `into` помечены `derivedBy` проектора (и который есть в `tenants`, если список задан). Если база отклоняет запись результатов участника, он выбывает: его изменения пропускаются до перестройки. Сам вызов `db.projector()` в базу не обращается: классы и арендаторов проектор читает при первом `run()`, `rebuild()` или `status()`. Своё состояние — курсор журнала, версию, выбывших арендаторов — проектор хранит в базе под своим именем, поэтому после перезапуска процесса продолжает с того же места. Писатель у проектора один: пока пачку пишет один процесс, проектор с тем же именем в другом процессе свой проход пропускает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | `string` | обязательный | Имя проектора: строчные латинские буквы, цифры и `_.:-`, до 64 символов, первый — буква или цифра. Это же имя стоит в опции `derivedBy` его производных классов. |
| `opts` | `ProjectorOptions` | обязательный | Опции проектора — таблица ниже. Обязательны `from`, `into`, `version` и `handle`. |

**Опции `ProjectorOptions`**

| Опция | Тип | По умолчанию | Описание |
|---|---|---|---|
| <span id="projector-from"></span>`from` | `string[]` | обязательная | Классы-источники (с потомками); должны вести журнал. Изменений класса без журнала (`history: false`) проектор не видит: арендатор, у которого такой класс среди источников, выбывает с кодом `invalid_class`. Классы `into` источниками не бывают, даже если попадают в `from`: свои результаты проектор не читает.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="projector-into"></span>`into` | `string[]` | обязательная | Производные классы (с потомками): описание каждого — derivedBy: имя проектора. Производные классы заводит только администратор — `syncModels` на администраторском подключении. Приложение строки таких классов читает, а `create` или `update` от него — `derived_class`.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="projector-version"></span>`version` | `number` | обязательная | Версия логики проектора — целое число от 1. Вместе с позицией в журнале проектор хранит в базе версию, которой построена проекция: если она другая, `run()` и `rebuild({ tenant })` отклоняются с `rebuild_required`, а полная перестройка `rebuild()` строит проекцию заново и запоминает новую версию. Меняйте версию, когда меняется логика `handle`, и перестраивайте проекцию `rebuild()`.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="projector-handle"></span>`handle` | `(changes: ProjectorChange[], out: ProjectorOut) => void \| Promise<void>` | обязательная | Функция `handle(changes, out)`: получает изменения одного арендатора и пишет его результаты через `out`. Пачку журнала проектор делит по арендаторам и вызывает `handle` для каждого по очереди. Объект `out` описан в разделе «Запись из проектора» ниже. Поля изменения: `cursor`, `id`, `class`, `tenant`, `op`, `rev`, `at`, `author`, `row`, а если есть — `agent`, `reason`, `moved`, `before`; `row` — версия из журнала, у удаления — надгробие с `$deleted`. Функция может быть асинхронной. Служебные записи журнала (`op` — `purge`, `trim` или `reset`, у них `rev` равен 1) тоже приходят изменениями, поэтому сначала проверьте `op`. При перестройке изменения — строки текущего состояния: `op` — `create`, `rebuild: true`, `cursor` пустой.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="projector-withbefore"></span>`withBefore` | `boolean` | `false` | Подавать прошлую версию объекта (before). С ней у изменения есть поле `before` — прошлая версия того же id. Оно равно `null`, если прошлой версии нет (создание, первая версия нового id после `reclass` или `rekey`), если прошлая версия — удаление или версия класса вне `from`, и у всех изменений перестройки. У служебных изменений `purge`, `trim` и `reset` поля `before` нет совсем.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="projector-onexpired"></span>`onExpired` | `'rebuild' \| 'error'` | `'error'` | Курсор старше яруса all политики хранения источников (cursor_expired): 'rebuild' — перестроить самому, пачками. Ярус — по арендатору: истёк у части участников — выбывают они (с 'rebuild' — перестраиваются сами, по одному, пачками), у всех — вся проекция. Ярус `all` — срок, в течение которого журнал хранит все версии; более старые версии прореживаются, и часть изменений после такого курсора могла пропасть. С `'error'` курсор, истёкший у всех участников, — ошибка `cursor_expired` из `run()`, и нужна перестройка `rebuild()`; если он истёк только у части участников, они выбывают, пока их не перестроят `rebuild({ tenant })`.<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |
| <span id="projector-batch"></span>`batch` | `number` | `500` | Изменений в пачке (по умолчанию 500). От 1 до 10 000. Чем больше пачка, тем больше приращений `out.inc` одной строки складывается в одну правку.<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |
| <span id="projector-pollms"></span>`pollMs` | `number` | `1000` | Как часто проектор сам проверяет журнал, если сигнал не пришёл, мс (по умолчанию 1000); сигналы источников будят его раньше.<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |
| <span id="projector-locktimeout"></span>`lockTimeout` | `number` | `5000` | Сколько транзакция проектора ждёт чужую блокировку строки, мс (по умолчанию 5000; 0 — без предела). Дольше — пачка откатывается, курсор остаётся, run() не отклоняется, а пропускает проход и повторяет его.<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |
| <span id="projector-lockretries"></span>`lockRetries` | `number` | `0` | Сколько проходов подряд запись одного арендатора может упираться в lockTimeout, прежде чем он выбудет (код 55P03, дальше — rebuild({ tenant })), а пачка пойдёт для остальных; по умолчанию 0 — не выбывает, проход повторяется для всех. Счёт — в процессе, удачная запись арендатора его сбрасывает. `55P03` — код PostgreSQL «не дождались блокировки».<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |
| <span id="projector-tenants"></span>`tenants` | `string[]` | все арендаторы, у которых каждый класс `into` помечен `derivedBy` проектора | Явный список арендаторов проектора: участники — только они (и только те, у кого каждый класс into помечен derivedBy). Без списка участник — любой арендатор с такими классами.<br>Примеры: [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора) |

**Возвращает:** `Projector` ([Projector](./types#type-projector)) — Объект проектора с методами `run()`, `rebuild()`, `status()`, `stop()` и `close()` — они описаны ниже.

**Ошибки** ([все коды](../errors/)):

- `admin_required` — подключение не администраторское: нужны `connect({ allowBypassRls: true })` и роль, которая может стать владельцем схемы.
- `invalid_query` — вызов внутри `db.begin()`: проектор создают на самом подключении.
- `invalid_data` — неверное имя или опции: `from` и `into` — не непустые списки классов, `version` — не целое число от 1, нет функции `handle`, `onExpired` — не `'rebuild'` и не `'error'`, `tenants` — не непустой список id арендаторов, `batch` — не от 1 до 10 000, `lockTimeout` или `lockRetries` — не целое число от 0.

**Примеры:** [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала)

### projector.run() {#projector-run}

```ts
run(opts?: { once?: boolean; wait?: number }): Promise<ProjectorReport>
```

Догнать журнал и следовать за ним до stop(); { once: true } — только догнать: всё, что зафиксировано до вызова. Проектор читает журнал ниже горизонта — самой старой открытой транзакции кластера, иначе потерял бы события транзакций, зафиксированных позже; поэтому once ждёт транзакции, открытые в момент вызова, до wait мс (по умолчанию 5000, 0 — не ждать) и отвечает caughtUp: true, если догнал. Первый запуск (проекции ещё нет) начинается с перестройки пачками, прерванная перестройка пачками продолжается; так же, пачками, перестраивает onExpired: 'rebuild' (горизонт подписок кластера стоит не дольше пачки).

«Пачками» — значит, каждая пачка строк источников идёт своей транзакцией: подписки и проекторы во всём кластере PostgreSQL ждут не дольше одной пачки. Пока такая перестройка не закончена, производные данные неполные (`status().state` — `'rebuilding'`). Первый `run({ once: true })` вернёт отчёт, только когда проекция построена и журнал догнан. Каждая пачка журнала — одна транзакция: изменения, `handle`, запись результатов и сдвиг курсора фиксируются вместе. После обрыва повтор начинается с того же места, и каждое изменение применяется ровно один раз. Если база отклоняет запись результатов арендатора (например, данные не проходят описание производного класса), выбывает только он (`status().failed`), остальные идут дальше. Исключение из `handle`, запись `out` в чужой класс или арендатора и сбой окружения (взаимная блокировка, отмена запроса, обрыв связи) откатывают пачку, и `run()` отклоняется. Поэтому `run()` без `once` ловите (`catch`): после ошибки проектор остановлен. Если пачку уже пишет проектор с тем же именем в другом процессе или строку держит чужая транзакция дольше `lockTimeout`, `run()` пропускает проход (счётчик `skipped`): без `once` повторяет его позже, а с `once` сразу возвращает отчёт. Журнал проектор читает до горизонта — самой старой открытой транзакции кластера: изменения, зафиксированные после её начала, ждут её конца. Поэтому `once` ждёт транзакции, открытые в момент вызова, до `wait` мс и отвечает `caughtUp`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `opts` | `{ once?: boolean; wait?: number }` | `{}` | Опции запуска. |
| `opts.once` | `boolean` | `false` | `true` — только догнать журнал — всё, что зафиксировано до вызова, — и вернуть отчёт. Без него `run()` следует за журналом, пока не вызовут `stop()` или `close()`. |
| `opts.wait` | `number` | `5000` | Сколько `once` ждёт транзакции, открытые в момент вызова (они держат горизонт), мс; `0` — не ждать. |

**Возвращает:** `Promise<ProjectorReport>` ([ProjectorReport](./types#type-projectorreport)) — Отчёт за весь запуск: `batches` — записано пачек журнала; `changes` — изменений передано в `handle` (при перестройке — строк источников); `created`, `updated`, `deleted`, `unchanged` — что стало со строками производных классов; `skipped` — проходов пропущено из-за блокировки; `rebuilds` — перестроек; `locked` — арендаторы, чья запись упиралась в чужую блокировку строки дольше `lockTimeout`; `caughtUp` — только с `once`: догнал ли запуск всё, что зафиксировано до вызова (`false` — горизонт дольше `wait` держала долгая транзакция, пачку пишет другой процесс или вызван `stop()`). Без `once` промис выполняется после `stop()`.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — этот объект проектора уже выполняет `run()`.
- `rebuild_required` — проекция построена другой версией проектора (`version`): нужна перестройка `rebuild()`.
- `cursor_expired` — курсор старше яруса `all` политики хранения источников у всех участников, а после него есть изменения: часть их могла проредиться. С `onExpired: 'rebuild'` проектор вместо ошибки перестраивается сам.
- `derived_class` — ни у одного арендатора (из `tenants`, если список задан) не помечены `derivedBy` проектора все классы `into`; или `handle` пишет через `out` в класс вне `into`.
- `tenant_denied` — `handle` пишет через `out` в арендатора, чьих изменений он не получал.
- `invalid_class` — классов `from` нет ни у одного арендатора-участника.
- `invalid_data` — схема установлена движком другой ревизии, чем у библиотеки: обновите её — `up({ upgrade: true })`.

**Примеры:** [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) · [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора)

### projector.rebuild() {#projector-rebuild}

```ts
rebuild(opts?: { chunked?: boolean; tenant?: string }): Promise<ProjectorReport>
```

Перестроить проекцию с текущего состояния: атомарно (одна транзакция: до фиксации читатели видят прежние строки, но горизонт подписок стоит) или { chunked: true } — пачками: производные строки удаляются сразу, до конца перестройки данные неполные (status() — rebuilding); прерванную перестройку продолжает следующий запуск. Полная перестройка начинает всех участников заново: отметки выбывших снимаются, а чьи данные снова не проходят — выбывают снова. { tenant: id } — только этот арендатор, одной транзакцией: его производные строки удаляются и строятся из его текущих строк источников, отметка выбывшего снимается. { tenant, chunked: true } — этот арендатор пачками, пока хвост журнала идёт для всех: его производные строки удаляются сразу и до конца перестройки неполны; блокировку, занятую run() другого процесса, перестройка пережидает.

Перестройка нужна после смены `version` (иначе `run()` бросает `rebuild_required`) и чтобы вернуть выбывших арендаторов. «Горизонт подписок стоит» значит: пока атомарная перестройка не зафиксирована, подписки и проекторы во всём кластере PostgreSQL ждут её конца; перестройка пачками задерживает их не дольше пачки. Прерванную перестройку пачками продолжит `run()`, а повторный `rebuild({ chunked: true })` начнёт её заново. С `tenant` ошибка записи результатов арендатора отклоняет перестройку с этим кодом, и арендатор остаётся выбывшим.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `opts` | `{ chunked?: boolean; tenant?: string }` | `{}` | Как перестраивать. Без опций — вся проекция одной транзакцией. |
| `opts.chunked` | `boolean` | `false` | `true` — пачками, каждая своей транзакцией. Производные строки удаляются сразу, и до конца перестройки данные неполные: `status().state` — `'rebuilding'`, а при перестройке одного арендатора он есть в `status().rebuildingTenants`. |
| `opts.tenant` | `string` | нет — все участники | id арендатора: перестроить только его — например, выбывшего (`status().failed`). |

**Возвращает:** `Promise<ProjectorReport>` ([ProjectorReport](./types#type-projectorreport)) — Отчёт, как у `run()`: `changes` — сколько строк источников передано в `handle`, `created` и другие счётчики — что стало со строками производных классов, `rebuilds` — перестроек, `skipped` — сколько раз перестройка ждала чужую блокировку.

**Ошибки** ([все коды](../errors/)):

- `projector_busy` — проектор сейчас пишет пачку в другом процессе. `rebuild({ tenant, chunked: true })` в этом случае не отказывает, а ждёт.
- `rebuild_required` — с `tenant`: проекции ещё нет, идёт перестройка пачками или проекция построена другой версией проектора — сначала `run()` или `rebuild()`.
- `tenant_denied` — с `tenant`: арендатор не участник — у него не все классы `into` помечены `derivedBy` проектора или его нет в `tenants`; или `handle` пишет через `out` в чужого арендатора.
- `invalid_class` — классов `from` нет ни у одного участника; с `tenant` — источники арендатора не ведут журнал (`history: false`).
- `derived_class` — ни у одного арендатора не помечены `derivedBy` проектора все классы `into`; или `handle` пишет через `out` в класс вне `into`.
- `invalid_data` — `tenant` — не id арендатора; схема установлена движком другой ревизии, чем у библиотеки; с `tenant` — его данные не проходят описание производного класса.
- `target_not_found` — с `tenant`: цель конца в его результатах не найдена.

**Примеры:** [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора)

### projector.status() {#projector-status}

```ts
status(): Promise<ProjectorStatus>
```

Читает из базы, в каком состоянии проекция. Это состояние данных, а не процесса: `'running'` не значит, что какой-то процесс сейчас выполняет `run()`.

**Возвращает:** `Promise<ProjectorStatus>` ([ProjectorStatus](./types#type-projectorstatus)) — Объект `{ name, state, version, cursor, at, lag, failed, rebuildingTenants }`: `state` — `'new'` (проекции ещё нет, её построит первый `run()` или `rebuild()`), `'running'` (проекция построена и ведётся по журналу) или `'rebuilding'` (идёт или прервана перестройка пачками); `version` — версия проектора, которой построена проекция (`null`, пока проекции нет); `cursor` — докуда прочитан журнал; `at` — у догнавшего проектора время последнего прохода (без новых изменений отметка обновляется не чаще раза в минуту), у отстающего — время последнего обработанного изменения; `lag` — возраст самого старого необработанного изменения источников в мс, без выбывших арендаторов (`0` — догнал); `failed` — выбывшие арендаторы: `{ [id]: { cursor, code, message } }`, их изменения пропускаются до перестройки; `rebuildingTenants` — арендаторы, которых перестраивают пачками.

**Ошибки** ([все коды](../errors/)):

- `derived_class` — ни у одного арендатора не помечены `derivedBy` проектора все классы `into`.
- `invalid_class` — классов `from` нет ни у одного участника.
- `invalid_data` — схема установлена движком другой ревизии, чем у библиотеки.

**Примеры:** [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала)

## Запись из проектора

Объект `out` получает функция `handle(changes, out)` проектора.

### out.upsert() {#out-upsert}

```ts
upsert(cls: string, row: ProjectorRow, opts: { tenant: string }): void
```

Создать или заменить целиком по ключу класса (у класса без ключа — по $id).

Данные и концы строки заменяются целиком, теги — если передан `$tags`; владелец (`$owner`) задаётся только при создании. Правка, которая ничего не меняет, версии не даёт. Записи `out` копятся и уходят в базу одним вызовом после `handle` (или раньше — перед `out.get`). Если база отклоняет запись (данные не проходят описание класса, цель конца не найдена и т. п.), откатываются только изменения этого арендатора, и он выбывает (`status().failed`); в `rebuild({ tenant })` такая ошибка отклоняет перестройку. Версии производных строк пишутся от System с агентом `letopis projector <имя>`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `string` | обязательный | Производный класс: один из классов `into` проектора или их потомок у этого арендатора. |
| `row` | `ProjectorRow` | обязательный | Строка в формате загрузчика: поля и роли концов на верхнем уровне (значение роли — id цели), служебные `$tags`, `$owner` и `$id`. `$id` нужен только классу без ключа. |
| `opts` | `{ tenant: string }` | обязательный | Объект с арендатором строки. |
| `opts.tenant` | `string` | обязательный | id арендатора — того, чьи изменения получил `handle` (`c.tenant`). |

**Возвращает:** ничего.

**Ошибки** ([все коды](../errors/)):

- `derived_class` — класс не входит в классы `into` проектора у этого арендатора: пачка откатывается целиком, `run()` или `rebuild()` отклоняется.
- `tenant_denied` — `opts.tenant` — не арендатор изменений, переданных в `handle`: пачка откатывается целиком.
- `invalid_data` — вместо строки передан не объект (например, `null`): изменения арендатора откатываются, и он выбывает.

**Примеры:** [Проектор как процесс: run() в фоне, stop(), close(), out.upsert и служебные методы](../derived/#проектор-как-процесс)

### out.inc() {#out-inc}

```ts
inc(cls: string, row: ProjectorRow, deltas: Record<string, number>, opts: { tenant: string }): void
```

Прибавляет к полям строки числа из `deltas`: читать строку не нужно, и итог не зависит от порядка приращений. Поле приращения, которого в строке нет, считается от 0, а если нет самой строки, она создаётся; поля `row` дописываются в её данные. Приращения одной строки, заданной только полями ключа (или только `$id`), до отправки в базу складываются в одну правку, пока между ними нет `upsert`, `delete` или `get`.

Роли концов в `row` заменяют прежние концы, без них концы остаются. Если приращения сложены в одну правку, правила класса проверяют итог, а не каждое приращение. Ошибки базы — как у `out.upsert`: выбывает только этот арендатор.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `string` | обязательный | Производный класс: один из классов `into` проектора или их потомок у этого арендатора. |
| `row` | `ProjectorRow` | обязательный | Какую строку дополнить: поля ключа класса (у класса без ключа — `$id`) и, если нужно, ещё поля данных, роли концов, `$tags`, `$owner`. |
| `deltas` | `Record<string, number>` | обязательный | Приращения `{ поле: число }`: сколько прибавить к полю. Отрицательное число вычитает. |
| `opts` | `{ tenant: string }` | обязательный | Объект с арендатором строки. |
| `opts.tenant` | `string` | обязательный | id арендатора — того, чьи изменения получил `handle` (`c.tenant`). |

**Возвращает:** ничего.

**Ошибки** ([все коды](../errors/)):

- `derived_class` — класс не входит в классы `into` проектора у этого арендатора: пачка откатывается целиком.
- `tenant_denied` — `opts.tenant` — не арендатор изменений, переданных в `handle`: пачка откатывается целиком.
- `invalid_data` — приращение — не конечное число или вместо строки передан не объект: изменения арендатора откатываются, и он выбывает.

**Примеры:** [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала)

### out.delete() {#out-delete}

```ts
delete(cls: string, keyOrId: string | ProjectorRow, opts: { tenant: string }): void
```

Удалить строку: у класса с ключом — по полям ключа, у класса без ключа — по id (строкой или { $id }); строки нет — ничего. Один id у класса с ключом — invalid_data.

Удаление уходит в базу вместе с остальными записями `out` — после `handle` или перед `out.get`. У класса с журналом остаётся надгробие. Ошибки базы — как у `out.upsert`: выбывает только этот арендатор.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `string` | обязательный | Производный класс: один из классов `into` проектора или их потомок у этого арендатора. |
| `keyOrId` | `string \| ProjectorRow` | обязательный | Какую строку удалить: у класса с ключом — объект с полями ключа, у класса без ключа — id строкой или `{ $id }`. |
| `opts` | `{ tenant: string }` | обязательный | Объект с арендатором строки. |
| `opts.tenant` | `string` | обязательный | id арендатора — того, чьи изменения получил `handle` (`c.tenant`). |

**Возвращает:** ничего.

**Ошибки** ([все коды](../errors/)):

- `derived_class` — класс не входит в классы `into` проектора у этого арендатора: пачка откатывается целиком.
- `tenant_denied` — `opts.tenant` — не арендатор изменений, переданных в `handle`: пачка откатывается целиком.
- `invalid_data` — у класса с ключом строку назвали одним id, а не полями ключа — это ошибка кода `handle`: пачка откатывается целиком; передан не id и не объект — изменения арендатора откатываются, и он выбывает.

**Примеры:** [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора)

### out.get() {#out-get}

```ts
get(cls: string, keyOrId: string | ProjectorRow, opts: { tenant: string }): Promise<Row | null>
```

Текущая строка внутри пачки (с записями пачки, сделанными до вызова); нет — null. Строку называют, как в delete: у класса с ключом — полями ключа, у класса без ключа — id; один id у класса с ключом — invalid_data.

Перед чтением `get` отправляет в базу накопленные записи `out`. Если база их отклонит, `get` бросит эту ошибку, и изменения арендатора откатятся, даже если `handle` её поймает. После `get` приращения `inc` к прежним уже не складываются: правки уходят в базу по порядку.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `string` | обязательный | Производный класс: один из классов `into` проектора или их потомок у этого арендатора. |
| `keyOrId` | `string \| ProjectorRow` | обязательный | Какую строку прочитать: у класса с ключом — объект с полями ключа, у класса без ключа — id строкой или `{ $id }`. |
| `opts` | `{ tenant: string }` | обязательный | Объект с арендатором строки. |
| `opts.tenant` | `string` | обязательный | id арендатора — того, чьи изменения получил `handle` (`c.tenant`). |

**Возвращает:** `Promise<Row \| null>` ([Row](./types#type-row)) — Строку в том же виде, что у чтения цепочкой (`id`, `class`, `rev`, `data`, `links`, `tags`, `owner`, `at` и другие поля), или `null`.

**Ошибки** ([все коды](../errors/)):

- `derived_class` — класс не входит в классы `into` проектора у этого арендатора: пачка откатывается целиком.
- `tenant_denied` — `opts.tenant` — не арендатор изменений, переданных в `handle`: пачка откатывается целиком.
- `invalid_data` — у класса с ключом строку назвали одним id, а не полями ключа (ошибка кода `handle`: пачка откатывается целиком); передан не id и не объект; или база отклонила накопленные записи `out`: данные не проходят описание класса.
- `target_not_found` — база отклонила накопленные записи `out`: цель конца или владелец строки не найдены.
- `id_mismatch` — база отклонила накопленные записи `out`: `$id` не совпал с ключом класса или id занят строкой другого класса или арендатора.

**Примеры:** [Опции проектора: пачки, опрос, блокировки, арендаторы, просроченный курсор](../derived/#опции-проектора)

## Агрегаты

### db.rebuildAggregates() {#db-rebuildaggregates}

```ts
rebuildAggregates(cls: string): Promise<number>
```

Ремонт агрегатов в базе: поля класса (с потомками) во всех арендаторах — заново из живых строк источников, под исключительными блокировками; версия — только у исправленных. Возвращает их число. Только на администраторском подключении (иначе `admin_required`).

Ремонт нужен, если агрегатные поля разошлись с источниками; расхождения показывает `verify({ data: true })`. Весь ремонт — одна транзакция. На это время запись в классы целей и источников ждёт: пересчёт идёт под исключительными блокировками. Версии исправленных строк пишутся с причиной `rebuildAggregates`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `string` | обязательный | Имя класса с агрегатными полями (`aggregate`). Пересчитываются агрегаты этого класса и его потомков у всех арендаторов, где есть классы с таким именем. |

**Возвращает:** `Promise<number>` — Число исправленных строк; `0` — все агрегаты были верны.

**Ошибки** ([все коды](../errors/)):

- `admin_required` — подключение не администраторское: нужны `connect({ allowBypassRls: true })` и роль, которая может стать владельцем схемы.
- `invalid_query` — вызов внутри `db.begin()`: ремонт идёт своей транзакцией.
- `invalid_class` — ни у класса, ни у его потомков нет агрегатных полей — в том числе если класса с таким именем нет.
- `invalid_data` — имя класса — не непустая строка; или пересчитанный итог не проходит описание класса (например, правило `min(0)`) — тогда ремонт откатывается целиком.

**Примеры:** [Агрегат: баланс считает сама база](../derived/#агрегат-в-базе)
