# Вход: db.auth

`db.auth` — креды, вход и сессии. Проверку паролей, кодов и TOTP, выпуск сессий и подтверждение кредов вызывает сервис (права `auth.*`); обычному пользователю отвечают `acl_denied`.

## Свойство

### db.auth {#db-auth}

```ts
readonly auth: AuthApi
```

Креды, вход и сессии.

Кред (от англ. credential) — то, чем учётная запись входит: пароль или другой логин с паролем, ключ API, пара «ключ + секрет», одноразовый код, TOTP или привязка внешней учётной записи. Креды и сессии лежат в таблице `secret`; приложение не читает её напрямую, а работает с ней через `db.auth`.

**Примеры:** [Три таблицы: entity, log и secret](../basics/what-is#три-таблицы-на-примере)

## Пароли

### db.auth.setPassword() {#auth-setpassword}

```ts
setPassword(a: { account: AccountRef; identifier: string; password: string; kind?: string; confirmed?: boolean; keepCurrent?: boolean }): Promise<string>
```

Пароль (и любой «логин/пароль»: kind — PASSWORD, EMAIL, …): создать или заменить. Смена гасит остальные сессии аккаунта.

Кто может вызвать: сам пользователь в течение 10 минут после интерактивного входа (вход по ключу API, по паре «ключ + секрет» и сессия от сервиса не в счёт; при включённом TOTP нужен вход с TOTP) или сервис с правом `auth.credential`. Пароль System, сервиса или системного администратора меняет только он сам или системный администратор. Новый идентификатор добавляет ещё один кред, прежний остаётся, пока его не удалит `revokeCredential()`. Сессии гаснут только при замене пароля существующего идентификатора.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; identifier: string; password: string; kind?: string; confirmed?: boolean; keepCurrent?: boolean }` | обязательный | Что записать: учётная запись, идентификатор и пароль. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.identifier` | `string` | обязательный | Логин — почта, телефон или другое имя для входа, непустая строка. Регистр букв не важен. |
| `a.password` | `string` | обязательный | Пароль открытым текстом. В базу уходит только его хэш scrypt. |
| `a.kind` | `string` | `'PASSWORD'` | Вид креда: `PASSWORD`, `EMAIL` и т. п. — заглавная латинская буква, затем заглавные буквы, цифры и `_`, всего 2–32 знака. Служебные виды (`SESSION`, `APIKEY`, `KEYSECRET`, `OTP`, `TOTP`, `KEY`, `PROJECTOR`, `LOCK`) заняты. |
| `a.confirmed` | `boolean` | нет: у нового креда — `false`, у существующего отметка не меняется | Отметить кред подтверждённым (почту или телефон проверил сервис). Действует только у вызывающего с правом `auth.credential`, у остальных молча не учитывается. |
| `a.keepCurrent` | `boolean` | `true` | Оставить сессию, из которой идёт вызов, когда пароль меняет сам пользователь. `false` — погасить и её. Когда пароль меняет сервис, гаснут все сессии пользователя. |

**Возвращает:** `Promise<string>` — id креда: нового или того, чей пароль заменён.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет недавнего входа и права `auth.credential`; учётная запись — System, сервис или системный администратор, а вызывающий не он сам и не системный администратор; идентификатор занят другой учётной записью.
- `invalid_data` — вид креда не подходит или идентификатор пустой.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.verifyPassword() {#auth-verifypassword}

```ts
verifyPassword(a: { identifier: string; password: string; kind?: string; requireConfirmed?: boolean; ttl?: number; totp?: string }): Promise<LoginResult | null>
```

Вход по паролю — для сервиса с правом auth.password и auth.session. Неудача — null. С `totp` после верного пароля база проверяет код TOTP аккаунта (право auth.totp; счётчик неудач и блокировка — общие с verifyTotp): верный — сессия со способами [kind, 'TOTP'], неверный или повторный — null.

Любая неудача — `null` без объяснения: нет такого логина, пароль неверен, кред не подтверждён, кред или учётная запись выключены, код TOTP не подошёл. Для несуществующего логина ответ не быстрее, чем для неверного пароля. Без `totp` код не проверяется, даже если TOTP у пользователя включён: требовать второй фактор решает сервис (проверьте `totpEnabled()`). System, сервису и системному администратору сессию так не выпустить.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ identifier: string; password: string; kind?: string; requireConfirmed?: boolean; ttl?: number; totp?: string }` | обязательный | Данные входа. |
| `a.identifier` | `string` | обязательный | Логин. Регистр букв не важен. |
| `a.password` | `string` | обязательный | Пароль, который ввёл пользователь. |
| `a.kind` | `string` | `'PASSWORD'` | Вид креда, как в `setPassword()`. |
| `a.requireConfirmed` | `boolean` | `true` | Пускать только по подтверждённому креду. `false` — и по неподтверждённому. |
| `a.ttl` | `number` | 7 суток | Срок новой сессии в секундах. Срок считается от последнего использования: подключение само продлевает сессию. |
| `a.totp` | `string` | нет: код не проверяется | Код TOTP из приложения-аутентификатора. Проверяется после верного пароля; нужно право `auth.totp`. |

**Возвращает:** `Promise<LoginResult \| null>` ([LoginResult](./types#type-loginresult)) — `{ account, token }` — id учётной записи и токен новой сессии или `null`. Способы входа сессии (`methods` в `session()`) — `[kind]`, с верным кодом TOTP — `[kind, 'TOTP']`.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения сервиса нет действующей сессии.
- `acl_denied` — нет права `auth.password` или `auth.session` (с `totp` — ещё `auth.totp`); пароль верен, но учётная запись — System, сервис или системный администратор.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа) · [Три таблицы: entity, log и secret](../basics/what-is#три-таблицы-на-примере)

## Ключи API

### db.auth.issueApiKey() {#auth-issueapikey}

```ts
issueApiKey(a: { account: AccountRef; name?: string; ttl?: number }): Promise<{ key: string; id: string }>
```

Ключ API `lts_…`: отдаётся один раз. Себе сервис выпускает ключ сам по сессии своего ключа.

Кто может выпустить: сам пользователь в течение 10 минут после интерактивного входа или сервис с правом `auth.credential`. Ключи System, сервисов и системных администраторов выпускает системный администратор. Ключей у учётной записи может быть несколько: так ключ меняют без простоя — выпускают новый, переводят на него процессы и отзывают старый.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; name?: string; ttl?: number }` | обязательный | Чей ключ и как его назвать. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.name` | `string` | нет | Название ключа для людей, например «интеграция»; видно в `credentials()` (поле `meta.name`). |
| `a.ttl` | `number` | бессрочно, пока ключ не отозван | Срок действия ключа в секундах. |

**Возвращает:** `Promise<{ key: string; id: string }>` — `{ key, id }`: `key` — сам ключ вида `lts_…` (показывается один раз, база хранит только хэш), `id` — id креда для `revokeCredential()` и `setFlags()`.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет недавнего входа и права `auth.credential`, или ключ для System, сервиса или системного администратора просит не он сам и не системный администратор.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.verifyApiKey() {#auth-verifyapikey}

```ts
verifyApiKey(key: string): Promise<LoginResult | null>
```

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `key` | `string` | обязательный | Ключ API вида `lts_…`. |

**Возвращает:** `Promise<LoginResult \| null>` ([LoginResult](./types#type-loginresult)) — `{ account, token }` — id учётной записи и токен новой сессии или `null`, если ключа нет, он истёк, отозван или выключен, или учётная запись выключена.

**Ошибки:** собственных кодов нет.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.issueKeySecret() {#auth-issuekeysecret}

```ts
issueKeySecret(a: { account: AccountRef; name?: string }): Promise<{ key: string; secret: string; id: string }>
```

Пара ключ + секрет: секрет отдаётся один раз. Себе сервис выпускает пару сам по сессии своего ключа.

Пара нужна интеграциям, которые хранят открытый ключ отдельно от секрета. Кто может выпустить — как у `issueApiKey()`. Срока у пары нет: она действует, пока её не отзовут или не выключат.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; name?: string }` | обязательный | Чья пара и как её назвать. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.name` | `string` | нет | Название пары для людей; видно в `credentials()` (поле `meta.name`). |

**Возвращает:** `Promise<{ key: string; secret: string; id: string }>` — `{ key, secret, id }`: `key` — открытый ключ (16 шестнадцатеричных знаков), `secret` — секрет (показывается один раз, база хранит только хэш), `id` — id креда.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет недавнего входа и права `auth.credential`, или пару для System, сервиса или системного администратора просит не он сам и не системный администратор.

**Примеры:** [Сессии и арендаторы: переключение, способы входа, выход, закрытие арендатора](../auth/#сессии-и-арендаторы)

## TOTP

### db.auth.enrollTotp() {#auth-enrolltotp}

```ts
enrollTotp(a: { account: AccountRef; issuer?: string; label?: string }): Promise<{ secret: string; uri: string }>
```

TOTP: секрет в base32 и ссылка otpauth:// для QR; фактор включает первая успешная проверка.

Кто может подключить: сам пользователь в течение 10 минут после интерактивного входа (при уже включённом TOTP — входа с TOTP) или сервис с правом `auth.credential`; System, сервисам и системным администраторам — только он сам или системный администратор. Повторный вызов заменяет секрет: прежний перестаёт действовать, и второй фактор выключен, пока новый код не пройдёт `verifyTotp()`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; issuer?: string; label?: string }` | обязательный | Кому подключить и как подписать запись в приложении. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.issuer` | `string` | нет: в ссылку не попадает | Название сервиса, которое покажет приложение-аутентификатор. |
| `a.label` | `string` | id учётной записи | Подпись учётной записи в приложении, например логин. |

**Возвращает:** `Promise<{ secret: string; uri: string }>` — `{ secret, uri }`: `secret` — секрет в base32 (показывается один раз), `uri` — ссылка `otpauth://totp/…` для QR-кода (SHA1, 6 цифр, новый код каждые 30 секунд).

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет недавнего входа и права `auth.credential`, или учётная запись — System, сервис или системный администратор, а вызывающий не он сам и не системный администратор.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.verifyTotp() {#auth-verifytotp}

```ts
verifyTotp(a: { account: AccountRef; code: string; window?: number }): Promise<boolean>
```

Проверяет код TOTP из приложения-аутентификатора. Нужно право `auth.totp` (по умолчанию оно у сервисов и системных администраторов). Первая верная проверка после `enrollTotp()` включает второй фактор. Уже принятый код и более старые коды отклоняются. Пять неудач подряд закрывают проверку на 5 минут. Если транзакция вызывающего откатится, откатится и счётчик неудач, поэтому частоту попыток должен ограничивать сам сервис.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; code: string; window?: number }` | обязательный | Чей код проверить. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.code` | `string` | обязательный | Код из приложения: 6 цифр. |
| `a.window` | `number` | `1` | Сколько соседних 30-секундных интервалов принимать в каждую сторону: `0` — только текущий, `1` — ещё предыдущий и следующий. Значение больше 1 база урезает до 1. |

**Возвращает:** `Promise<boolean>` — `true` — код принят; `false` — код неверен или уже использован, TOTP не подключён или проверка закрыта после пяти неудач.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет права `auth.totp`, или учётная запись — System, сервис или системный администратор, а вызывающий не он сам и не системный администратор.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

```ts
totpEnabled(account: AccountRef): Promise<boolean>
```

Проверяет, включён ли у учётной записи второй фактор TOTP. Свою учётную запись проверяет любая сессия, чужую — сессия с правом `auth.totp`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |

**Возвращает:** `Promise<boolean>` — `true` — TOTP подключён и подтверждён первой верной проверкой; `false` — не подключён или ещё не подтверждён (в том числе после повторного `enrollTotp()`).

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — чужая учётная запись без права `auth.totp`, или учётная запись — System, сервис или системный администратор, а вызывающий не системный администратор.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

## Одноразовые коды

### db.auth.issueOtp() {#auth-issueotp}

```ts
issueOtp(a: { account: AccountRef; identifier: string; kind?: string; ttl?: number; digits?: number; maxAttempts?: number }): Promise<{ code: string }>
```

Одноразовый код для доставки сервисом (право auth.otp).

Письмо или СМС с кодом отправляет сам сервис; база хранит только хэш кода. Новый код на тот же идентификатор и вид заменяет прежний: действует только последний. Коды для System, сервисов и системных администраторов выпускает только системный администратор.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; identifier: string; kind?: string; ttl?: number; digits?: number; maxAttempts?: number }` | обязательный | Кому и куда выпустить код. |
| `a.account` | `AccountRef` | обязательный | Учётная запись, в которую код даст войти: id или объект с полем `id`. |
| `a.identifier` | `string` | обязательный | Куда сервис отправит код — почта или телефон, непустая строка. По нему же код найдёт `verifyOtp()`. |
| `a.kind` | `string` | `'OTP'` | Вид кода: `OTP` или `OTP_<ИМЯ>` (например, `OTP_RESET` для сброса пароля) — коды разных видов не мешают друг другу. |
| `a.ttl` | `number` | 10 минут | Срок действия кода в секундах. |
| `a.digits` | `number` | `6` | Число цифр в коде: от 4 до 10. |
| `a.maxAttempts` | `number` | `5` | Сколько неверных попыток сжигают код. Значение вне 1–10 база приводит к ближайшей границе. |

**Возвращает:** `Promise<{ code: string }>` — `{ code }` — код строкой из `digits` цифр (с ведущими нулями).

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет права `auth.otp`, или учётная запись — System, сервис или системный администратор, а вызывающий не системный администратор.
- `invalid_data` — вид не `OTP` и не `OTP_<ИМЯ>`, пустой идентификатор или `digits` вне 4–10.
- `target_not_found` — учётной записи нет или она выключена.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.verifyOtp() {#auth-verifyotp}

```ts
verifyOtp(a: { identifier: string; code: string; kind?: string }): Promise<LoginResult | null>
```

Вход по одноразовому коду: успех и перебор (лимит задал выпуск, 1–10, по умолчанию 5) сжигают код.

Нужно право `auth.otp`. Верный код открывает сессию на 7 суток; способ входа в ней — вид кода. Каждая неверная попытка увеличивает счётчик; когда он доходит до `maxAttempts`, код сгорает. Если транзакция вызывающего откатится, откатится и счётчик, поэтому частоту попыток должен ограничивать сам сервис.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ identifier: string; code: string; kind?: string }` | обязательный | Данные входа. |
| `a.identifier` | `string` | обязательный | Идентификатор, на который выпущен код. Регистр букв не важен. |
| `a.code` | `string` | обязательный | Код, который ввёл пользователь. |
| `a.kind` | `string` | `'OTP'` | Вид кода, как при выпуске. |

**Возвращает:** `Promise<LoginResult \| null>` ([LoginResult](./types#type-loginresult)) — `{ account, token }` — id учётной записи и токен новой сессии или `null`: кода нет, он неверен, истёк, уже сгорел или учётная запись выключена.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения сервиса нет действующей сессии.
- `acl_denied` — нет права `auth.otp`.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

## Внешние учётные записи

### db.auth.link() {#auth-link}

```ts
link(a: { account: AccountRef; kind: string; identifier: string; meta?: Record<string, unknown>; confirmed?: boolean }): Promise<string>
```

Внешняя identity (TELEGRAM, GOOGLE, SSO): токен проверяет сервис, здесь — связка.

Привязка связывает учётную запись с её id у внешнего провайдера (Telegram, Google, SSO): потом по нему входят через `lookup()`. Кто может привязать — как у `setPassword()`: сам пользователь после недавнего входа или сервис с правом `auth.credential`. Занятый идентификатор (в том числе уже привязанный к этой же учётной записи) отклоняется тем же `acl_denied`, что и отказ в праве.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `a` | `{ account: AccountRef; kind: string; identifier: string; meta?: Record<string, unknown>; confirmed?: boolean }` | обязательный | Что привязать. |
| `a.account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |
| `a.kind` | `string` | обязательный | Вид внешней учётной записи: `TELEGRAM`, `GOOGLE` и т. п. Правила имени — как у вида креда в `setPassword()`; `PASSWORD` и служебные виды не подходят. |
| `a.identifier` | `string` | обязательный | id пользователя у внешнего провайдера, непустая строка. Регистр букв не важен. |
| `a.meta` | `Record<string, unknown>` | `{}` | Любые данные о привязке, например имя у провайдера; видны в `credentials()`. Ключи `confirmed` и `enabled` не учитываются. |
| `a.confirmed` | `boolean` | `false` | Отметить привязку подтверждённой. Действует только у вызывающего с правом `auth.credential`. |

**Возвращает:** `Promise<string>` — id нового креда.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — нет недавнего входа и права `auth.credential`; учётная запись — System, сервис или системный администратор, а вызывающий не он сам и не системный администратор; идентификатор этого вида уже привязан.
- `invalid_data` — вид не подходит или идентификатор пустой.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### db.auth.lookup() {#auth-lookup}

```ts
lookup(a: { kind: string; identifier: string; requireConfirmed?: boolean; ttl?: number; totp?: string }): Promise<LoginResult | null>
```

Вход по identity — для сервиса с правами auth.identity и auth.session; `totp` — как у verifyPassword.

Сначала сервис сам проверяет токен провайдера (Telegram, Google), затем этим вызовом находит по привязке учётную запись и получает её сессию. System, сервису и системному администратору сессию так не выпустить.

- `no_session` — у подключения сервиса нет действующей сессии.

### db.auth.session() {#auth-session}

```ts
purgeAccount(account: AccountRef): Promise<{ account: string; rows: number; versions: number; memberships: number; owned: number }>
```

Удалить аккаунт: системный администратор или владелец его арендатора; себя и последнего владельца арендатора — нельзя. Данные арендатора стираются, владение строками в чужих арендаторах переходит им, сессии гаснут, креды удаляются. Владелец стирает и арендатора, в котором работает: его сессия возвращается в личный арендатор.

Строки и журнал арендатора этой учётной записи стираются физически, а её членства в других арендаторах снимаются. Сама учётная запись удаляется, но остаётся надгробие: её история сохраняется для аудита. Сессии гаснут с сигналом — процессы сбрасывают кэш ответов этих сессий, — а все её строки `secret` (сессии, пароли, ключи, TOTP, привязки внешних учётных записей) стираются сразу, как и при удалении строки `Account` системным администратором.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `account` | `AccountRef` | обязательный | Учётная запись: id или объект с полем `id`. |

**Возвращает:** `Promise<{ account: string; rows: number; versions: number; memberships: number; owned: number }>` — `{ account, rows, versions, memberships, owned }`: id удалённой учётной записи, сколько строк и версий журнала её арендатора стёрто, сколько членств снято и у скольких строк в других арендаторах сменился владелец.

**Ошибки** ([все коды](../errors/)):

- `no_session` — у подключения нет действующей сессии.
- `acl_denied` — вызывающий — не системный администратор и не владелец арендатора этой учётной записи; попытка удалить себя; учётная запись — последний владелец другого арендатора (его id — в `detail.tenant`).
- `target_not_found` — учётной записи нет или это System.
- `delete_restricted` — на учётную запись ссылаются строки других арендаторов.
