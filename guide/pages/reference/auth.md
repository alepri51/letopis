# Вход, приглашения и ключи

Вход — у консьержа `db`: пароль, ключ API, ключ с секретом и внешний вход открывают квартиру этого ключа, вход кодом (`db.requestCode`) доказывает контакт, а квартиру выбирают при входе; ответ — корень квартиры `me` с правами жильца. Новых людей зовут приглашением `me.invite(контакт, роли)`: ссылку с токеном доставляет почтальон из `connect(pass, { postman })`, человек принимает её `db.accept(token)` — пароль по желанию. Остальные ключи жилец заводит сам — `me.keys`, только свои и только в квартире, куда вошёл. Ключ, который не подошёл, — `auth_failed`, причину ответ не раскрывает.

**Что здесь:** [Вход](#вход) · [Приглашения](#приглашения) · [Контакт и имя](#контакт-и-имя) · [Ключи жильца](#ключи-жильца) · [Сессия и выписка](#сессия-и-выписка). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Вход

### db.open() {#house-open}

```ts
open(key: Key): Promise<Room<M>>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Вход ключом жильца. Вход кодом при нескольких квартирах без tenant — api.tenant_required (detail.tenants); неверный код — api.code_failed. tenant у входа паролем — проверка: пароль открывает другую квартиру — api.auth_failed.

Формы ключа — поля контакта прямо в ключе: `{ phone | email | telegram | kind+address, password, totp? }` — пароль этой квартиры (пароли одного аккаунта в разных квартирах разные, поэтому пароль сам выбирает квартиру; `tenant` у пароля — проверка: пароль должен открывать именно эту квартиру, иначе тот же `auth_failed`, что у неверного пароля); `{ …контакт, code, tenant? }` — код из письма `db.requestCode()`: квартира одна — `tenant` не нужен, несколько без `tenant` — `tenant_required` со списком квартир в `err.detail.tenants` (код при этом не гаснет), успех гасит код; `{ apiKey }` — ключ API; `{ key, secret }` — ключ и секрет; `{ external: { kind, identifier }, totp? }` — внешний вход: токен провайдера (Telegram, Google, SSO) проверяет приложение, а letopis находит ключ по внешнему id. Контакт сравнивается без учёта регистра. Если у жильца в этой квартире подтверждён TOTP, пароль и внешний вход открывают её только с верным `totp`. Неверный пароль и несуществующий контакт отвечают одинаково и за то же время; отозванный или просроченный ключ, выписанный жилец, выключенный аккаунт или квартира — тот же `auth_failed`: причину ответ не раскрывает. Пять неверных вводов кода подряд гасят код. События журнала — `auth.login`, при отказе — `auth.fail`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `key` | `Key` | обязательный | Ключ — одна из форм выше. У любой формы есть `ttl` — срок сессии: секунды числом или строка (`'15m'`, `'7 days'`), по умолчанию 7 дней. |

**Возвращает:** `Promise<Room<M>>` — Корень квартиры жильца (`me`) — с его правами.

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — ключ не подошёл: неверный, отозванный или просроченный, жилец выписан, аккаунт или квартира выключены, `tenant` у пароля — не та квартира (`api.auth_failed`); код неверный, истёк или квартира, где аккаунт не прописан (`api.code_failed`); нужен `totp` (`api.totp_required`).
- `target_not_found` — вход кодом: квартиры с таким именем нет в доме (`api.tenant_unknown`).
- `tenant_required` — вход кодом, у аккаунта несколько квартир, а `tenant` не задан (`api.tenant_required`): список — `err.detail.tenants`.
- `invalid_data` — ключ не одной из форм или с пустыми полями (`api.key_form`); неверный `ttl` (`access.bad_ttl`).

### db.resume() {#house-resume}

```ts
resume(token: string): Promise<Room<M>>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Вернуться по токену сессии (me.token). Сессия погашена, истекла или токен неверен — api.session_closed.

Например, по cookie веб-сессии. Токен проверяется при вызове: сессия истекла, погашена (`me.close()`, `me.closeAll()`, смена пароля, отзыв ключа) или жилец выписан — `auth_failed`. Токен корня консьержа (`db.in()`, `db.as()`) не принимается.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `token` | `string` | обязательный | Токен сессии жильца — `me.token` корня из `db.open()`, `db.resume()` или `db.accept()`. |

**Возвращает:** `Promise<Room<M>>` — Корень квартиры жильца — такой же, какой дал вход.

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — сессия закрыта или истекла: выход, выписка, смена пароля, отзыв ключа, неверный токен (`api.session_closed`).

### db.requestCode() {#house-requestcode}

```ts
requestCode(
  to: Contact,
  opts?: { ttl?: string | number; digits?: number; maxAttempts?: number },
): Promise<{ expiresAt: string }>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Запросить код входа на контакт: код выдаёт библиотека, доставляет почтальон; контакта нет в доме или аккаунт нигде не прописан — тот же ответ без письма.

Код — 6 цифр, 10 минут, 5 попыток; доставляет почтальон (письмо `kind: 'code'`). Ответ одинаков всегда: контакта нет в доме, аккаунт выключен или нигде не прописан — письма нет, ответ тот же. Новый код заменяет прежний. Код доказывает контакт, а не открывает одну квартиру: квартиры аккаунта — `db.tenantsOf({ …контакт, code })`, вход — `db.open({ …контакт, code, tenant? })`. Событие журнала — `auth.credential`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `to` | `Contact` | обязательный | Контакт: `{ email }`, `{ phone }`, `{ telegram }` или `{ kind, address }`. |
| `opts` | `{ ttl?: string \| number; digits?: number; maxAttempts?: number }` | `{}` | Срок и форма кода. |
| `opts.ttl` | `string \| number` | 10 минут | Срок кода: секунды числом или строка (`'15m'`). |
| `opts.digits` | `number` | `6` | Цифр в коде — от 4 до 10. |
| `opts.maxAttempts` | `number` | `5` | Попыток ввода — от 1 до 10. |

**Возвращает:** `Promise<{ expiresAt: string }>` — `{ expiresAt }` — срок кода, строка ISO 8601. Самого кода в ответе нет: его получает почтальон.

**Ошибки** ([все коды](../errors/)):

- `no_postman` — почтальон не задан в `connect(pass, { postman })` (`api.no_postman`).
- `postman_failed` — почтальон бросил ошибку — код не выдан, исходная ошибка в `err.cause` (`api.postman_failed`).
- `invalid_data` — контакт не одной формы (`api.contact_form`, `sql-access.contact_args`); число цифр, попыток или `ttl` не по правилу.

**Примеры:** [Ключи жильца: пароль и TOTP, ключ API, ключ и секрет, внешний вход, код](../auth/#пример-все-ключи-жильца) · [Вход кодом: requestCode, tenantsOf и выбор квартиры](../auth/#вход-кодом-из-письма) · [Смена контакта и имени: код на новый адрес, changeName](../auth/#смена-контакта) · [Обслуживание: letopis maintain убирает погашенные сессии, коды и истёкшие приглашения](../ops/#обслуживание-letopis-maintain)

### db.tenantsOf() {#house-tenantsof}

```ts
tenantsOf(key: Contact & { code: string }): Promise<{ id: string; name: string }[]>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Квартиры аккаунта контакта по коду входа — по имени (по возрастанию); код не гаснет. Неверный код — api.code_failed.

Код не гаснет: следом им же входят — `db.open({ …контакт, code, tenant })`. Неверный код тратит попытку; пять неверных вводов подряд (здесь и в `db.open`) гасят код.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `key` | `Contact & { code: string }` | обязательный | Контакт и код из письма: `{ phone \| email \| telegram \| kind+address, code }`. |

**Возвращает:** `Promise<{ id: string; name: string }[]>` — Массив `{ id, name }` — квартиры, где прописан аккаунт контакта, по имени (по возрастанию).

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — код не подошёл или истёк (`api.code_failed`).
- `invalid_data` — контакт не одной формы (`api.contact_form`).

**Примеры:** [Ключи жильца: пароль и TOTP, ключ API, ключ и секрет, внешний вход, код](../auth/#пример-все-ключи-жильца) · [Вход кодом: requestCode, tenantsOf и выбор квартиры](../auth/#вход-кодом-из-письма)

## Приглашения

### me.invite() {#db-invite}

```ts
invite(
  to: Contact,
  roles: string[],
  opts?: { ttl?: string | number },
): Promise<{ id: string; expiresAt: string }>
```

**Откуда:** `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`); у транзакции `me.begin()` этого нет.

Позвать по контакту: ссылку (токен) получит только почтальон. Роли — те, что звавшему разрешает выдать матрица (`me.acl.grant({ role, assign })`); контакт уже прописан — already_member; прежнее приглашение контакта гаснет.

Звать может жилец, консьерж в квартире (`db.in()`) и консьерж от имени жильца (`db.as()` — тогда права жильца). Право звать — право выдать **каждую** роль приглашения: правило `me.acl.grant({ role, assign })`; приглашение без ролей требует права на все роли (`assign: '*'`). Живое приглашение того же контакта в эту квартиру гаснет. Приглашение записывается, и в той же транзакции вызывается почтальон: `{ to, message: { kind: 'invite', token, tenant, tenantName, roles, from?, expiresAt } }`; почтальон бросил ошибку — приглашения нет, прежняя ссылка жива. Токен — 48 шестнадцатеричных знаков, в базе — только его хэш. Событие журнала — `auth.invite`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `to` | `Contact` | обязательный | Контакт: `{ email }`, `{ phone }`, `{ telegram }` или `{ kind, address }`. |
| `roles` | `string[]` | обязательный | Роли будущей прописки, например `['staff']`: разные имена без запятых, фигурных скобок, крайних пробелов и «!» в начале. |
| `opts` | `{ ttl?: string \| number }` | `{}` | Срок приглашения. |
| `opts.ttl` | `string \| number` | 7 дней | Срок: секунды числом или строка (`'2 days'`). |

**Возвращает:** `Promise<{ id: string; expiresAt: string }>` — `{ id, expiresAt }`: id приглашения (для `revokeInvite()`) и срок, строка ISO 8601. Токена в ответе нет.

**Ошибки** ([все коды](../errors/)):

- `no_postman` — почтальон не задан в `connect(pass, { postman })` (`api.no_postman`).
- `postman_failed` — почтальон бросил ошибку — приглашения нет (`api.postman_failed`).
- `acl_denied` — нельзя выдать роль (`sql-access.role_denied`, `err.params.role`) или звать без ролей без права на все роли (`sql-access.invite_denied`).
- `exists` — контакт уже прописан в квартире (`sql-access.already_member`).
- `invalid_data` — контакт не одной формы (`api.contact_form`, `sql-access.contact_args`); роли не по правилу (`sql-access.roles_args`); неверный `ttl`.

**Примеры:** [Несколько жильцов: owner, сотрудник и правила по ролям](../access/#пример-жильцы-роли-и-правила) · [Роли: кто их выдаёт — правило матрицы assign](../access/#роль-ресурс-матрицы) · [Ключи жильца: пароль и TOTP, ключ API, ключ и секрет, внешний вход, код](../auth/#пример-все-ключи-жильца) · [Выписка, удаление аккаунта и квартиры](../auth/#выписка-удаление-аккаунта-и-квартиры) · [Hello, world!](../#hello-world) · [Дом, консьерж, квартира и первый жилец](../install/#пример-дом-консьерж-квартира-и-первыи-жилец) · [Приглашение целиком: позвать, письмо, страница, принять](../invites/#пример-приглашение-целиком) · [Края приглашения: повтор, отмена, потеря права, почтальон не доставил](../invites/#края-что-будет-если) · [Первые 15 минут: дом, консьерж, квартира, жилец и три цепочки](../first/#четыре-шага-на-примере) · [С нуля: дом, пропуск, вход по ключу и второй жилец](../start/#семь-шагов-на-примере)

### db.invitation() {#house-invitation}

```ts
invitation(token: string): Promise<Invitation>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Посмотреть приглашение по ссылке: ничего не меняет. Токена нет — api.invite_unknown.

Только смотрит: ничего не пишет и попыток не считает — страница «вас пригласили» показывает его до принятия. Погашенное приглашение видно со своим `status`, пока не истёк его срок и его не убрал `db.maintain()`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `token` | `string` | обязательный | Токен из ссылки приглашения. |

**Возвращает:** `Promise<Invitation>` ([Invitation](./types-setup#type-invitation)) — `{ tenant, tenantName, to, roles, from?, expiresAt, status, hasAccount }`: квартира, контакт под маской (`o***@x.ru`), роли, кто позвал (`from.name` — имя аккаунта, у аккаунта без имени — пустая строка; у приглашения консьержа поля нет), срок, состояние (`active`, `expired`, `revoked`, `used`) и есть ли у контакта аккаунт в доме.

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — токена нет (`api.invite_unknown`).

### db.accept() {#house-accept}

```ts
accept(
  token: string,
  opts?: { password?: string; name?: string; ttl?: string | number },
): Promise<Room<M>>
```

**Откуда:** `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Принять приглашение: аккаунт контакта (есть — он, нет — новый) прописывается в квартире с ролями приглашения. password — по желанию: пароль этой квартиры; name — имя нового аккаунта (его видят соседи по квартире: `me.acl.people()`); не задано — имя пустое: адрес контакта именем не становится.

Входить заранее не нужно: один вызов и для нового человека, и для того, у кого аккаунт в доме уже есть. Всё — одной транзакцией: матрица проверяется заново — звавший ещё прописан и вправе выдать каждую роль приглашения (приглашение консьержа эту проверку проходит всегда), иначе ссылка гаснет; аккаунт ищется по контакту приглашения — есть — прописывается он (имя не меняется), нет — заводится новый (без `name` — с пустым именем); с `password` в этой квартире заводится ключ «пароль», имя для входа — контакт; прописка с ролями приглашения, сессия, приглашение — `used`. Пароль, совпавший с паролем этого аккаунта в другой квартире, — `invalid_data`, ссылка жива, попытка засчитана; пятая такая попытка гасит ссылку. Ссылку можно переслать, поэтому сессия из `accept` у аккаунта, который уже был, не считается недавним входом: ключи, контакт и удаление аккаунта — после входа паролем или кодом; новому аккаунту это доступно 10 минут. Событие журнала — `auth.login` (`method: 'invite'`).

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `token` | `string` | обязательный | Токен из ссылки приглашения — 48 шестнадцатеричных знаков; его получает только почтальон (письмо `kind: 'invite'`). |
| `opts` | `{ password?: string; name?: string; ttl?: string \| number }` | `{}` | Пароль, имя и срок сессии. |
| `opts.password` | `string` | нет | Пароль этой квартиры; без него вход — кодом (`db.requestCode`). |
| `opts.name` | `string` | пустая строка: адрес контакта именем не становится | Имя нового аккаунта — его видят соседи по квартире (`me.acl.people()`); у существующего имя не меняется, сменить — `me.changeName()`. |
| `opts.ttl` | `string \| number` | 7 дней | Срок сессии: секунды числом или строка (`'1 day'`). |

**Возвращает:** `Promise<Room<M>>` — Корень квартиры (`me`) принявшего.

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — токена нет (`api.invite_unknown`); приглашение истекло, отменено или уже принято (`api.invite_inactive`, `err.params.status`); пятая неудачная попытка (`api.invite_attempts`).
- `acl_denied` — звавший больше не вправе выдать роли приглашения, ссылка погашена (`api.invite_lost`).
- `invalid_data` — пароль уже открывает другую квартиру этого аккаунта (`api.password_reused`); неверный `ttl`.
- `exists` — контакт уже прописан в квартире (`sql-access.already_member`).

### me.changeName() {#db-changename}

```ts
changeName(name: string): Promise<{ name: string }>
```

**Откуда:** `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`); у транзакции `me.begin()` этого нет.

Сменить имя своего аккаунта: аккаунт один на дом, новое имя сразу видно во всех квартирах человека (`me.acl.people()`, `from.name` новых приглашений, строка `me.Account(me.account)`). Имя — строка от 1 до 200 знаков, пробелы по краям отбрасываются, иначе sql-access.name_args. Жильцу нужен недавний вход (как у changeContact); у корня `db.as(аккаунт, квартира)` — имя этого человека, без недавнего входа (за него ручается приложение); у корня `db.in` — api.resident_only. Ответ — имя, как оно записано.

Аккаунт один на дом, поэтому новое имя сразу видно во всех квартирах человека: в `me.acl.people()`, в `from.name` новых приглашений, в строке `me.Account(me.account)`. Кто зовёт: сам человек со своей сессии (`db.open`, `db.resume`) — после недавнего входа паролем, кодом или внешним входом; приложение от лица человека — `(await db.as(аккаунт, 'Мир')).changeName(имя)` — без недавнего входа (за человека ручается приложение); консьерж в квартире (`db.in()`) — нельзя. Чужое имя не сменить никаким путём: правка строки `Account` цепочкой закрыта (`write.rows_denied`). Правка — новая версия строки `Account` в журнале; то же имя ещё раз — без новой версии. Сессии не гаснут, прав имя не меняет.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | `string` | обязательный | Новое имя: строка от 1 до 200 знаков; пробельные знаки по краям отбрасываются. |

**Возвращает:** `Promise<{ name: string }>` — `{ name }` — имя, как оно записано (без крайних пробелов).

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — имя пустое после обрезки, длиннее 200 знаков или не строка (`sql-access.name_args`).
- `acl_denied` — сам человек вошёл давно, по ключу API, по ключу с секретом или его сессия — из `accept` аккаунта, который уже был (`sql-access.bind_denied`).
- `invalid_query` — у консьержа в квартире `db.in()` (`api.resident_only`).
