### ne() {#export-ne}

```ts
ne(v: Scalar): Op
```

≠ (IS DISTINCT FROM)

Условие «значение поля не равно `v`»: `db.Order({ status: ne('cancelled') })`. Строки, где поля нет или в нём `null`, тоже подходят. `ne(null)` находит строки, где у поля есть значение. Значение приводится к типу поля из описания класса.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `v` | `Scalar` | обязательный | Значение для сравнения: строка, число, логическое значение или `null`. |

**Возвращает:** `Op` ([Op](./types#type-op)) — Оператор фильтра — объект-маркер для значения поля в фильтре шага.

### isOp() {#export-isop}

```ts
isOp(v: unknown): v is Op
```

Проверяет, оператор ли перед вами: результат `gt()`, `like()`, `or()` и других функций этого раздела. | Параметр | Тип | По умолчанию | Описание |

| `v` | `unknown` | обязательный | Любое значение. |

**Возвращает:** `v is Op` — `true`, если `v` — оператор фильтра, иначе `false`.

## Приращение и курсор

### inc() {#export-inc}

```ts
inc(by: number, opts?: { start?: number }): IncMarker
```

Приращение в update: `update({ balance: inc(-300) })` — величина прибавляется в базе, внутри оператора, над свежей строкой (функция inc). Поля нет — ошибка; `{ start }` — начать с него.

Прибавляет величину к числовому полю при записи: `db.Product(id).update({ price: inc(-500) })`. Сложение делает сама база над текущим значением поля, без чтения в приложении, поэтому одновременные приращения не теряются, а правило класса вроде `min(0)` проверяется над итогом. Поле во вложенном объекте — `update({ stats: { views: inc(1) } })`, путь идёт только через существующие объекты. Работает только в `update()`. Сама функция ничего не проверяет: ошибки приходят при выполнении цепочки — `invalid_data`, если маркер стоит в `create()`, `upsert()`, `rekey()`, `reclass()`, загрузчике или внутри массива, если величина не конечное число, если поля нет и не задан `start`, если в поле `null` или не число (даже со `start`), если итог нарушает описание класса.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `by` | `number` | обязательный | Сколько прибавить; отрицательное число вычитает. Деньги храните целым числом мелких единиц (копеек). |
| `opts` | `{ start?: number }` | `{}` | Настройки приращения. |
| `opts.start` | `number` | нет | Начальное значение, если поля ещё нет: поле получит `start + by`. Без `start` отсутствующее поле — ошибка `invalid_data`. |

**Возвращает:** `IncMarker` ([IncMarker](./types#type-incmarker)) — Маркер приращения — замороженный объект, который понимает `update()`. Из JSON его не получить.

**Ошибки:** собственных кодов нет.

**Примеры:** [Счётчики inc и защита от параллельной правки { rev }](../write/#числа-счетчики-и-защита-от-параллельнои-правки)

### cursorOf() {#export-cursorof}

```ts
cursorOf(row: Row, field: string): Cursor
```

Курсор keyset-пагинации из последней строки страницы.

Нужен для постраничного вывода «после такой-то строки»: возьмите последнюю строку страницы и передайте курсор в `after()` следующего запроса с тем же `sort()`: `db.Product().sort('data.price', 'desc').after(cursorOf(page.at(-1), 'data.price')).limit(20).rows()`. Направление берётся из `sort()`. Такой вывод не сбивается от вставок и удалений между страницами. Курсор — простой объект `{ v, id }`: его можно отдать клиенту в JSON и принять обратно. Поле курсора должно совпадать с полем `sort()`: значение проверяется по типу поля до запроса, и неподходящее даёт `invalid_query` в `after()`, но курсор того же типа с другого поля проверка не отличит.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `row` | `Row` | обязательный | Последняя строка страницы — строка ответа с `id` и тем полем, по которому идёт сортировка. |
| `field` | `string` | обязательный | Поле сортировки, как в `sort()`: `'at'`, `'rev'`, `'id'` или `'data.<путь>'`, например `'data.price'`. |

**Возвращает:** `Cursor` ([Cursor](./types#type-cursor)) — Курсор `{ v, id }`: значение поля в этой строке и её id. Если поля данных в строке нет, `v` — `null`.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — Поле не `at`, `rev`, `id` и не начинается с `data.`.

**Примеры:** [Сортировка, страницы и итоги](../read/#сортировка-страницы-и-итоги)

## id объектов

### idOf() {#export-idof}

```ts
idOf(cls: KeyedClass, key: Readonly<Record<string, unknown>>, opts: { tenant: string }): string
```

id объекта класса с ключом: `idOf(класс, { поле: значение, Роль: id }, { tenant })`. Значения ключевых полей — строки как есть (база их не нормализует), значения концов — id целей. Для класса без ключа id выдаёт база — ошибка `no_key`.

Вычисляет id без запроса к базе — тот же, что база даст объекту при создании: UUID версии 5 из арендатора, имени класса и значений ключа в порядке, в котором ключ объявлен. Значения берутся как есть: «Anna@x.ru» и «anna@x.ru» дают разные id. Подключение делает то же короче: `db.idOf('Shop', { name: 'Ромашка' })` берёт описание класса из реестра и арендатора сессии.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cls` | `KeyedClass` | обязательный | Описание класса: `{ name, key, ends }` — имя класса, части ключа в объявленном порядке и имена концов класса. Для класса из базы подходит `db.registry.resolve(имя)` с `ends: Object.keys(класс.ends)`. |
| `key` | `Readonly<Record<string, unknown>>` | обязательный | Значения частей ключа: у поля — строка, у конца — id цели. id цели можно писать в любом регистре: он приводится к строчным буквам. |
| `opts` | `{ tenant: string }` | обязательный | Где вычислять id. |
| `opts.tenant` | `string` | обязательный | id арендатора, которому принадлежит объект. |

**Возвращает:** `string` — id объекта — строка UUID.

**Ошибки** ([все коды](../errors/)):

- `no_key` — У класса нет ключа: id такого объекта выдаёт база при создании.
- `invalid_data` — Часть ключа не передана или не строка, значение конца — не uuid, `opts.tenant` — не uuid.

**Примеры:** [Служебные экспорты: id из ключа, пароли, валидатор, типы, зарезервированные имена](../models/#служебные-функции-пакета)

### uuidv5() {#export-uuidv5}

### fromDbError() {#export-fromdberror}

```ts
fromDbError(e: unknown): unknown
```

Ошибка базы → LetopisError (ValidationError для invalid_data с нарушениями). Детали из DETAIL (JSON) переносятся в detail; прочие ошибки возвращаются как есть.

Библиотека сама переводит ошибки базы, поэтому вызывать функцию нужно только для сырого SQL через свой клиент PostgreSQL: ошибка с SQLSTATE `LT001`–`LT023` становится `LetopisError` с кодом из главы «Ошибки», `invalid_data` со списком нарушений — `ValidationError`. Отказ политики доступа на новых значениях строки (SQLSTATE `42501`) становится `acl_denied`. Исходная ошибка остаётся в `cause`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `e` | `unknown` | обязательный | Пойманная ошибка — обычно ошибка драйвера PostgreSQL. |

**Возвращает:** `unknown` — Переведённую ошибку; остальные ошибки — без изменений, тем же объектом. Функция ошибку возвращает, а не бросает: `throw fromDbError(e)`.

**Ошибки:** собственных кодов нет.

**Примеры:** [Ошибки базы: что ловят триггеры при записи в обход библиотеки](../errors/#запись-в-обход-библиотеки-что-ловит-база)

## Пароли и коды

### hashPassword() {#export-hashpassword}

```ts
hashPassword(password: string): Promise<string>
```

Хэш пароля scrypt: `scrypt$N$r$p$соль$хэш`.

`db.auth.setPassword()` хэширует пароль сам, вызывать эту функцию для него не нужно. Параметры scrypt: N = 32768, r = 8, p = 1, соль — 16 случайных байт, хэш — 32 байта; соль и хэш записаны в base64. Из-за случайной соли два вызова с одним паролем дают разные строки; проверяет пароль `verifyHash()`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `password` | `string` | обязательный | Пароль открытым текстом. |

**Возвращает:** `Promise<string>` — Строку вида `scrypt$32768$8$1$<соль>$<хэш>`.

**Ошибки:** собственных кодов нет.

**Примеры:** [Служебные экспорты: id из ключа, пароли, валидатор, типы, зарезервированные имена](../models/#служебные-функции-пакета)

### verifyHash() {#export-verifyhash}

```ts
verifyHash(password: string, stored: string): Promise<boolean>
```

Проверка пароля по хэшу scrypt; другие форматы не проверяются.

Параметры scrypt берутся из самой строки хэша, поэтому подходят и хэши с другими N, r, p. Сравнение идёт за постоянное время, чтобы по времени ответа нельзя было подобрать хэш. Строка не в формате `scrypt$…` даёт `false`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `password` | `string` | обязательный | Пароль, который ввёл пользователь. |
| `stored` | `string` | обязательный | Сохранённый хэш — строка от `hashPassword()`. |

**Возвращает:** `Promise<boolean>` — `true`, если пароль подходит к хэшу, иначе `false`.

**Ошибки:** собственных кодов нет.

**Примеры:** [Служебные экспорты: id из ключа, пароли, валидатор, типы, зарезервированные имена](../models/#служебные-функции-пакета)

### totpCode() {#export-totpcode}

```ts
totpCode(secretBase32: string, atMs?: number): string
```

Код приложения-аутентификатора для секрета на момент времени (RFC 6238; помощник для тестов и сервисов).

Вычисляет тот же шестизначный код, что показывает приложение-аутентификатор: шаг 30 секунд, HMAC-SHA1. Нужен в тестах и сервисах, которые сами получают код, например `db.auth.verifyTotp({ account, code: totpCode(secret) })`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `secretBase32` | `string` | обязательный | Секрет TOTP в base32 — `secret` из `db.auth.enrollTotp()`; регистр не важен, `=` в конце допускаются. |
| `atMs` | `number` | `Date.now()` | Момент времени в миллисекундах с 1970 года. |

**Возвращает:** `string` — Код из шести цифр строкой, с ведущими нулями.

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — В секрете есть символ не из алфавита base32.

**Примеры:** [Вход: пароль, ключ API, одноразовый код, TOTP, внешняя учётная запись](../auth/#пример-все-способы-входа)

### DDL_REVISION {#export-ddl-revision}

```ts
const DDL_REVISION = 7
```

Ревизия движка в базе: штамп в lib/sql/99-revision.sql должен совпадать.

Номер версии SQL-части letopis, которую знает эта версия пакета. `up()` записывает ревизию в комментарий схемы. Если схема старше пакета, `connect()` предупреждает в консоли, а `up()` без `upgrade: true` отказывается работать — нужен `up({ schema, upgrade: true })`. ### RESERVED_CLASS_NAMES {#export-reserved-class-names}

```ts
const RESERVED_CLASS_NAMES: readonly string[]
```

Зарезервированные имена: Proxy разбирает их раньше классов, поэтому класс с таким именем недостижим как шаг. Установщик подставляет список в функцию базы reserved_names(), которая отклоняет связи с такими именами; совпадение со switch Proxy проверяет check-docs.

Это имена методов цепочки, корня `db` и батча. Библиотека сначала проверяет, не метод ли это, и только потом ищет класс, поэтому класс с таким именем нельзя назвать шагом цепочки. Класс-связь (`link`) с таким именем база не создаст (`invalid_class`).

**Примеры:** [Служебные экспорты: id из ключа, пароли, валидатор, типы, зарезервированные имена](../models/#служебные-функции-пакета)
