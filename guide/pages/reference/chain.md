# Цепочка

Цепочка — это вызовы подряд: `me.Класс(фильтр)` начинает путь у корня квартиры, шаги переходят по концам, модификаторы уточняют выборку, глагол говорит, что сделать, а терминал отправляет запрос в базу. Пока не вызван терминал, база не тронута. Глаголы складывают план записи — что сделать с какими объектами; терминал выполняет весь план одной транзакцией. Корень квартиры `me` даёт консьерж `db` из `connect(pass)`: жильцу — `db.open(ключ)` или `db.accept(token)`, консьержу — `db.in(квартира)`; у самого `db` шагов классов нет.

**Что здесь:** [Шаг](#шаг) · [Модификаторы](#модификаторы) · [Терминалы](#терминалы). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

::: info Цепочка — не промис
<span id="chain-then"></span>У цепочки нет метода `then`: `await me.Класс(…)` без терминала отдаёт саму цепочку и ничего не читает. Имя `then` занято — класс так назвать нельзя. Пример: [Концы шагами ролей: set, unset, add, remove; entity(), cache(); await цепочки — не запрос](../write/#концы-из-пути-цепочки-и-вызовами-роль-set-add-remove).
:::

## Шаг

### .Класс(фильтр) {#chain-step}

```ts
me.Класс(filter?: Filter): Chain
chain.Класс(filter?: Filter): Chain
chain.Конец(filter?: Filter): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Шаг цепочки — имя класса, его алиаса или роли с необязательным фильтром: `me.Shop(id).Product({ price: gt(1000) })`; каждый следующий шаг переходит по концам от объектов предыдущего. После `create()`, `update()` или `upsert()` имя роли без вызова задаёт конец записываемой строки: `.Роль.set(…)`, `.Роль.unset()`, у множественного конца ещё `.Роль.add(…)` и `.Роль.remove(…)`.

Объекты классов-потомков шаг тоже находит. Первый шаг (`me.Класс(…)`) выбирает объекты класса, а переход идёт в обе стороны: к тем, кто ссылается на объекты предыдущего шага (назад), или к целям их концов (вперёд); шаг к тому же классу ведёт к детям. Шаг с именем роли переходит именно по этому концу. Концы записываемой строки задают шаги концов — раздел «Шаги ролей».

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `filter` | `Filter` | нет — все объекты шага | Фильтр шага: id, список id, строка ответа (объект из результата терминала; берётся её id), объект полей `data` любой вложенности (простое значение — равенство, оператор вроде `gt(5)` — сравнение) или `or(…)`. Ключ с именем роли отбирает по концу: значение — id цели или `null` (конец пуст). |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с этим шагом в конце.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — такого класса, алиаса или роли нет — сразу при обращении к имени.
- `no_path` — от предыдущего шага к этому нет перехода: ни один класс не ссылается на другой.
- `invalid_query` — фильтр неверной формы (например, оператор вне поля, кроме `or`) или поле фильтра не описано ни в одном классе шага (похожие имена — в `err.params.similar`); ошибку бросает терминал, когда собирает запрос, у записи — до записи.

**Примеры:** [Шаги и переходы: от объекта к объекту](../read/#пример-шаги-и-переходы) · [Фильтры: все 18 операторов](../read/#фильтры) · [Наследование, абстрактный класс и алиас](../models/#наследование-и-алиасы)

## Модификаторы

Модификатор уточняет цепочку и возвращает её продолжение: сколько строк, в каком порядке, на какой момент.

### .limit() {#chain-limit}

```ts
limit(n: number): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Не больше n строк ответа: объектов последнего шага, у `paths()` — путей, у `versions()` — версий, перед `countBy()` — групп. До глагола сужает его цели. Сразу после глагола перед `rows`, `first`, `ids`, `count` и `paths` — `invalid_query`: глагол уже прошёл по всем целям, сужать нечего. `n` — целое от 0: иное (дробное, отрицательное, строка, `null`, вызов без числа) — `invalid_query` при вызове `limit()`.

Какие строки попадут в ответ, задаёт `sort()`: без него порядок не определён. Группы `countBy()` идут от самых частых значений; на `count()`, `sum()`, `avg()`, `min()` и `max()` ограничение не влияет. Сужение целей глагола: `me.Product().sort('data.price', 'desc').limit(1).update(…)` правит один самый дорогой товар. Число проверяется при вызове `limit()`: всё, кроме целого от 0 (дробное, отрицательное, строка, `null`, вызов без числа), — отказ `invalid_query` до запроса.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `n` | `number` | обязательный | Сколько строк вернуть: целое число от 0. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с ограничением.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — число не целое от 0 или лишний аргумент — при вызове `limit()`; модификатор стоит сразу после глагола записи, а за ним — `rows()`, `first()`, `ids()`, `count()` или `paths()`.

**Примеры:** [Сортировка, страницы и итоги](../read/#сортировка-страницы-и-итоги)

### .offset() {#chain-offset}

```ts
offset(n: number): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Пропустить первые n строк ответа — тех же, что считает `limit()`; где действует — как у `limit()`. `n` — целое от 0: иное (дробное, отрицательное, строка, `null`, вызов без числа) — `invalid_query` при вызове `offset()`.

Постраничный вывод по номеру страницы, обычно вместе с `sort()` и `limit()`. Для длинных списков надёжнее `after()`: вставки и удаления между запросами сдвигают страницы `offset()`. Число проверяется при вызове `offset()`: всё, кроме целого от 0, — отказ `invalid_query` до запроса.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `n` | `number` | обязательный | Сколько строк пропустить: целое число от 0. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку со сдвигом.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — число не целое от 0 или лишний аргумент — при вызове `offset()`; модификатор стоит сразу после глагола записи, а за ним — `rows()`, `first()`, `ids()`, `count()` или `paths()`.

**Примеры:** [Сортировка, страницы и итоги](../read/#сортировка-страницы-и-итоги)

### .sort() {#chain-sort}

```ts
sort(field: string, dir?: 'asc' | 'desc' | boolean): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Сортировка по полю последнего шага: 'at' | 'rev' | 'id' | 'data.&lt;путь&gt;'. Поле одно — строка: список полей, объект и вызов без поля — `invalid_query` при вызове `sort()`; направление — `'asc'`, `'desc'` или `true` (по убыванию), иное значение и лишний аргумент (второе поле) — тоже `invalid_query`. Повторный `sort()` заменяет прежний.

Поле данных сравнивается по типу из описания класса (число — как число, дата — как дата), путь внутрь поля-объекта без описания типа — как текст. При равных значениях порядок — по id. Строки, где поля нет или оно `null`, идут в конце при возрастании и в начале при убывании. Перед глаголом записи `sort()` с `limit()` выбирает его цели. Поле сортировки одно: повторный `sort()` заменяет прежний.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `field` | `string` | обязательный | `'at'` (время версии), `'rev'` (номер версии), `'id'` или `'data.<путь>'` — поле данных, путь через точку. |
| `dir` | `'asc' \| 'desc' \| boolean` | `'asc'` | `'asc'` — по возрастанию, `'desc'` или `true` — по убыванию. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с порядком.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — поле не строкой (список полей, объект, число, вызов без поля) — сразу при вызове (`query.sort_field`); после поля не направление или лишний аргумент, например второе поле, — сразу при вызове (`api.sort_args`); поле не `at`, `rev`, `id` и не `data.<путь>` или поле `data.<путь>` не описано ни в одном классе шага (похожие имена — в `err.params.similar`; сверяется первый ключ пути) — ошибку бросает терминал.

**Примеры:** [Несколько жильцов: owner, сотрудник и правила по ролям](../access/#пример-жильцы-роли-и-правила) · [Сортировка, страницы и итоги](../read/#сортировка-страницы-и-итоги) · [Первые 15 минут: дом, консьерж, квартира, жилец и три цепочки](../first/#четыре-шага-на-примере)

### .after() {#chain-after}

```ts
after(cursor: Cursor): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Постраничный вывод по курсору: ответ начинается строго после строки, на которой кончилась прошлая страница, в порядке `sort()` (без `sort()` — ошибка `invalid_query`). Курсор этой строки даёт `cursorOf(строка, поле)` с тем же полем, что в `sort()`. Листает `rows()`, `ids()`, `versions()` и `paths()` (курсор пути — `cursorOf(путь, поле)`); перед `count()` и агрегатами (`sum`, `avg`, `min`, `max`, `countBy`) — `invalid_query`: они считают по всем объектам.

Страницы отсчитываются по значению поля, а не по номеру строки, поэтому вставки и удаления между запросами их не сдвигают. Курсор — простой объект: его можно отдать клиенту в JSON и получить обратно.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `cursor` | `Cursor` | обязательный | Курсор `{ v, id, rev }` из `cursorOf(последняя строка страницы, поле)`; поле — то же, что в `sort()`. Для `paths()` — `cursorOf(последний путь, поле)`: в нём ещё `path` с id всех узлов. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку, которая начинает ответ после курсора.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — нет `sort()`, курсор без `v`, `id` курсора не uuid или значение не подходит к типу поля `sort()`; терминал — `count()` или итог (`sum()`, `avg()`, `min()`, `max()`, `countBy()`): курсор листает только `rows()`, `ids()`, `versions()` и `paths()`. Ошибку бросает терминал до запроса.

**Примеры:** [Сортировка, страницы и итоги](../read/#сортировка-страницы-и-итоги)

### .asOf() {#chain-asof}

```ts
asOf(t: string | Date): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Срез «как было на момент T»: версии журнала. Момент — `Date` или строка ISO 8601: дата (`2026-10-07`) либо дата и время (`2026-10-07T10:00:00Z`; секунды и пояс необязательны, без пояса — время UTC); иное — `invalid_query` при вызове `asOf()`.

Срез действует на каждый шаг цепочки. Он собирается из журнала, поэтому дороже чтения текущего состояния. Время версии хранит микросекунды, а `Date` — только миллисекунды: передавайте строку `at` как есть, иначе срез на момент версии может её не застать. У класса без журнала (`history: false`) истории нет, и срез пуст; библиотека один раз предупреждает об этом в консоли.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `t` | `string \| Date` | обязательный | Момент: строка ISO 8601 — дата (`2026-10-07`) либо дата и время (`2026-10-07T10:00:00Z`; секунды, их доли и пояс необязательны), например `at` строки ответа, — или `Date`. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку, которая читает данные такими, какими они были в этот момент.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — момент не строка ISO 8601 и не `Date` (`'now'`, `'20261002'`, число, `null`, неверная дата, вызов без момента) — сразу при вызове; после `asOf()` стоит глагол записи: прошлое не меняют.

**Примеры:** [Версии и срез на момент](../history/#пример-версии-и-срез-на-момент)

### .withDeleted() {#chain-withdeleted}

```ts
withDeleted(): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Шаг, после которого стоит, находит и удалённые объекты — модификатор своего шага, как `exact()`: `me.Member(id).withDeleted().Loan().withDeleted()` — удалённые выдачи удалённого участника. Удалённый объект приходит надгробием — своей последней версией, версией удаления, — с `$deleted: true`.

`withDeleted()` не у последнего шага, когда у последнего его нет (`X().withDeleted().Y()`), даёт живых `Y` — letopis один раз предупреждает (`console.warn`). Переход идёт по последней версии строки. Надгробие несёт данные на момент удаления; живые объекты шага тоже в ответе. У класса без журнала (`history: false`) удалённых не найти: надгробий у него нет.

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с надгробиями в ответе.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — дальше идёт глагол записи, кроме `restore()`, или на последнем шаге стоит `deep()`.
- `lock_unsupported` — вместе с `forUpdate()`.

**Примеры:** [Вернуть удалённое](../delete/#вернуть-удаленное)

### .deep() {#chain-deep}

```ts
deep(max?: number): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Дети любой глубины на переходе к тому же классу; $depth в строке. `max` — целое от 1, иное — `invalid_query`.

Ставится на шаг к тому же классу (категория → её подкатегории): без `deep()` такой шаг даёт только детей, с ним — ещё внуков и дальше, до `max` уровней. `$depth` строки — её уровень: 1 — дети, 2 — внуки. Фильтр, теги и владелец шага отбирают объекты любого уровня, но обход не обрывают. Обрывает его только объект, невидимый по правам: дальше него обход не идёт.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `max` | `number` | `32` | Наибольшая глубина обхода — число уровней. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с обходом в глубину.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — `deep()` на первом шаге, не на переходе к тому же классу, вместе с `withDeleted()` на том же шаге или после глагола записи.
- `lock_unsupported` — вместе с `forUpdate()`.

**Примеры:** [Деревья, пути и подсчёт путей](../read/#деревья-и-пути)

### .alias() {#chain-alias}

```ts
alias(name: string): Chain
```

### .cache() {#chain-cache}

```ts

```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Ответ на тот же запрос того же жильца берётся из памяти, пока данные не изменились: его сбрасывают записи цепочками через корни этого консьержа и сигналы базы — о записях других процессов и загрузке `letopis load` (подробно — у `me.cache`). Кэш не работает внутри `me.begin()`, в батче, с `forUpdate()` и у цепочек с глаголами. |---|---|---|---|
| `opts` | `{ ttl?: number }` | нет | Настройки кэша. |
| `opts.ttl` | `number` | срок подключения (`connect(pass, { cache: { ttl } })`), иначе `60` | Сколько секунд хранить ответ — положительное число. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку, ответ которой кэшируется.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — `ttl` не положительное число.

Терминал исполняет цепочку и возвращает результат. После глагола записи терминал исполняет план записи и возвращает записанные строки.
