# Загрузка

Загрузчик пишет много строк любых классов быстрее цепочек: проверки — в коде, строки — через `COPY`. Запускается только мастер-ключом — командой `letopis load`; у корня квартиры метода `load` нет.

**Что здесь:** [Команда](#команда). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Команда

### letopis load {#cli-load}

```sh
letopis load <файлы…> --dsn <мастер-ключ> --schema <дом> --tenant <квартира> [--class <Класс>]
  [--duplicates error|first|last] [--existing error|skip|update] [--commit-every <N>] [--initial]
  [--with-history] [--agent <имя>]
```

Массовая загрузка строк из файлов NDJSON в квартиру — мастер-ключом. Строки проверяются в коде по тем же описаниям классов, что и при записи цепочкой (данные, концы, ключ класса), уходят в базу командой `COPY`, а концы к объектам вне загрузки сверяет один запрос в конце. Все файлы — одна загрузка и, без `--commit-every`, одна транзакция: ошибка в любой строке отменяет всё.

Строки пишет роль-владелец схемы; исполнитель в журнале — `letopis load`. Порядок строк и классов не важен, концы по кругу допустимы. Ошибку называет код первой проблемы, а `detail.rows` — первые 100 нарушений (`line` — номер строки входа с 1, `code`, `message`, `id`, `class`, `issues`): они идут в stderr второй строкой. Подписки и кэши узнают о загруженных строках по сигналу базы после фиксации. Неизвестный флаг любая команда отклоняет до подключения к базе: в stderr «неизвестный флаг --aply; см. letopis --help» и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `<файлы…>` | `аргумент` | обязательный | Один или несколько файлов NDJSON в UTF-8: в каждой строке — объект JSON с полями, концами и служебными ключами (`$class` — класс, `$ext` — внешний ключ: id строки в другой системе, `$tags` — теги, `$owner` — владелец). Цель конца — её id, ключ `{ $key: [...] }` или внешний ключ `{ $ext: '…' }`. Пустые строки пропускаются. |
| `--dsn` | `<мастер-ключ>` | обязательный | Мастер-ключ — строка подключения администратора PostgreSQL: суперпользователь или роль, которая может стать владельцем схемы. |
| `--schema` | `<дом>` | обязательный | Имя дома из `setup()`: `shop` (или полное `v2.shop`). |
| `--tenant` | `<квартира>` | обязательный | Квартира, в которую идут строки: имя или id. |
| `--class` | `<Класс>` | нет: класс — в `$class` строки | Класс для строк, у которых нет `$class`. |
| `--duplicates` | `error\|first\|last` | `error` | Повтор id внутри загрузки (одинаковый ключ класса или `$ext`): `error` — отменить загрузку, `first` или `last` — оставить первую или последнюю строку. |
| `--existing` | `error\|skip\|update` | `error` | Объект уже есть в базе: `error` — отменить (`exists`; удалённый раньше — `deleted`), `skip` — пропустить, `update` — записать новую версию, если содержимое отличается (удалённый — создать заново с прежним id). |
| `--commit-every` | `<N>` | одна транзакция | Фиксировать порциями примерно по N строк: ошибка отменяет только текущую порцию, и повтор с `--existing skip` допишет остальное. |
| `--initial` | `флаг` | нет | Первая заливка в пустой дом (кроме строк системных классов): одной транзакцией, на время заливки таблицы дома закрыты, индексы и триггеры сняты и перестраиваются в конце. Несовместима с `--commit-every` и `--existing` (кроме `error`). |
| `--with-history` | `флаг` | нет: каждая строка — новая версия сейчас | Строки — версии объектов с историей: у каждой `$rev`, `$at` (время версии) и `$op`; журнал получает эти версии как есть. Несовместима с `--existing update`. |
| `--agent` | `<имя>` | `letopis load` | Исполнитель записи: строка, которую журнал сохранит в поле `agent` загруженных версий. |

**Возвращает:** Печатает отчёт одной строкой JSON и выходит с кодом 0: `rows` — строк во входе; `loaded` — записано объектов, новых и созданных заново; `updated` — новых версий существующих (`--existing update`); `skipped` — пропущено существующих и неизменённых; `duplicates` — пропущено повторов; `byClass` — новых объектов по классам; `external` — целей вне загрузки, сверенных в конце; `portions` — зафиксировано порций; `ms` — время. Без файлов или `--tenant` — подсказка по командам и код 2; при ошибке — её текст и нарушения в stderr, код 1; строка файла, которая не разбирается как JSON, — тоже код 1.

**Ошибки** ([все коды](../errors/)):

- `admin_required` — мастер-ключ не может стать владельцем схемы.
- `target_not_found` — квартиры с таким именем нет (`api.tenant_unknown`); цель конца или владелец `$owner` не найдены.
- `invalid_data` — строка не проходит описание класса или неверны её концы, `$tags`, `$owner`, `$ext`, части ключа класса; `--initial` вместе с `--commit-every` или `--existing`; имя дома неверно или такого дома нет.
- `invalid_class` — класс строки не найден, абстрактный или у строки нет класса.
- `class_not_loadable` — во входе строки `Class`: классы записывают `setup(…, { models })` и `letopis sync`.
- `duplicate` — id повторяется во входе при `--duplicates error`.
- `exists` — объект уже есть в базе при `--existing error`.
- `deleted` — объект с этим id был раньше и удалён (при `--existing error`).
- `not_empty` — `--initial`, а в доме уже есть данные.
- `tenant_denied` — квартира выключена.
