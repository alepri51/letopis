# Цепочка: запись

Запись — те же цепочки: шаги выбирают объекты, глагол ставит запись в план, терминал (`rows()`, `first()`, `ids()`, `count()`, `paths()`) выполняет весь план одной транзакцией. Шаги, модификаторы и терминалы — на странице [Цепочка](./chain).

**Что здесь:** [Глаголы записи](#глаголы-записи) · [Шаги концов](#шаги-концов). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Глаголы записи

Глагол ставит запись в план. Исполняет план терминал (`rows()`, `first()`, `ids()`, `count()`, `paths()`). `update()` и `delete({ confirm: true, expect })` правят только цели, которые сузили фильтр, id, `tags()`, `owner()` или `limit()` хотя бы одного шага; все строки шага — явно, опцией `{ all: true }`, иначе `invalid_query` до записи. Подтверждённое удаление идёт только с `expect` — предпросмотром, который видел пользователь, а `restore()` — только с `expect` (надгробиями); без сверки — осознанно, `{ all: true }`.

### .create() {#chain-create}

```ts
create(data?: Record<string, unknown>, opts?: { reason?: string }): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Создать объект: концы — из пути и шагов роли; занятый ключ — ошибка exists с id.

Концы новой строки берутся из пути: `me.Shop(shop).Product().create(…)` ссылается на `shop`; явно их задают шаги концов `.Конец.set(…)` после глагола. id новой строки вычисляет база, а id в шаге (`me.Класс(id).create(…)`) его не задаёт — только проверяется. Теги — `.tags([…])` перед глаголом, владелец — `.owner(id)`. Удалённый объект можно создать снова тем же ключом: история продолжится.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `data` | `Record<string, unknown>` | `{}` | Поля нового объекта — целиком, как в описании класса. |
| `opts` | `{ reason?: string }` | нет | Опции записи. |
| `opts.reason` | `string` | причина `me.batch()` или `me.begin()`, иначе нет | Причина изменения — строка до 1000 символов; пишется в журнал. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с глаголом. Терминал вернёт созданные строки; следующий шаг пойдёт от каждой из них.

**Ошибки** ([все коды](../errors/)):

- `exists` — объект с таким ключом уже есть; `detail.id` — его id.
- `invalid_data` — данные не объект, в них `inc()` или оператор фильтра, или они не проходят описание класса (проверка до отправки и в базе).
- `invalid_query` — шаг пути дал не один объект для конца, роль конца неоднозначна, фильтр шага не id, `create()` сразу после другого глагола, неверный `reason`.
- `id_mismatch` — id шага не равен id, вычисленному из ключа.
- `id_from_db` — id задан у класса без ключа: такой id выдаёт база.
- `target_not_found` — цель конца или владелец не найдены (или не видны).
- `invalid_class` — класс абстрактный.
- `acl_denied` — правила доступа не разрешают создать строку.
- `no_session` — у корня нет действующей сессии.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Hello, world!](../#hello-world) · [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) · [Первые 15 минут: дом, консьерж, квартира, жилец и три цепочки](../first/#четыре-шага-на-примере) · [Создать, изменить, создать-или-заменить](../write/#пример-create-update-upsert)

### .update() {#chain-update}

```ts
update(
  patch?: Record<string, unknown>,
  opts?: { rev?: number; all?: boolean; reason?: string },
): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Новая версия каждой цели шага: слияние патча в базе; inc(n) — приращение; { rev } — с проверкой версии. Цели сужают фильтр, id, `tags()`, `owner()` или `limit()` хотя бы у одного шага, иначе `invalid_query`; правка всех строк — `{ all: true }`.

Патч сливается с данными: вложенные объекты — по ключам, а массивы, простые значения и `null` заменяют прежнее значение целиком. Если у шага нет своего фильтра, а в патче есть строка `id`, она выбирает цель и в данные не пишется: `me.Product().update({ id: p.id, price: 90 })` — то же, что `me.Product(p.id).update({ price: 90 })`. Цели сужают фильтр, id, `tags()`, `owner()` или `limit()` хотя бы у одного шага цепочки (или `create()` и `upsert()` раньше в ней); без них правка всех строк шага — только явно, с `{ all: true }`. Фильтр родительского шага тоже сужает: `me.Shop(shop).Product().update(…)` правит все товары магазина. Шаг ничего не нашёл — ответ пустой, без ошибки. Если хоть у одного шага фильтр не только по id (поля данных, концы, фильтр родителя, `tags()`, `owner()`), цели блокируются в порядке id и читаются заново тем же запросом: при гонке правятся только строки, которые после ожидания всё ещё подходят, — из двух одновременных `me.Order({ id, status: 'new' }).update({ status: 'paid' })` проходит один, у второго пустой ответ. Фильтр только по id перепроверять нечего: обе правки проходят по очереди, вторая поверх первой; защита — `{ rev }` (`conflict`) или `inc`. `inc(n)` прибавляет n к текущему значению в базе, а не к прочитанному раньше. `.tags([…])` перед `update()` и отбирает строки, и заменяет их теги целиком.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `patch` | `Record<string, unknown>` | `{}` | Изменения полей; `inc(n)` — приращение числа. Ключевые поля менять нельзя. |
| `opts` | `{ rev?: number; all?: boolean; reason?: string }` | нет | Опции записи. |
| `opts.rev` | `number` | нет — без проверки версии | Номер версии, которую вы прочитали (`rev` строки ответа): запись пройдёт, только если строку с тех пор не меняли. Только при одной цели. |
| `opts.all` | `boolean` | `false` — без условий на цели правка отклоняется (`invalid_query`) | `true` — править все строки шага, хотя ни у одного шага нет фильтра, id, `tags()`, `owner()` или `limit()`. |
| `opts.reason` | `string` | причина `me.batch()` или `me.begin()`, иначе нет | Причина изменения — строка до 1000 символов; пишется в журнал. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с глаголом. Терминал вернёт новые версии изменённых строк.

**Ошибки** ([все коды](../errors/)):

- `conflict` — с `{ rev }`: строку успели изменить; `detail` — `id`, `rev`, `expected`.
- `rev_ambiguous` — `{ rev }` у шага, у которого больше одной цели (и с `{ all: true }`).
- `target_not_found` — строку успели удалить, или с `{ rev }` у шага нет цели.
- `acl_denied` — строка видна, но править её нельзя.
- `invalid_data` — патч не объект, `inc()` внутри массива, оператор фильтра в патче, или итог не проходит описание класса (например, после `inc()` число стало меньше минимума).
- `immutable_key` — патч меняет ключевое поле: ключ, класс и id строки неизменны — объект с другим ключом создают заново.
- `invalid_query` — ни у одного шага нет фильтра, id, `tags()`, `owner()` или `limit()`, а `{ all: true }` не задан (отказ до записи); `rev` не целое число от 1, неверный `reason`, перед глаголом `asOf()` или `withDeleted()`.
- `no_session` — у корня нет действующей сессии.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Создать, изменить, создать-или-заменить](../write/#пример-create-update-upsert)

### .upsert() {#chain-upsert}

```ts
upsert(data: Record<string, unknown>, opts?: { reason?: string }): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Создать или заменить целиком (класс с ключом); строка ответа несёт $upsert.

Это один оператор `INSERT … ON CONFLICT`: между проверкой «такого объекта нет» и созданием никто не вклинится. Существующий объект заменяется целиком — данные, концы и теги; поля, которых нет в переданном объекте, пропадают. Приращать `upsert` не умеет — для счётчиков и денег берите `update()` с `inc()`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `data` | `Record<string, unknown>` | обязательный | Объект целиком, вместе с полями ключа. |
| `opts` | `{ reason?: string }` | нет | Опции записи. |
| `opts.reason` | `string` | причина `me.batch()` или `me.begin()`, иначе нет | Причина изменения — строка до 1000 символов; пишется в журнал. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с глаголом. Терминал вернёт строки с `$upsert`: `created`, `updated` или `unchanged`.

**Ошибки** ([все коды](../errors/)):

- `no_key` — у класса нет ключа — не по чему искать существующий объект; ошибка — до обращения к базе.
- `invalid_data` — данные не объект или не проходят описание класса.
- `invalid_query` — фильтр шага не id, `upsert()` сразу после другого глагола, неверный `reason`.
- `acl_denied` — правила доступа не разрешают такую строку. Если строка уже есть, а править её нельзя, приходит не `acl_denied`, а ошибка PostgreSQL с кодом `42501`.
- `target_not_found` — цель конца не найдена.

**Примеры:** [Создать, изменить, создать-или-заменить](../write/#пример-create-update-upsert)

### .delete() {#chain-delete}

```ts
delete(opts?: DeleteOptions): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Удаляет цели шага; строки, которые на них ссылаются, база удаляет вместе с ними, отвязывает или не даёт удалить цель — как задано в `onDelete` их концов. Без `{ confirm: true }` — предпросмотр удаления: ничего не удаляется, терминал вернёт все строки, которых оно коснулось бы, у каждой `$action` — что с ней будет. `{ confirm: true, expect: предпросмотр }` удаляет ровно показанное: в транзакции удаления предпросмотр строится заново и сравнивается с `expect` по `id`, `rev` и `$action`; расхождение — `conflict` (ничего не удалено, новый предпросмотр — `err.detail.preview`); цели сужают фильтр, id, `tags()`, `owner()` или `limit()` хотя бы у одного шага, иначе `invalid_query`. `{ confirm: true }` без `expect` — `invalid_query` (`write.confirm_without_expect`); осознанно удалить текущий состав целей без сверки (и без фильтра — все строки) — `{ confirm: true, all: true }`.

Значения `$action`: `delete` (удалится), `unset` (конец очистится) или `restrict` (помешает удалению); у удаляемых строк ещё `$depth` — уровень каскада (0 — сама цель). Права на удаление предпросмотр не проверяет; предпросмотр идёт и без условий на цели. С подтверждением цели удаляются одним оператором. Правило одно для цепочек, `me.begin()` и `me.batch()`. История удалённого остаётся в журнале.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `opts` | `DeleteOptions` | нет — только предпросмотр | Опции удаления. |
| `opts.confirm` | `boolean \| undefined` | `false` | `true` — удалить по-настоящему: только вместе с `expect` или `all: true`, иначе `invalid_query` (`write.confirm_without_expect`). |
| `opts.all` | `boolean \| undefined` | `false` — без `expect` или без условий на цели удаление отклоняется (`invalid_query`) | `true` вместе с `confirm` — осознанно удалить текущий состав целей без сверки с предпросмотром: с фильтром — текущие цели фильтра, без фильтра, id, `tags()`, `owner()` и `limit()` — все строки шага. Вместе с `expect` снимает только требование фильтра, а предпросмотр по-прежнему сверяется. |
| `opts.expect` | `readonly Expected[] \| undefined` | нет — `confirm: true` без `expect` и без `all: true` отклоняется (`invalid_query`) | Показанный пользователю предпросмотр (строки `delete()` без подтверждения; нужны `id`, `rev` и, если есть, `$action`) — только с `confirm: true`. В транзакции удаления строки каскада блокируются (`for update`, по порядку id), предпросмотр строится заново под блокировкой и сравнивается с ним без учёта порядка; не совпал — `conflict`, ничего не удалено, новый предпросмотр — в `err.detail.preview`. Строка, которую добавляют в каскад позже, ждёт удаления и получает `target_not_found`. |
| `opts.reason` | `string \| undefined` | причина `me.batch()` или `me.begin()`, иначе нет | Причина изменения — строка до 1000 символов; пишется в журнал. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с глаголом. Терминал вернёт строки предпросмотра или надгробия удалённых (`$deleted: true`) — по уровням каскада, внутри уровня по id. Надгробия — готовый `expect` для `restore({ expect, partial: true })`.

**Ошибки** ([все коды](../errors/)):

- `delete_restricted` — на удаляемые строки ссылаются другие строки через конец с `onDelete: 'restrict'`.
- `conflict` — с `expect`: предпросмотр изменился с тех пор, как его показали (ключ `write.preview_changed`); `detail.preview` — новый предпросмотр.
- `acl_denied` — нет права удалить цель или строку каскада (или очистить её конец).
- `target_not_found` — цель успели удалить.
- `invalid_query` — `{ confirm: true }` без `expect` и без `all: true` (ключ `write.confirm_without_expect`); с `{ confirm: true, expect }` ни у одного шага нет фильтра, id, `tags()`, `owner()` или `limit()`, а `all: true` не задан (ключ `write.no_filter`); `expect` без `confirm: true` (`write.expect_without_confirm`) или не список строк `{ id, rev }`; перед глаголом `asOf()` или `withDeleted()`, неверный `reason`. Все — до записи.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Удаление: предпросмотр, каскад, запрет, очистка конца](../delete/#пример-предпросмотр-каскад-запрет-очистка-конца) · [Удаление по HTTP: предпросмотр, подтверждение, отмена](../recipes/undo#пример-сервер-с-билетами) · [Прокат: одна выдача на вещь, удаление по предпросмотру и возврат без лишнего](../first/#прокат-целиком-ключ-удаление-и-возврат-одним-фрагментом)

### .restore() {#chain-restore}

```ts
restore(opts: RestoreOptions): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Восстановить удалённые объекты шага: последний снимок новой версией (id прежний). `{ expect }` — надгробия `{ id, rev }` из ответа `delete()` или `withDeleted()`: восстанавливаются только цели из `expect`, и только если последняя версия каждой — та же; иначе ничего не восстановлено: уже восстановлена — `not_deleted` (`write.restore_already`), id занял новый объект — `not_deleted` (`write.restore_id_taken`), прочее (удалена снова, менялась) — `conflict` (`write.restore_stale`); причины по целям — `err.detail.stale`. `{ expect, partial: true }` — восстановить то, что можно: остальные цели приходят строками `{ …строка, $action: 'skip', $why }`. Без `expect` — `invalid_query` (`write.restore_without_expect`), и для явных id; осознанно вернуть все удалённые цели шага без сверки — `{ all: true }`.

Удалённые цели шаг находит сам, `withDeleted()` можно не писать. Возвращается последний снимок строки. Восстанавливаются только цели шага, а не весь каскад: строки, удалённые каскадом, возвращают отдельно — по надгробиям этого удаления, с `expect`. `restore()` без `expect` — отказ `invalid_query` (ключ `write.restore_without_expect`) до записи, и для явного id тоже: последнее надгробие могло смениться после того, что видел пользователь. Осознанно вернуть все удалённые цели шага последним снимком, без сверки, — `restore({ all: true })`. Правила приложения (кроме описания класса) не проверяются.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `opts` | `RestoreOptions` | обязательный | Опции возврата: нужен `expect` (надгробия, которые видел пользователь) или осознанно `all: true`. |
| `opts.expect` | `readonly Expected[] \| undefined` | нет — без `expect` и без `all: true` отказ `invalid_query` (`write.restore_without_expect`) | Надгробия, которые нужно вернуть, — строки `{ id, rev }` (подходят строки ответа `delete`, `withDeleted()` или версии удаления из `versions()`). Восстанавливаются только цели шага, чьи id есть в `expect`, и только если последняя версия каждой — то самое надгробие; иначе отказ (`conflict` или `not_deleted`, ниже) и ничего не восстановлено. id из `expect`, которых нет среди строк шага, пропускаются. |
| `opts.partial` | `boolean \| undefined` | нет — одна цель, которую не вернуть, отменяет весь вызов | `true` — только с `expect`: цели, которые не вернуть, не отменяют вызов, а приходят в ответе строками-пропусками — последняя строка цели с `$action: 'skip'` и причиной `$why`: `'changed'` — после удаления строку пересоздавали, правили или удалили снова, `'reissued'` — id занял новый живой объект с тем же ключом, `'restored'` — её уже вернули. Остальные цели восстанавливаются; ответ — в порядке целей. |
| `opts.all` | `boolean \| undefined` | `false` | `true` — осознанно вернуть все удалённые цели шага (с фильтром — удалённые цели фильтра, без него — всё удалённое класса) последним снимком, без сверки. Вместе с `expect` — сверка по `expect`. `partial` без `expect` не принимается и с `all`. |
| `opts.reason` | `string \| undefined` | причина `me.batch()` или `me.begin()`, иначе нет | Причина изменения — строка до 1000 символов; пишется в журнал. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Новую цепочку с глаголом. Терминал вернёт восстановленные строки (с `partial: true` — с `$action: 'restore'`) и строки-пропуски (`$action: 'skip'`, `$why`).

**Ошибки** ([все коды](../errors/)):

- `not_deleted` — шаг нашёл объекты, но ни один не удалён — ключ `write.not_deleted`; объект уже вернули — `write.restore_already`; id уже удаляли, а теперь его занял новый объект с тем же ключом (`create` по ключу удалённого), — `write.restore_id_taken`, с `expect` и без. `detail.ids` — такие цели; с `expect` ещё `detail.stale`, как у `conflict`.
- `conflict` — с `expect`: последняя версия цели уже не то надгробие — объект правлен или удалён снова (ключ `write.restore_stale`); `detail.stale` — каждая цель, которую не вернуть: `{ id, rev, expected, after, deleted, live, why }` (`after` — что было сразу после того удаления, `why` — `'changed'`, `'reissued'` или `'restored'`).
- `invalid_data` — последний снимок не проходит текущее описание класса.
- `acl_denied` — правила доступа не разрешают восстановить строку.
- `invalid_query` — нет ни `expect`, ни `all: true` (ключ `write.restore_without_expect`); перед глаголом `asOf()`, неверный `reason`, `expect` не список строк `{ id, rev }`, `partial: true` без `expect` (ключ `write.partial_without_expect`). Все — до записи.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Вернуть удалённое](../delete/#вернуть-удаленное) · [Удаление по HTTP: предпросмотр, подтверждение, отмена](../recipes/undo#пример-сервер-с-билетами) · [Прокат: одна выдача на вещь, удаление по предпросмотру и возврат без лишнего](../first/#прокат-целиком-ключ-удаление-и-возврат-одним-фрагментом)

## Шаги концов

После глагола записи шаг с именем конца без вызова задаёт конец: `.Конец.set(…)`, `.Конец.unset()`, у множественного конца ещё `.add(…)` и `.remove(…)`.

### .Конец.set() {#chain-set}

```ts
set(value: unknown): Chain
```

**Откуда:** цепочка `me.Класс(…)`; `me` — корень квартиры: жильцу его дают `db.open(ключ)`, `db.resume(токен)`, `db.accept(token)`, консьержу — `db.in(квартира)`, `db.as(аккаунт, квартира)`; `db` — консьерж из `connect(pass, { postman })` (`import { connect } from 'letopis'`).

Задаёт конец строки, которую пишет глагол: ставит в конец роли новую цель, у множественного конца — заменяет весь список. Вызывается после `create()`, `update()` или `upsert()`: `me.Category(green).update({}).Parent.set(tea)`. Концы меняются в базе атомарно, без чтения строки.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `value` | `unknown` | обязательный | Цель: id, список id, строка ответа, цепочка (исполнится в той же транзакции) или `null` — очистить конец. |

**Возвращает:** `Chain` ([Chain](./types-chain#type-chain)) — Цепочку того же глагола: можно задать следующий шаг конца или вызвать терминал.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — не после `create()`, `update()` или `upsert()`; конец этой роли уже задан; у одиночного конца значение дало не один объект; имя не роль класса или подходит нескольким ролям.
- `invalid_class` — имени нет ни среди ролей, ни среди классов.
- `target_not_found` — цель не найдена или не видна.

**Примеры:** [Концы шагами ролей: set, unset, add, remove; entity(), cache(); await цепочки — не запрос](../write/#концы-из-пути-цепочки-и-вызовами-роль-set-add-remove) · [Концы: из пути цепочки и вызовами .Роль.set(), .add(), .remove()](../write/#концы-из-пути-цепочки-и-вызовами-роль-set-add-remove)
