# MCP: letopis/mcp

Сервер MCP даёт ИИ-агенту инструменты letopis от имени одного пользователя: права и арендатор — его сессии.

**Что здесь:** [Сервер](#сервер) · [Инструменты](#инструменты). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Сервер

### createMcpServer() {#mcp-createmcpserver}

```ts
createMcpServer(db: DbCore, opts?: McpOptions): Promise<McpServer>
```

**Импорт:** `import { createMcpServer } from 'letopis/mcp'`

Сервер MCP для одного пользователя letopis: инструменты `letopis_model`, `letopis_query`, `letopis_history`, а с `{ write: true }` — ещё `letopis_write`. Подключение — сессия пользователя (`connect({ token })`) или фасад `db.as(пользователь)`. Транспорт выбирает приложение: `server.connect(транспорт)`, `serveStdio(() => createMcpServer(db))` или обработчик HTTP `createMcpHandler(() => createMcpServer(db))` из SDK; токен запроса HTTP проверяет приложение.

Сервер работает только с правами одного пользователя, поэтому подключение проверяется сразу, одним запросом к базе. Сервис может отдать агенту `db.as(пользователь)`: агент получает права пользователя, а ключ сервиса остаётся в процессе приложения. `serveStdio` и `createMcpHandler` — функции пакета `@modelcontextprotocol/server`: они вызывают фабрику на каждое соединение или каждый запрос HTTP, поэтому проверка подключения повторяется каждый раз. Встроенного HTTP-сервера нет: по токену запроса приложение само выбирает пользователя letopis. Пакет `@modelcontextprotocol/server` нужно установить отдельно: без него функция бросает ошибку с командой установки `npm i @modelcontextprotocol/server`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `db` | `DbCore` | обязательный | Подключение, от имени которого работает агент: `connect({ token })` с токеном сессии пользователя или `db.as(пользователь)`. |
| `opts` | `McpOptions` | `{}` | Опции сервера: запись, пределы ответа, доступ к классам прав и к арендатору System (таблица ниже). |

**Опции `McpOptions`**

| Опция | Тип | По умолчанию | Описание |
|---|---|---|---|
| <span id="mcpopt-write"></span>`write` | `boolean` | `false` | Инструмент letopis_write (create, update, upsert, delete); по умолчанию сервер только читает.<br>Примеры: [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет) |
| <span id="mcpopt-maxrows"></span>`maxRows` | `number` | `100` | Предел строк в одном ответе (по умолчанию 100). Остальные строки `letopis_query` отдаёт на следующих страницах по курсору, а версии и группы `countBy` сверх предела обрезаются с пометкой `more` или `truncated`. Целое от 1 до 10 000; иное значение — отказ `invalid_data` при создании сервера.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-maxbytes"></span>`maxBytes` | `number` | `50000` | Предел размера строк одного ответа в байтах JSON (по умолчанию 50 000); что не поместилось — так же, как сверх `maxRows`. Описание модели больше предела `letopis_model` отдаёт кратким. Целое от 1 000 до 50 000 000; иное значение — отказ `invalid_data` при создании сервера. Строка, которая сама больше предела, приходит на странице одна.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-allowaclwrite"></span>`allowAclWrite` | `boolean` | `false` | Разрешить `letopis_write` писать и классы прав — `rule`, `Resource`, `member`, `Account`, `Class` и их потомков (правила, ресурсы, членства, аккаунты, описания классов). По умолчанию — отказ `acl_denied`: агент, которому в данных подсунули чужие инструкции, мог бы без подтверждения человека выдать постороннему членство или право.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-allowsystemadmin"></span>`allowSystemAdmin` | `boolean` | `false` | Принять сессию в арендаторе System, то есть сессию системного администратора: с `true` агент получает его права на аккаунты, членства, правила и `letopis.*`, но писать классы прав по-прежнему может только с `allowAclWrite`. По умолчанию такая сессия — отказ `user_session_required`.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |

**Возвращает:** `Promise<McpServer>` — Сервер MCP пакета `@modelcontextprotocol/server`, ещё не подключённый к транспорту.

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — неизвестная опция (похожие имена — в `err.params.similar`); `maxRows` или `maxBytes` — не целое число в допустимых пределах; `write`, `allowAclWrite` или `allowSystemAdmin` — не `true` и не `false`; `db` получен не из `connect()` и не из `db.as()`.
- `bypass_rls` — подключение обходит RLS и видит данные всех арендаторов (администраторское подключение).
- `user_session_required` — у подключения нет сессии пользователя; это подключение сервиса без `as()`; сессия работает в арендаторе System, а `allowSystemAdmin` не задан.
- `invalid_query` — `db` — явная транзакция `db.begin()`.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

## Инструменты

### letopis_model {#mcptool-letopis-model}

```ts
letopis_model({ class? })
```

Описание модели данных, доступной пользователю: классы, поля (JSON Schema), условия `anyOf` и `oneOf`, концы, ключи, алиасы, наследование, метаданные и рабочие цепочки `examples`. Классы — из реестра подключения (`db.registry`): арендатора сессии и System. Только читает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | все классы | Имя или алиас класса: тогда ответ — подробное описание только этого класса. |

**Возвращает:** В `structuredContent.data` — `{ schema, tenant, classes }`. Если такое описание больше `maxBytes`, оно приходит сначала без `examples`, а если и так не помещается — краткое: `brief: true`, а у каждого класса — только имя, вид, алиас, родитель, признак системного класса, ключ и имена полей и концов. С `class` — `{ schema, tenant, class }`.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — класса с таким именем или алиасом нет; в `similar` — похожие имена.
- `invalid_query` — неизвестный параметр или `class` — не строка.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_query {#mcptool-letopis-query}

```ts
letopis_query({ class, id?, ids?, filter?, steps?, asOf?, withDeleted?, sort?, limit?, cursor?, terminal?, field? })
```

Чтение цепочкой, записанной в JSON, без SQL: старт с класса, переходы по связям, фильтры, срез на момент, сортировка, постраничный вывод, число строк и итоги по полю. Запрос `{ class: 'Product', filter: { price: { $lt: 1000 } }, steps: [{ step: 'Shop' }] }` — та же цепочка, что `db.Product({ price: lt(1000) }).Shop().rows()`. Только читает.

Фильтр — объект `{ поле: значение }`: значение означает равенство, вложенный объект — поля вложенного объекта, `{ Роль: id }` — цель конца. Операторы пишутся внутри поля, по одному на поле: `{ price: { $gt: 5 } }`; ключи и форма их значений — колонка MCP в таблице [операторов фильтров](./filters#операторы-фильтров). ИЛИ — `{ $or: [фильтр, …] }`: единственный ключ фильтра, не больше 64 условий. Каждый элемент `steps` — объект `{ step, id?, ids?, filter? }`, где `step` — роль, класс или алиас следующего шага; шагов не больше 16. У старта и у каждого шага задаётся что-то одно из `id`, `ids` и `filter`; без них шаг берёт все объекты. Пределы `maxRows` и `maxBytes` не ограничивают время запроса — для этого задайте `statement_timeout` роли базы.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | обязательный | Стартовый шаг: класс, алиас или роль. |
| `id` | `string` | нет | id объекта, с которого начать (uuid). |
| `ids` | `string[]` | нет | Список id объектов, с которых начать. |
| `filter` | `object` | все объекты класса | Фильтр стартового шага (как устроен — выше). |
| `steps` | `object[]` | нет | Переходы по связям по порядку: `[{ step, id?, ids?, filter? }]`, не больше 16. |
| `asOf` | `string` | сейчас | Срез на момент: данные такими, какими были тогда (строка ISO 8601). |
| `withDeleted` | `boolean` | `false` | `true` — последний шаг включает удалённые объекты (у них `$deleted`). |
| `sort` | `object` | по `id` | Порядок строк: `{ field, dir? }`, где `field` — `at`, `rev`, `id` или `data.<путь>`, а `dir` — `asc` или `desc` (по умолчанию `asc`). Только с терминалами `rows`, `first` и `ids`. |
| `limit` | `integer` | `maxRows` (100) | Сколько строк вернуть на странице, целое от 1; значение больше `maxRows` урезается до него. Только с `rows`, `first` и `ids`. |
| `cursor` | `string` | первая страница | `cursor` из прошлого ответа: следующая страница того же запроса с той же сортировкой. |
| `terminal` | `string` | `rows` | Что вернуть: `rows`, `first`, `ids`, `count`, `sum`, `avg`, `min`, `max` или `countBy`. |
| `field` | `string` | нет | Поле для `sum`, `avg`, `min`, `max` и `countBy`: `data.<путь>`. С этими терминалами обязательно, с остальными не задаётся. |

**Возвращает:** В `structuredContent.data` — ответ, форма которого зависит от терминала: `rows` — `{ rows, count, more, cursor? }`, `ids` — `{ ids, count, more, cursor? }`, `first` — `{ row }` (строка или `null`), `count` — `{ count }`, `countBy` — `{ counts, truncated? }` (самые частые значения), `sum`, `avg`, `min` и `max` — `{ value }`. У `rows` и `ids` `count` — число строк на этой странице, а не всего; `more: true` — есть ещё строки: передайте `cursor` в следующий вызов.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — неизвестный параметр или оператор, значение не того вида, сразу несколько из `id`, `ids` и `filter`, больше 16 шагов или 64 условий `$or`, `sort`, `limit` или `cursor` не с тем терминалом, курсор от запроса с другой сортировкой.
- `invalid_class` — класса, алиаса или роли с таким именем нет; в `similar` — похожие имена.
- `no_path` — между классами соседних шагов нет перехода по связи.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_history {#mcptool-letopis-history}

```ts
letopis_history({ class, id, kind? })
```

Версии одного объекта — с автором, временем, видом операции и причиной. Только читает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | обязательный | Класс или алиас объекта. |
| `id` | `string` | обязательный | id объекта (uuid). |
| `kind` | `string` | `versions` | Что показать: только `versions` — версии объекта. |

**Возвращает:** В `structuredContent.data` — `{ versions, more }`: последние версии, сколько поместится в пределы ответа (`maxRows`, `maxBytes`), от старой к новой; `more: true` — есть более старые.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — неизвестный параметр, `id` — не uuid, `kind` — не `versions` (в `similar` — похожие значения).
- `invalid_class` — класса или алиаса с таким именем нет; в `similar` — похожие имена.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_write {#mcptool-letopis-write}

```ts
letopis_write({ op, class, id?, ids?, data?, links?, rev?, confirm?, operation? })
```

Запись от имени пользователя: создать, изменить, создать или заменить по ключу, удалить. Инструмент есть, только если сервер создан с `write: true` (`letopis mcp --write`). Причина каждой записи в журнале — `mcp: letopis_write`.

`create` и `upsert` принимают `data` и `links`; `update` — `id`, `rev` и `data` или `links` (`data` — патч: он сливается с текущими данными); `delete` — `id` или `ids`, а также `confirm` и `operation`. Удаление идёт в два шага. Без `confirm` — только предпросмотр удаления: ответ показывает, что удалится вместе с целями, и код операции. С `confirm: true` клиент MCP спрашивает подтверждение у человека, затем предпросмотр повторяется, и удаление идёт с ним одной транзакцией: удаляется ровно то, что подтверждено. В ревизии протокола 2026-07-28 ответ человека принимается в течение 10 минут. Классы прав (`rule`, `Resource`, `member`, `Account`, `Class` и их потомки) инструмент без `allowAclWrite` не пишет, не правит и не удаляет.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `op` | `string` | обязательный | Операция: `create`, `update`, `upsert` или `delete`. |
| `class` | `string` | обязательный | Класс или алиас. |
| `id` | `string` | нет | `update` и `delete`: id объекта (uuid). |
| `ids` | `string[]` | нет | `delete`: список id объектов, если удалять несколько. |
| `data` | `object` | `{}` | `create` и `upsert` — данные объекта, `update` — патч: изменённые поля. |
| `links` | `object` | нет | Концы: `{ Роль: id \| [id] \| null }`; `null` очищает конец. |
| `rev` | `integer` | нет | `update`: номер версии, которую агент прочитал; обязателен для `update`. Если объект успели изменить — отказ `conflict`, а не потерянная правка. |
| `confirm` | `boolean` | `false` | `delete`: `true` — удалить после подтверждения человеком в клиенте MCP. |
| `operation` | `string` | нет | `delete`: код операции из предпросмотра. Если данные изменились и код не совпадает — отказ. Подтверждением код не считается. |

**Возвращает:** В `structuredContent.data`: `create`, `update` и `upsert` — `{ rows }`, записанные строки; `delete` без `confirm` — `{ preview, operation, confirm }`: строки предпросмотра с `$action`, код операции и подсказка, как подтвердить удаление; после подтверждения — `{ deleted, operation }`. В ревизии протокола 2026-07-28 первый вызов с `confirm: true` отвечает запросом подтверждения (`input_required`), и клиент повторяет вызов с ответом человека.

**Ошибки** ([все коды](../errors/)):

- `acl_denied` — класс прав без `allowAclWrite` или запись запрещают права пользователя.
- `invalid_query` — неизвестный параметр или `op`, параметр не для этой операции, `update` без `rev`, `id` не uuid, `delete` без `id` и `ids` или сразу с обоими.
- `invalid_class` — класса, алиаса или роли в `links` нет; в `similar` — похожие имена.
- `invalid_data` — данные не проходят описание класса.
- `exists` — `create`: объект с таким ключом уже есть.
- `no_key` — `upsert` у класса без ключа.
- `conflict` — `update`: объект изменили после версии `rev`.
- `confirmation_required` — удаление не подтверждено: клиент не умеет спрашивать человека, человек отказал, подтверждение устарело или относится к другой операции, данные изменились после предпросмотра.
- `target_not_found` — `delete` с `confirm`: целей не видно — удалять нечего.
- `delete_restricted` — `delete` с `confirm`: удалению мешают ссылающиеся строки (`$action: restrict` в предпросмотре).

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)
