# MCP: letopis/mcp

Сервер MCP даёт ИИ-агенту инструменты letopis от имени одного пользователя: права и арендатор — его сессии.

## Сервер

### createMcpServer() {#mcp-createmcpserver}

```ts
createMcpServer(db: Db, opts?: McpOptions): Promise<McpServer>
```

Сервер MCP для одного пользователя letopis: инструменты letopis_model, letopis_query, letopis_history и при { write: true } — letopis_write. Подключение — сессия пользователя (connect({ token })) или фасад db.as(пользователь). Транспорт выбирает приложение: server.connect(транспорт), serveStdio(() =&gt; createMcpServer(db)) или createMcpHandler(() =&gt; createMcpServer(db)) SDK — со своей авторизацией.

Сервер работает только с правами одного пользователя, поэтому подключение проверяется сразу, одним запросом к базе. Подходит подключение `connect({ token })` с токеном сессии пользователя или подключение `db.as(пользователь)`, которое сервис открывает от имени пользователя: ключ сервиса при этом остаётся в процессе приложения. Отказ получают подключение в обход RLS, подключение сервиса без `as()`, подключение без сессии, транзакция `db.begin()` и, без `allowSystemAdmin`, сессия в арендаторе System. `serveStdio` и `createMcpHandler` — функции пакета `@modelcontextprotocol/server`: они вызывают фабрику на каждое соединение или каждый запрос HTTP, поэтому проверка подключения повторяется каждый раз. Пакет `@modelcontextprotocol/server` нужно установить отдельно: без него функция бросает ошибку с командой установки `npm i @modelcontextprotocol/server`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `db` | `Db` | обязательный | Подключение, от имени которого работает агент: `connect({ token })` с токеном сессии пользователя или `db.as(пользователь)`. |
| `opts` | `McpOptions` | `{}` | Опции сервера: запись, пределы ответа, доступ к классам прав и к арендатору System (таблица ниже). |

**Опции `McpOptions`**

| Опция | Тип | По умолчанию | Описание |
|---|---|---|---|
| <span id="mcpopt-write"></span>`write` | `boolean` | `false` | Инструмент letopis_write (create, update, upsert, delete); по умолчанию сервер только читает.<br>Примеры: [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет) |
| <span id="mcpopt-maxrows"></span>`maxRows` | `number` | `100` | Строк в ответе не больше (по умолчанию 100); дальше — курсор. Целое от 1 до 10 000; иное значение — отказ `invalid_data` при создании сервера.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-maxbytes"></span>`maxBytes` | `number` | `50000` | Байт JSON строк в ответе не больше (по умолчанию 50 000); дальше — курсор. Целое от 1 000 до 50 000 000; иное значение — отказ `invalid_data` при создании сервера. Строка, которая сама больше предела, приходит на странице одна.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-allowaclwrite"></span>`allowAclWrite` | `boolean` | `false` | letopis_write пишет и классы прав — rule, Resource, member, Account, Class и их потомков (правила, членства, описания классов). По умолчанию — отказ acl_denied: агент под инъекцией в данных выдал бы постороннему членство или правило без подтверждения человека.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |
| <span id="mcpopt-allowsystemadmin"></span>`allowSystemAdmin` | `boolean` | `false` | Сессия в арендаторе System — так работает системный администратор: его роль admin даёт права на аккаунты, членства, правила и letopis.\*. По умолчанию — отказ user_session_required.<br>Примеры: [Опции сервера MCP: лимиты ответа и доступ к классам прав](../mcp/#опции-сервера) |

**Возвращает:** `Promise<McpServer>` — Сервер MCP из пакета `@modelcontextprotocol/server` с инструментами `letopis_model`, `letopis_query`, `letopis_history` и, при `write: true`, `letopis_write`. К транспорту сервер ещё не подключён: это делает приложение.

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — `maxRows` или `maxBytes` — не целое число в допустимых пределах, флаг — не `true` и не `false`; или `db` получен не из `connect()` и не из `db.as()`.
- `bypass_rls` — подключение обходит RLS и видит данные всех арендаторов (администраторское подключение).
- `user_session_required` — у подключения нет сессии пользователя; это подключение сервиса без `as()`; сессия работает в арендаторе System, а `allowSystemAdmin` не задан.
- `invalid_query` — `db` — явная транзакция `db.begin()`.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

## Инструменты

### letopis_model {#mcptool-letopis-model}

```ts
letopis_model({ class? })
```

Описание модели данных, доступной пользователю: классы, поля (JSON Schema), условия `anyOf` и `oneOf`, концы, ключи, алиасы, наследование и метаданные. Те же классы, что отдаёт `db.describe()`. Только читает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | все классы | Имя или алиас класса: тогда ответ — подробное описание только этого класса. |

**Возвращает:** В `structuredContent.data` — `{ schema, tenant, classes }`. Если такое описание больше `maxBytes`, приходит краткое: `brief: true`, а у каждого класса — только имя, вид, алиас, родитель, ключ и имена полей и концов. С `class` — `{ schema, tenant, class }`.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — класса с таким именем или алиасом нет; в `similar` — похожие имена.
- `invalid_query` — неизвестный параметр или `class` — не строка.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_query {#mcptool-letopis-query}

```ts
letopis_query({ class, id?, ids?, filter?, steps?, asOf?, withDeleted?, sort?, limit?, cursor?, terminal?, field? })
```

Чтение цепочкой, записанной в JSON, без SQL: старт с класса, переходы по связям, фильтры, срез на момент, сортировка, постраничный вывод и агрегаты. Запрос `{ class: 'Product', filter: { price: { $lt: 1000 } }, steps: [{ step: 'Shop' }] }` — та же цепочка, что `db.Product({ price: lt(1000) }).Shop().rows()`. Только читает.

Фильтр — объект `{ поле: значение }`: значение означает равенство, вложенный объект — поля вложенного объекта, `{ Роль: id }` — ссылку. Операторы пишутся внутри поля, по одному на поле: `{ price: { $gt: 5 } }`. Есть операторы `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$between` (`[от, до]`), `$in` (список), `$like`, `$ilike`, `$starts`, `$ends`, `$has`, `$hasAny` и `$hasAll` (список), `$exists` (`true` или `false`), `$isNull` (`true`) и `$not`. ИЛИ — `{ $or: [фильтр, …] }`: единственный ключ фильтра, не больше 64 условий. Шаг `steps` — объект `{ step, id?, ids?, filter? }`: `step` — роль или класс, следующий переход по связи; шагов не больше 16. У старта и у каждого шага задаётся что-то одно из `id`, `ids` и `filter`; без них шаг берёт все объекты. Время запроса пределы не ограничивают — задайте `statement_timeout` роли базы.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | обязательный | Стартовый шаг: класс, алиас или роль. |
| `id` | `string` | нет | id объекта, с которого начать (uuid). |
| `ids` | `string[]` | нет | Список id объектов, с которых начать. |
| `filter` | `object` | все объекты класса | Фильтр стартового шага (как устроен — выше). |
| `steps` | `object[]` | нет | Переходы по связям по порядку: `[{ step, id?, ids?, filter? }]`, не больше 16. |
| `asOf` | `string` | сейчас | Срез на момент: данные такими, какими были тогда (строка ISO 8601). |
| `withDeleted` | `boolean` | `false` | `true` — последний шаг включает удалённые объекты (у них `$deleted`). |
| `sort` | `object` | по `id` | Порядок строк: `{ field, dir? }`, где `field` — `at`, `rev`, `id` или `data.<путь>`, а `dir` — `asc` или `desc` (по умолчанию `asc`). Только с терминалами `rows`, `first` и `ids`. |
| `limit` | `integer` | `maxRows` (100) | Сколько строк вернуть на странице: целое от 1, но не больше `maxRows`. Только с `rows`, `first` и `ids`. |
| `cursor` | `string` | первая страница | `cursor` из прошлого ответа: следующая страница того же запроса с той же сортировкой. |
| `terminal` | `string` | `rows` | Что вернуть: `rows`, `first`, `ids`, `count`, `sum`, `avg`, `min`, `max` или `countBy`. |
| `field` | `string` | нет | Поле для `sum`, `avg`, `min`, `max` и `countBy`: `data.<путь>`. С этими терминалами обязательно, с остальными не задаётся. |

**Возвращает:** В `structuredContent.data` — ответ, форма которого зависит от терминала: `rows` — `{ rows, count, more, cursor? }`, `ids` — `{ ids, count, more, cursor? }`, `first` — `{ row }` (строка или `null`), `count` — `{ count }`, `countBy` — `{ counts, truncated? }` (самые частые значения), `sum`, `avg`, `min` и `max` — `{ value }`. У `rows` и `ids` `count` — число строк на этой странице; `more: true` — есть ещё строки, и `cursor` отдаёт следующую страницу.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — неизвестный параметр или оператор, значение не того вида, сразу несколько из `id`, `ids` и `filter`, больше 16 шагов или 64 условий `$or`, `sort`, `limit` или `cursor` не с тем терминалом, курсор от запроса с другой сортировкой.
- `invalid_class` — класса, алиаса или роли с таким именем нет; в `similar` — похожие имена.
- `no_path` — между классами соседних шагов нет перехода по связи.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_history {#mcptool-letopis-history}

```ts
letopis_history({ class, id, kind, from?, to?, at?, follow?, limit? })
```

История одного объекта: его версии, что изменилось между версиями (`diff`) или кто, когда и почему последним менял каждое поле (`blame`). Только читает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `class` | `string` | обязательный | Класс или алиас объекта. |
| `id` | `string` | обязательный | id объекта (uuid). |
| `kind` | `string` | обязательный | Что показать: `versions` — версии, `diff` — изменения, `blame` — авторов полей. |
| `from` | `integer \| string` | предыдущая версия | Только `diff`: начало сравнения — номер версии или момент ISO. |
| `to` | `integer \| string` | текущая версия | Только `diff`: конец сравнения — номер версии или момент ISO. |
| `at` | `string` | текущая версия | Только `blame`: на какой момент смотреть (ISO). |
| `follow` | `boolean` | `false` | `true` — продолжать историю через смену id (`reclass`, `rekey`). Только `versions` и `diff`. |
| `limit` | `integer` | `1000` | Только `blame`: сколько последних версий просмотреть, целое от 1. |

**Возвращает:** В `structuredContent.data`: `versions` — `{ versions, more }`, последние версии в пределах ответа, от старой к новой (`more: true` — есть более старые); `diff` — `{ diff }`; `blame` — `{ blame }`. Если изменения или поля не поместились в пределы ответа, в нём есть `truncated: true` и `total`.

**Ошибки** ([все коды](../errors/)):

- `invalid_query` — неизвестный параметр, `id` — не uuid, `kind` не из списка, параметр не для этого `kind`, `follow` с `blame`.
- `invalid_class` — класса или алиаса с таким именем нет; в `similar` — похожие имена.

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)

### letopis_write {#mcptool-letopis-write}

```ts
letopis_write({ op, class, id?, ids?, data?, links?, rev?, confirm?, operation? })
```

Запись от имени пользователя: создать, изменить, создать или заменить по ключу, удалить. Инструмент есть, только если сервер создан с `write: true` (`letopis mcp --write`). Причина каждой записи в журнале — `mcp: letopis_write`.

Что передавать для каждой операции. `create` и `upsert` — `data` и `links`. `update` — `id`, `rev` и `data` или `links`: `data` — патч, он сливается с текущими данными. `delete` — `id` или `ids`, `confirm` и `operation`. Параметр не для своей операции — отказ `invalid_query`. Удаление идёт в два шага. Без `confirm` ничего не удаляется: ответ показывает, что удалится вместе с целями, и код операции. С `confirm: true` клиент MCP спрашивает подтверждение у человека, а превью и удаление повторяются одной транзакцией: удаляется ровно то, что подтверждено. Подтверждение действует 10 минут. Клиент, который не умеет спрашивать человека, получает отказ. Классы прав (`rule`, `Resource`, `member`, `Account`, `Class` и их потомки) инструмент без `allowAclWrite` не пишет, не правит и не удаляет.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `op` | `string` | обязательный | Операция: `create`, `update`, `upsert` или `delete`. |
| `class` | `string` | обязательный | Класс или алиас. |
| `id` | `string` | нет | `update` и `delete`: id объекта (uuid). |
| `ids` | `string[]` | нет | `delete`: список id объектов, если удалять несколько. |
| `data` | `object` | `{}` | `create` и `upsert` — данные объекта, `update` — патч: изменённые поля. |
| `links` | `object` | нет | Ссылки: `{ Роль: id \| [id] \| null }`; `null` снимает ссылку. |
| `rev` | `integer` | нет | `update`: номер версии, которую агент прочитал; обязателен для `update`. Если объект успели изменить — отказ `conflict`, а не потерянная правка. |
| `confirm` | `boolean` | `false` | `delete`: `true` — удалить после подтверждения человеком в клиенте MCP. |
| `operation` | `string` | нет | `delete`: код операции из превью. Если данные изменились и код не совпадает — отказ. Подтверждением код не считается. |

**Возвращает:** В `structuredContent.data`: `create`, `update` и `upsert` — `{ rows }`, записанные строки; `delete` без `confirm` — `{ preview, operation, confirm }`: строки превью с `$action` и код операции; после подтверждения — `{ deleted, operation }`. В ревизии протокола 2026-07-28 первый вызов с `confirm: true` отвечает запросом подтверждения (`input_required`), и клиент повторяет вызов с ответом человека.

**Ошибки** ([все коды](../errors/)):

- `acl_denied` — класс прав без `allowAclWrite` или запись запрещают права пользователя.
- `invalid_query` — неизвестный параметр или `op`, параметр не для этой операции, `update` без `rev`, `id` не uuid, `delete` без `id` и `ids`.
- `invalid_class` — класса, алиаса или роли в `links` нет; в `similar` — похожие имена.
- `invalid_data` — данные не проходят описание класса.
- `exists` — `create`: объект с таким ключом уже есть.
- `no_key` — `upsert` у класса без ключа.
- `conflict` — `update`: объект изменили после версии `rev`.
- `confirmation_required` — удаление не подтверждено: клиент не умеет спрашивать человека, человек отказал, подтверждение устарело или относится к другой операции, данные изменились после превью.
- `target_not_found` — `delete` с `confirm`: целей не видно — удалять нечего.
- `delete_restricted` — `delete` с `confirm`: удалению мешают ссылающиеся строки (`$action: restrict` в превью).

**Примеры:** [ИИ-агент через MCP: модель, чтение, история, запись с проверкой версии](../mcp/#пример-агент-читает-и-пишет)
