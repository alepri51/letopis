# Командная строка

Команда `letopis` ставится вместе с пакетом. Служебные команды `sync`, `types`, `load` и `maintain` работают мастер-ключом (обслуживание без мастер-ключа — `db.maintain()` консьержа): `--dsn` — строка подключения администратора PostgreSQL, `--schema` — имя дома из `setup()` (`shop` — это `v2.shop`). `letopis mcp` — сервер MCP для ИИ-агента: пропуск консьержа и ключ API жильца. У любой команды есть `--log[=уровень]` — события JSON-строками в stderr: `debug`, `info`, `warn`, `error` или `off`, без значения — `info`; без флага действует переменная `LETOPIS_LOG`. Загрузка `letopis load` — на странице [Загрузка](./load).

**Что здесь:** [Команды](#команды). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Команды

### letopis sync {#cli-sync}

```sh
letopis sync <модуль> --dsn <мастер-ключ> --schema <дом> [--apply | --check]
```

Сравнивает модели из модуля с общими классами дома и, с `--apply`, записывает их — так же, как `setup(…, { models })`: классы пишет консьерж в System, их видят все квартиры. Берутся модели `hub()` и `link()` среди экспортов модуля (и элементов экспортированных массивов). Без `--apply` это сухой прогон: изменения выполняются и откатываются, поэтому ошибки базы видны уже в нём.

Пропуск консьержа команда читает из базы мастер-ключом сама. Неизвестный флаг любая команда отклоняет до подключения к базе: в stderr «неизвестный флаг --aply; см. letopis --help» и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `<модуль>` | `аргумент` | обязательный | Путь к модулю JavaScript или TypeScript с моделями; относительный путь — от текущего каталога. |
| `--dsn` | `<мастер-ключ>` | обязательный | Мастер-ключ — строка подключения администратора PostgreSQL. |
| `--schema` | `<дом>` | обязательный | Имя дома из `setup()`: `shop` (или полное `v2.shop`). |
| `--apply` | `флаг` | сухой прогон | Записать изменения; без флага — только сухой прогон. |
| `--check` | `флаг` | нет | Сухой прогон с кодом выхода 1, если модели расходятся с базой (есть что создать или изменить), — шаг CI перед `--apply`. Вместе с `--apply` — подсказка по командам и код 2. |

**Возвращает:** Печатает итог строкой «сухой прогон: создать N, изменить N, без изменений N, системных N» (с `--apply` — «применено: …»), затем имена классов по группам и правила Zod `refine`, которых нет в базе: их проверяет только библиотека. Код выхода 0; с `--check` — 1, если есть что создать или изменить. Без модуля, `--dsn` или `--schema` — подсказка по командам и код 2, при ошибке — её текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — в модели преобразование Zod (`.trim()`, `.transform()` и подобные), модели зависят друг от друга по кругу или база отклонила описание класса.
- `tightening_conflict` — новому, более строгому описанию мешают существующие строки.
- `invalid_data` — дома нет или у него нет пропуска консьержа (`boot.no_pass`): дом строит `setup()`.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis types {#cli-types}

```sh
letopis types --dsn <мастер-ключ> --schema <дом> [--out <файл>] [--system]
```

Печатает объявления TypeScript по общим классам дома: для каждого класса — интерфейсы `<Класс>Data` (поля) и `<Класс>Links` (концы) и `<Класс>Model` (имя, алиас, концы с классами целей и предки), а в конце — список `Models`. С ним `connect<Models>(pass)` даёт корни квартир со строгими типами цепочек и без моделей Zod. Системные классы движка — только с `--system`; без флага строгим типам их даёт встроенный набор `SystemModels`.

Неизвестный флаг любая команда отклоняет до подключения к базе: в stderr «неизвестный флаг --aply; см. letopis --help» и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--dsn` | `<мастер-ключ>` | обязательный | Мастер-ключ — строка подключения администратора PostgreSQL. |
| `--schema` | `<дом>` | обязательный | Имя дома из `setup()`: `shop` (или полное `v2.shop`). |
| `--out` | `<файл>` | вывод в терминал | Файл, в который записать объявления. |
| `--system` | `флаг` | нет: только классы дома | Добавить системные классы движка: `Account`, `Class`, `member`, `Resource`, `rule`. |

**Возвращает:** Текст объявлений — в терминал или в файл `--out`; код выхода 0. При ошибке — её текст в stderr и код 1, а файл `--out` не трогается.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — имя класса не годится для идентификатора TypeScript.
- `invalid_data` — имя дома неверного вида или такого дома нет.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis maintain {#cli-maintain}

```sh
letopis maintain --dsn <мастер-ключ> --schema <дом>
```

Обслуживание дома мастер-ключом: одной транзакцией удаляет истёкшие и погашенные сессии, одноразовые коды и приглашения, которые больше не действуют, строки-замки удалённых классов и проверяет заполнение очереди сигналов. Журнал не трогает. Команду запускают по расписанию внешним планировщиком (cron и т. п.).

Из нескольких процессов работает один: если обслуживание уже идёт в другом процессе, команда ничего не делает и отвечает `skipped: true`. Неизвестный флаг любая команда отклоняет до подключения к базе: в stderr «неизвестный флаг --aply; см. letopis --help» и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--dsn` | `<мастер-ключ>` | обязательный | Мастер-ключ — строка подключения администратора PostgreSQL. |
| `--schema` | `<дом>` | обязательный | Имя дома из `setup()`: `shop` (или полное `v2.shop`). |

**Возвращает:** Печатает отчёт одной строкой JSON: `{ skipped, sessions, codes, queue }` — удалено сессий, удалено кодов и приглашений, заполнение очереди сигналов PostgreSQL от 0 до 1 (больше половины — предупреждение в stderr). Код выхода 0; при ошибке — её текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — имя дома неверного вида или такого дома нет.

**Примеры:** [Обслуживание: letopis maintain убирает погашенные сессии, коды и истёкшие приглашения](../ops/#обслуживание-letopis-maintain) · [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка) · [Курсор подписки не устаревает](../watch/#пример-курсор-подписки-не-устаревает)

### letopis mcp {#cli-mcp}

```sh
letopis mcp --pass <пропуск> --api-key <ключ жильца> [--write]
  (или LETOPIS_PASS и LETOPIS_KEY; агент работает только как жилец)
```

Сервер MCP по stdio для клиентов MCP (Claude Desktop, Claude Code, Cursor) от имени одного жильца — тот же сервер, что `createMcpServer()`. Нужен пакет `@modelcontextprotocol/server`. Пропуск консьержа и ключ API жильца клиент передаёт флагами или переменными окружения `LETOPIS_PASS` и `LETOPIS_KEY`; флаг важнее переменной.

Команда открывает дом пропуском и входит ключом жильца (`db.open({ apiKey })`): агент получает права жильца в его квартире, полного доступа консьержа у него нет. Вход проверяется до начала протокола: при отказе процесс сразу завершается. В stdout идёт только протокол MCP, журнал `--log` — в stderr. Опций `allowAclWrite`, `maxRows` и `maxBytes` у команды нет: классы прав она не пишет. Неизвестный флаг любая команда отклоняет до подключения к базе: в stderr «неизвестный флаг --aply; см. letopis --help» и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--pass` | `<пропуск>` | обязательный — флагом или переменной окружения | Пропуск консьержа — строка из `setup()` (или переменная `LETOPIS_PASS`). |
| `--api-key` | `<ключ жильца>` | обязательный — флагом или переменной окружения | Ключ API жильца — из `me.keys.issueApiKey()` (или переменная `LETOPIS_KEY`). |
| `--write` | `флаг` | только чтение | Включить инструмент записи `letopis_write`. |

**Возвращает:** Обслуживает клиента по stdio и завершается с кодом 0, когда клиент закрывает stdin. Без пропуска или ключа — текст причины в stderr и код 2; ключ не подошёл или пропуск устарел — текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `auth_failed` — ключ API не подошёл — неверный, отозван, просрочен или жилец выписан (`api.auth_failed`); пропуск устарел (`boot.pass_stale`).
- `invalid_data` — строка — не пропуск консьержа (`boot.pass_invalid`).

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)
