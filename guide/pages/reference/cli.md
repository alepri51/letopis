# Командная строка

Команда `letopis` ставится вместе с пакетом. Подключение — `--dsn` и `--schema`, вход — `--token` (токен сессии) или `--api-key` (ключ API); `letopis mcp` принимает только `--token`.

**Что здесь:** [Команды](#команды). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и ссылки на живые примеры сайта.

## Команды

### letopis sync {#cli-sync}

```sh
letopis sync <модуль> --dsn <строка> --schema <v2.имя> (--token <токен> | --api-key <ключ>) [--apply | --check]
```

Сравнивает модели из модуля с описаниями классов в базе и, с `--apply`, записывает их. Модели — все экспорты модуля (и элементы экспортированных массивов), у которых есть `describe()` и имя. Без `--apply` это сухой прогон: изменения выполняются и откатываются, поэтому ошибки базы видны уже в нём.

Неизвестный флаг любая команда отклоняет до подключения к базе: текст ошибки в stderr и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `<модуль>` | `аргумент` | обязательный | Путь к модулю JavaScript или TypeScript с моделями; относительный путь — от текущего каталога. |
| `--dsn` | `<строка>` | обязательный | Строка подключения PostgreSQL. Подходит и роль приложения, и администраторская роль. |
| `--schema` | `<v2.имя>` | обязательный | Схема установки: полное имя вида `v2.shop`. |
| `--token` | `<токен>` | обязательный | Токен сессии пользователя или сервиса: классы пишутся в его арендатора. Нужен он или `--api-key`. |
| `--api-key` | `<ключ>` | обязательный | Ключ API сервиса вместо токена: команда входит по нему сама. |
| `--apply` | `флаг` | сухой прогон | Записать изменения; без флага — только сухой прогон. |
| `--check` | `флаг` | нет | Сухой прогон с кодом выхода 1, если модели расходятся с базой (есть что создать или изменить), — шаг CI перед `--apply`. Вместе с `--apply` — подсказка по командам и код 2. |

**Возвращает:** Печатает итог строкой «сухой прогон: создать N, изменить N, без изменений N, системных N» (с `--apply` — «применено: …»), затем имена классов по группам и правила Zod `refine`, которых нет в базе: их проверяет только библиотека. Код выхода 0; с `--check` — 1, если есть что создать или изменить. Без модуля, `--dsn` или `--schema` — подсказка по командам и код 2, при ошибке — её текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — в модели преобразование Zod (`.trim()`, `.transform()` и подобные), модели зависят друг от друга по кругу или база отклонила описание класса.
- `tightening_conflict` — новому, более строгому описанию мешают существующие строки.
- `no_session` — нет действующей сессии: не задан или устарел токен, неверный ключ API.
- `acl_denied` — у пользователя нет права записывать описания классов.
- `invalid_data` — имя схемы — не вида `v<N>.<имя>` или такой схемы нет в базе.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis types {#cli-types}

```sh
letopis types --dsn <строка> --schema <v2.имя> (--token <токен> | --api-key <ключ>) [--out <файл>] [--system]
```

Печатает объявления TypeScript по модели из базы: для каждого класса арендатора сессии — интерфейсы `<Класс>Data` (поля) и `<Класс>Links` (концы) и `<Класс>Model` (имя, алиас, концы с классами целей и предки), а в конце — список `Models`. С ним `connect<Models>({ … })` даёт строгие типы цепочек и без моделей Zod. Классы арендатора System — системные и классы сидов пакета, например `booking`, — только с `--system`; без флага системные классы строгим типам даёт встроенный набор `SystemModels`.

Неизвестный флаг любая команда отклоняет до подключения к базе: текст ошибки в stderr и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--dsn` | `<строка>` | обязательный | Строка подключения PostgreSQL роли приложения: администраторскую роль команда не принимает. |
| `--schema` | `<v2.имя>` | обязательный | Схема установки: полное имя вида `v2.shop`. |
| `--token` | `<токен>` | обязательный | Токен сессии: типы строятся по классам, видимым этой сессии. Нужен он или `--api-key`. |
| `--api-key` | `<ключ>` | обязательный | Ключ API сервиса вместо токена. |
| `--out` | `<файл>` | вывод в терминал | Файл, в который записать объявления. |
| `--system` | `флаг` | нет: только классы арендатора сессии | Добавить классы арендатора System: системные (`Account`, `Class`, `member`, `Resource`, `rule`) и классы сидов пакета (например, `booking`). |

**Возвращает:** Текст объявлений — в терминал или в файл `--out`; код выхода 0. При ошибке — её текст в stderr и код 1, а файл `--out` не трогается.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — имя класса не годится для идентификатора TypeScript.
- `bypass_rls` — строка подключения — администраторская роль, которая обходит RLS.
- `no_session` — нет действующей сессии: токен истёк, погашен, неверен или не задан; ключ API неверен, отозван, отключён или истёк.
- `invalid_data` — имя схемы — не вида `v<N>.<имя>` или такой схемы нет в базе.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis load {#cli-load}

```sh
letopis load <файлы…> --dsn <строка> --schema <v2.имя> (--token <токен> | --api-key <ключ>) [--class <Класс>]
  [--duplicates error|first|last] [--existing error|skip|update] [--commit-every <N>] [--initial]
```

Массовая загрузка строк из файлов NDJSON — то же, что `db.load()`. Работает только с администраторской строкой подключения. Строки идут в арендатора сессии. Все файлы — одна загрузка и, без `--commit-every`, одна транзакция: ошибка в любой строке отменяет всё.

Неизвестный флаг любая команда отклоняет до подключения к базе: текст ошибки в stderr и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `<файлы…>` | `аргумент` | обязательный | Один или несколько файлов NDJSON в UTF-8: в каждой строке — объект JSON с полями, концами и служебными ключами (`$class`, `$ext`, `$tags`, `$owner`). Пустые строки пропускаются. |
| `--dsn` | `<строка>` | обязательный | Строка подключения администраторской роли: суперпользователь или роль, которая может стать владельцем схемы. |
| `--schema` | `<v2.имя>` | обязательный | Схема установки: полное имя вида `v2.shop`. |
| `--token` | `<токен>` | обязательный | Токен сессии: строки идут в её арендатора. Нужен он или `--api-key`. |
| `--api-key` | `<ключ>` | обязательный | Ключ API сервиса вместо токена. |
| `--class` | `<Класс>` | нет: класс — в `$class` строки | Класс для строк, у которых нет `$class`. |
| `--duplicates` | `error\|first\|last` | `error` | Повтор id внутри загрузки: `error` — отменить загрузку, `first` или `last` — оставить первую или последнюю строку. |
| `--existing` | `error\|skip\|update` | `error` | Объект уже есть в базе: `error` — отменить, `skip` — пропустить, `update` — записать новую версию, если содержимое отличается. |
| `--commit-every` | `<N>` | одна транзакция | Фиксировать порциями примерно по N строк; ошибка отменяет только текущую порцию. |
| `--initial` | `флаг` | нет | Первая заливка в пустую схему: быстрее, одной транзакцией. Несовместима с `--commit-every` и `--existing` (кроме `error`). |

**Возвращает:** Печатает отчёт одной строкой JSON: `{ rows, loaded, updated, skipped, duplicates, byClass, external, portions, ms }`; код выхода 0. При ошибке — её текст и список нарушений по строкам (`detail.rows`) в stderr, код 1. Строка файла, которая не разбирается как JSON, — тоже код 1.

**Ошибки** ([все коды](../errors/)):

- `admin_required` — строка подключения — не администраторская роль.
- `invalid_data` — данные строки не проходят описание класса; `--initial` вместе с `--commit-every` или `--existing`; нет арендатора — сессия не задана; имя схемы неверно или такой схемы нет.
- `not_empty` — `--initial`, а в схеме уже есть данные.
- `duplicate` — id повторяется в загрузке при `--duplicates error`.
- `exists` — объект уже есть в базе при `--existing error`.
- `deleted` — объект с этим id был раньше и удалён.
- `invalid_class` — класс строки не найден, абстрактный или у строки нет класса.
- `class_not_loadable` — строки `Class`: классы записывает `letopis sync`.
- `target_not_found` — цель конца или владелец не найдены.
- `no_session` — неверный ключ API.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis maintain {#cli-maintain}

```sh
letopis maintain --dsn <строка> --schema <v2.имя> [--token <токен> | --api-key <ключ>]
```

Обслуживание установки — то же, что `db.maintain()`: одной транзакцией удаляет истёкшие и погашенные сессии, одноразовые коды, которые больше не действуют, и строки-замки удалённых классов и проверяет заполнение очереди сигналов. Журнал не трогает. Команду запускают по расписанию внешним планировщиком (cron и т. п.).

Неизвестный флаг любая команда отклоняет до подключения к базе: текст ошибки в stderr и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--dsn` | `<строка>` | обязательный | Строка подключения. С администраторской ролью команда работает и без сессии. |
| `--schema` | `<v2.имя>` | обязательный | Схема установки: полное имя вида `v2.shop`. |
| `--token` | `<токен>` | нет | Токен сессии с правом `letopis.maintain`, если роль подключения не администраторская. |
| `--api-key` | `<ключ>` | нет | Ключ API вместо токена, с тем же правом. |

**Возвращает:** Печатает отчёт одной строкой JSON: `{ skipped, sessions, codes, queue }`; `skipped: true` — обслуживание уже идёт в другом процессе. Код выхода 0. Если очередь сигналов заполнена больше чем наполовину, в stderr — предупреждение. При ошибке — её текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `acl_denied` — роль подключения не администраторская, а у сессии нет права `letopis.maintain`.
- `no_session` — неверный ключ API.
- `invalid_data` — имя схемы — не вида `v<N>.<имя>` или такой схемы нет в базе.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)

### letopis mcp {#cli-mcp}

```sh
letopis mcp --dsn <строка> --schema <v2.имя> --token <токен пользователя> [--write]
  (или LETOPIS_DSN, LETOPIS_SCHEMA, LETOPIS_TOKEN; ключ сервиса --api-key не принимается)
у любой команды: --log[=debug|info|warn|error|off] — события JSON-строками в stderr (без значения — info)
```

Сервер MCP по stdio для клиентов MCP (Claude Desktop, Claude Code, Cursor) от имени одного пользователя — тот же сервер, что `createMcpServer()`. Нужен пакет `@modelcontextprotocol/server`. Строку подключения, схему и токен клиент передаёт флагами или переменными окружения `LETOPIS_DSN`, `LETOPIS_SCHEMA` и `LETOPIS_TOKEN`; флаг важнее переменной.

Подключение и сессия проверяются до начала протокола: при отказе процесс сразу завершается. В stdout идёт только протокол MCP. Опций `allowAclWrite` и `allowSystemAdmin` у команды нет: классы прав она не пишет, а сессию в арендаторе System отклоняет. Флаг `--api-key` команда не принимает: ключ сервиса даёт все права `auth.*` и не должен лежать на машине агента. Неизвестный флаг любая команда отклоняет до подключения к базе: текст ошибки в stderr и код выхода 1. `--help` печатает подсказку по командам с кодом 0.

**Параметры**

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `--dsn` | `<строка>` | обязательный | Строка подключения роли приложения (или переменная `LETOPIS_DSN`): администраторскую роль сервер отклоняет. |
| `--schema` | `<v2.имя>` | обязательный | Схема установки: полное имя вида `v2.shop` (или `LETOPIS_SCHEMA`). |
| `--token` | `<токен пользователя>` | обязательный | Токен сессии пользователя (или `LETOPIS_TOKEN`). Его выпускает приложение: `auth.sessionFor(пользователь, { ttl })`. |
| `--write` | `флаг` | только чтение | Включить инструмент записи `letopis_write`. |
| `--log` | `флаг` | обязательный | Журнал событий JSON-строками в stderr: `--log` (уровень `info`) или `--log=debug\|info\|warn\|error\|off`; есть у любой команды. stdout остаётся протоколу MCP. |

**Возвращает:** Обслуживает клиента по stdio и завершается с кодом 0, когда клиент закрывает stdin. Без токена или с `--api-key` — текст причины в stderr и код 2; без строки подключения или схемы — подсказка по командам и код 2; отказ подключению — текст в stderr и код 1.

**Ошибки** ([все коды](../errors/)):

- `user_session_required` — нет токена, передан `--api-key`, у токена нет действующей сессии или сессия работает в арендаторе System.
- `bypass_rls` — строка подключения — администраторская роль, которая обходит RLS.
- `invalid_data` — имя схемы — не вида `v<N>.<имя>` или такой схемы нет в базе.

**Примеры:** [Командная строка: letopis sync, types, load, maintain, mcp](../ops/#командная-строка)
