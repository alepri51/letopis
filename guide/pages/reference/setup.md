# Дом и консьерж

`setup()` мастер-ключом строит или достраивает дом и отдаёт пропуск консьержа, `demolish()` сносит дом. `connect(pass, { postman })` подключает консьержа — `db`: квартиры, вход по ключам и кодам, приглашения, обслуживание; письма (ссылки приглашений и коды) доставляет почтальон — функция приложения. В квартиру консьерж входит `db.in()` или `db.as()`. Неизвестную опцию `setup()` и `connect()` отклоняют с `invalid_data` и похожими именами до подключения.

**Что здесь:** [Дом](#дом) · [Консьерж](#консьерж) · [Строгие типы](#строгие-типы). У каждого пункта — сигнатура с типами, что делает, параметры и опции (тип, значение по умолчанию), что возвращает, коды ошибок и переходы к живым примерам сайта.

## Дом

### setup() {#export-setup}

```ts
setup(adminDsn: string, name: string, opts?: SetupOptions): Promise<SetupResult>
```

**Импорт:** `import { setup } from 'letopis'`

Строит дом или достраивает его (модели, сиды, правило по умолчанию) и отдаёт пропуск консьержа. Нужен мастер-ключ — строка подключения администратора PostgreSQL. Дом другой ревизии движка setup не трогает: его сносит demolish().

Ждёт базу и создаёт её, если её нет; проверяет, что сервер — PostgreSQL 18 или новее, а база — в кодировке UTF8; ставит в схему `v2.<имя>` таблицы, функции, триггеры, политики доступа, системные классы, сиды и матрицу с правилом по умолчанию; собирает статистику PostgreSQL для таблиц, у которых её ещё нет. При первом вызове заводит консьержа — роль базы `letopis_c_<имя>` (длинное имя сокращается хэшем) и аккаунт-службу с ключом — и пропуск. Повторный `setup()` накатывает функции движка заново (данные не трогает), достраивает модели и сиды и отдаёт тот же пропуск. На PostgreSQL ниже 18.2 предупреждает: такой сервер мог удалить служебные данные непрочитанных сигналов — его лучше обновить.

Имя дома — одно на сервер PostgreSQL, а не на базу: роли дома (`letopis_c_<имя>`, `letopis_a_<имя>`) общие на все базы сервера. Дом с именем, которое занято домом в другой базе того же сервера, `setup()` не строит — отказ `exists` (`boot.house_elsewhere`) до любых изменений. После сноса дома имя свободно для любой базы.

Дом другой ревизии движка `setup()` не трогает: старше пакета — отказ `invalid_data` с подсказкой снести дом `demolish()` и построить заново (данные не переносятся), новее — ошибка `Error` с текстом `letopis.setup: …`. Тем же `Error` отвечают отказы без своего кода: не установлены пакеты PGlite, сервер ниже PostgreSQL 18 или база не в UTF8, сервер не ответил за `waitTimeoutMs`, ошибка в файле SQL (текст называет файл). Ошибки подключения, например неверный пароль в мастер-ключе, приходят от PostgreSQL как есть.

::: warning Пропуск — секрет
В пропуске — пароль роли консьержа и его ключ: храните его как пароль, вне репозитория. Он же лежит в базе (строка `secret` вида `CONCIERGE`, её видит только владелец схемы) и потому попадает в резервные копии. Утёк — `setup(мастер-ключ, имя, { rotate: true })`: прежний пропуск сразу перестаёт работать.
:::

**Возвращает:** `Promise<SetupResult>` ([SetupResult](./types-setup#type-setupresult)) — `{ pass, schema, created, revision, analyzed, warnings, models?, pglite? }`: пропуск консьержа (повтор — тот же, с `rotate` — новый); полное имя схемы; построен ли дом этим вызовом; ревизия движка; таблицы, для которых собрана статистика; предупреждения; с `models` — итог их записи, как у `syncModels()`; с `pglite` — запущенный PGlite.

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — неизвестная опция (похожие имена — в `err.params.similar`), неверное имя дома (`boot.setup_name`), `defaultRule` (`boot.setup_default_rule`), `signals` или имя сида, нет мастер-ключа и нет `pglite` (`boot.no_connection`) — всё до подключения; дом старой ревизии или без штампа ревизии (`boot.schema_old`) — до любых изменений; роль консьержа уже есть и она привилегированная (`boot.login_privileged`) или установщику нельзя выдать ей служебную роль дома `letopis_a_<имя>` (`boot.login_grant_denied`); модели не прошли проверку, как у `syncModels()`.
- `admin_required` — роль-владелец уже есть, а у установщика нет на неё права `ADMIN OPTION` (`boot.owner_no_admin`).
- `exists` — имя дома занято домом в другой базе этого сервера (`boot.house_elsewhere`).

### demolish() {#export-demolish}

```ts
demolish(
  adminDsn: string,
  name: string,
  opts?: { quiet?: boolean },
): Promise<{ schema: string; dropped: boolean }>
```

**Импорт:** `import { demolish } from 'letopis'`

Сносит дом: схему со всеми квартирами и вещами, роль консьержа и служебную роль дома. Нужен мастер-ключ. Ответ — `{ schema, dropped }`: `dropped: true` — дом снесён, в stdout строка `letopis.demolish: v2.<имя>` (`{ quiet: true }` её не печатает); дома с таким именем нет — без ошибки и без вывода, `dropped: false` (оставшиеся роли дома всё равно убираются — кроме случая, когда их держит дом с этим именем в другой базе того же сервера: тогда роли не трогаются). Неизвестная опция — invalid_data.

Схему удаляет её владелец (`drop schema … cascade`), затем — роль консьержа и служебная роль дома: пропуск дома больше не работает. Роли дома с тем же именем в другой базе сервера `demolish()` не трогает.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `adminDsn` | `string` | обязательный | Мастер-ключ — строка подключения администратора PostgreSQL, как у `setup()`. |
| `name` | `string` | обязательный | Имя дома — как у `setup()`. |
| `opts` | `{ quiet?: boolean }` | `{}` | Опции. |
| `opts.quiet` | `boolean` | `false` | Не печатать `letopis.demolish: <схема>`. |

**Возвращает:** `Promise<{ schema: string; dropped: boolean }>` — `{ schema, dropped }`: полное имя схемы и снесён ли дом (`false` — его не было).

**Ошибки** ([все коды](../errors/)):

- `invalid_data` — неверное имя дома (`boot.setup_name`); неизвестная опция (`api.unknown_option`, похожие имена — в `err.params.similar`).

**Примеры:** [Аварии и конец: новый пропуск и снос дома](../install/#новыи-пропуск-и-снос-дома)

## Консьерж

### connect() {#export-connect}

```ts
connect<const M extends readonly AnyModelLike[]>(
  pass: string,
  opts: HouseOptions & { models: M },
): Promise<House<M>>
connect(pass: string, opts?: HouseOptions): Promise<House>
// Строгие типы без моделей Zod — из объявлений `letopis types`: `connect<Models>(pass)`.
connect<M extends readonly AnyModelLike[]>(pass: string, opts?: HouseOptions): Promise<House<M>>
```

**Импорт:** `import { connect } from 'letopis'`

Подключиться к дому пропуском консьержа (результат setup()); с моделями — строгие типы цепочек корней квартир.

Разбирает пропуск, проверяет дом и входит ключом консьержа. Дом старой ревизии или без штампа ревизии — отказ до входа (`boot.schema_old`). О ревизии новее пакета и о несовпавшем штампе движка (дом той же ревизии ставила другая версия пакета) `connect()` только предупреждает в консоли. Пул на `max` соединений — общий для консьержа и всех корней квартир; закрывает его `db.close()`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `pass` | `string` | обязательный | Пропуск — строка из `setup()` (`r.pass`): строка подключения роли консьержа с домом и ключом консьержа (`letopis_schema`, `letopis_key`). |
| `opts` | `HouseOptions & { models: M }` | `{}` | Опции — таблица `HouseOptions` ниже. |

**Опции `HouseOptions`**

| Опция | Тип | По умолчанию | Описание |
|---|---|---|---|
| <span id="connect-max"></span>`max` | `number` | `10` | Размер пула (по умолчанию 10). Пул один на консьержа и все корни квартир.<br>Примеры: [Опции connect(pass): наблюдение за запросами, пул, сигналы, кэш](../install/#опции-connect) · [Разработка без PostgreSQL: PGlite](../install/#разработка-без-postgresql) |
| <span id="connect-cache"></span>`cache` | `CacheOptions \| false` | включён: срок 60 с, до 10 000 ответов | Кэш результатов: срок по умолчанию, размер, `ttlOnly`; `false` — выключен. Кэш хранит ответы только тех цепочек, где вызван `.cache()`, и чтения классов с `cache` в модели. Контакт — он же имя для входа. Только у консьержа: корень квартиры о своём аккаунте отдаёт `me.account` (id) и больше ничего, чужих контактов жилец не узнаёт. Имя аккаунта — строка `Account`: `(await me.Account(me.account).first())?.data.name`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |

**Возвращает:** `Promise<ContactAddress | null>` ([ContactAddress](./types-setup#type-contactaddress)) — `{ kind, address }` — контакт аккаунта; `null` — такого аккаунта нет.

## Строгие типы

`connect(pass, { models })` с моделями `letopis/model` или `connect<Models>(pass)` с объявлениями `letopis types` дают корни квартир со строгими типами: шаг — только известный класс, переход — по концам, шаг конца — конец записываемого класса. Без моделей корень принимает шагом любое имя (`me.Order()`) и проверяет его во время выполнения. Имя, известное только во время выполнения, — через `loose(me)`.

### loose() {#export-loose}

```ts
loose<T extends DbBase>(db: T): T & { [className: string]: StepFn }
```

**Импорт:** `import { loose } from 'letopis'`

Тот же корень без строгих типов: шагом может быть любое имя, в том числе известное только во время выполнения, — `loose(room)[имя]()`. Объект тот же: проверки во время выполнения (неизвестное имя или поле, переход, шаг роли) не меняются.

Нужен, когда имя класса известно только во время выполнения — из настроек, запроса или данных. Ничего не копирует и не открывает: это тот же объект.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `db` | `DbBase` | обязательный | Корень квартиры или транзакция `me.begin()` — со строгими типами или без. |

**Возвращает:** `T & { [className: string]: StepFn }` — Тот же объект без строгих типов: шагом может быть любое имя. Неизвестное имя даёт `invalid_class`, неизвестное поле фильтра, `sort()` или итога — `invalid_query` — во время выполнения.

**Ошибки:** собственных кодов нет.

**Примеры:** [Ошибки строгого режима, MCP и квартир](../errors/#строгии-режим-mcp-чужая-квартира) · [Служебные экспорты: id из ключа, валидатор, типы, строгие типы, зарезервированные имена](../models/inside#служебные-функции-пакета)
