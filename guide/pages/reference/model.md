# Модели: letopis/model

Модель описывается в коде: `hub` — класс-объект, `link` — класс-связь, `one` и `many` — концы. `syncModels` записывает модель в базу, `generateTypes` печатает типы для TypeScript.

## Классы и концы

### hub() {#model-hub}

```ts
hub<N extends string, S extends z.ZodRawShape>(
  name: N,
  shape: S,
  opts: Omit<ClassDef, 'fields'>,
): Model<N, z.output<z.ZodObject<S>>, Record<never, never>>
hub<N extends string, const D extends ClassDef<z.ZodRawShape, EndsInput, AnyModel | undefined>>(
  name: N,
  def?: D,
): Model<N, DataOf<D['extends'], ShapeOf<D['fields']>>, AllLinks<D['extends'], D['ends'] extends EndsInput ? D['ends'] : Record<never, never>>, AliasOf<D>>
```

Хаб — объект (мастер, услуга).

Возвращает модель класса — описание, которое `syncModels()` (или `letopis sync`) записывает в базу строкой `Class`. Формы вызова две. Полная — `hub(имя, { fields, ends, key, … })`. Короткая — `hub(имя, поля, опции)`: поля объектом типов Zod вторым аргументом, остальное описание третьим. Полная форма нужна, например, для `extends`, чтобы TypeScript вывел типы данных потомка. Свойства описания — в таблице ниже; `link()` принимает то же описание.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | `N` | обязательный | Имя класса: латинские или русские буквы, цифры и `_`, первый знак — не цифра, до 63 знаков. Этим именем называют шаг цепочки: `db.Shop()`. |
| `def` | `D` | нет: класс без полей, концов и ключа | Описание класса `ClassDef` — свойства в таблице ниже. В короткой форме вторым аргументом идут поля, а описание без `fields` — третьим. |

**Опции `ClassDef`**

| Опция | Тип | По умолчанию | Описание |
|---|---|---|---|
| <span id="class-alias"></span>`alias` | `string` | нет | Второе имя класса: им тоже можно назвать шаг цепочки, например по-русски (`db.Товар()`). Алиас не совпадает с именем или алиасом другого класса и не наследуется. Сменить алиас существующего класса может только тот, у кого есть права `READ`, `WRITE` и `DELETE` без условий на все строки класса и его потомков.<br>Примеры: [Наследование, абстрактный класс и алиас](../models/#наследование-и-алиасы) |
| <span id="class-extends"></span>`extends` | `P` | нет | Предок — модель класса. Потомок получает поля, концы и ключ предка, а также `history`, `ownerDefault`, `cache`, `meta`, `derivedBy` и `aggregate`; своё поле или конец с тем же именем заменяет унаследованное целиком. Шаг цепочки по предку находит и строки потомков (`.exact()` — только сам класс). Предок должен быть в базе раньше потомка: `syncModels()` сам записывает его первым.<br>Примеры: [Наследование, абстрактный класс и алиас](../models/#наследование-и-алиасы) |
| <span id="class-abstract"></span>`abstract` | `boolean` | `false` | `true` — у класса не бывает своих строк, только у потомков: запись строки такого класса — `invalid_class`. Не наследуется.<br>Примеры: [Наследование, абстрактный класс и алиас](../models/#наследование-и-алиасы) |
| <span id="class-ends"></span>`ends` | `E` | нет концов | Концы — ссылки на другие объекты: роль → `one(…)`, `many(…)` или сама модель (`{ Shop }` — то же, что `one(Shop)`). Имя роли — по правилам имени класса, и во всей схеме роль с этим именем ведёт на один и тот же класс. Концы наследуются: свой конец с той же ролью заменяет конец предка.<br>Примеры: [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) |
| <span id="class-fields"></span>`fields` | `z.ZodObject<S> \| S` | нет своих полей | Поля данных: объект Zod (`z.object({ … })`) или просто объект типов Zod. В короткой форме `hub(имя, поля, опции)` поля идут вторым аргументом. Имя поля не начинается с `$`, лишние ключи верхнего уровня база отклоняет. Поля наследуются: своё поле с тем же именем заменяет поле предка целиком. |
| <span id="class-key"></span>`key` | `readonly string[]` | ключ предка; без предка — ключа нет, id выдаёт база | Поля и роли, из которых вычисляется id: UUID v5 из арендатора, класса и значений ключа, поэтому второй объект с тем же ключом база не создаст. В ключ входят только обязательные строковые поля (умолчание допустимо) и обязательные одиночные концы. Ключ наследуется; `[]` — класс без ключа, даже если ключ есть у предка. Новый ключ класса со строками задают `db.rekeyClass()`: правку описания с другим ключом база отклонит (`tightening_conflict`).<br>Примеры: [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) |
| <span id="class-ondelete"></span>`onDelete` | `Partial<Record<keyof E & string, OnDelete>>` | `restrict` у каждого конца | Действие при удалении цели для собственных концов класса по ролям: `{ Customer: 'unset' }` — то же, что `.onDelete('unset')` у конца. `restrict` — запретить удаление цели, пока на неё ссылаются; `cascade` — удалить вместе с целью и эту строку; `unset` — снять ссылку (только у необязательного одиночного конца и у списка без `min`).<br>Примеры: [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) |
| <span id="class-history"></span>`history` | `boolean \| HistoryPolicy` | `true` | Журнал класса. `true` — журнал ведётся, а хранит версии по умолчанию установки `up({ history })`, без него — все. `false` — журнала нет: нет версий, среза на дату, восстановления и событий подписки. Объект `{ all, daily, weekly, monthly, yearly, tz }` — политика хранения по ярусам: сроки — интервалы PostgreSQL (`'1 day'`, `'3 months'`) по возрастанию, `all` — не меньше суток, `'forever'` — только у последнего яруса; `tz` — часовой пояс границ периодов. Наследуется. Сменить у существующего класса может только тот, у кого есть права `READ` и `DELETE` без условий на все строки класса и его потомков.<br>Примеры: [Хранение истории по ярусам: maintain, trimHistory, cursor_expired](../history/#хранение-по-ярусам) · [Настройки класса: без истории, владелец-автор, метаданные, описание модели](../models/#настроики-класса) |
| <span id="class-ownerdefault"></span>`ownerDefault` | `'tenant' \| 'actor'` | `'tenant'` | Кто владелец новых строк: `'tenant'` — арендатор, `'actor'` — сам пользователь. `'actor'` пригодится для правила «каждый видит свои записи». Наследуется.<br>Примеры: [Настройки класса: без истории, владелец-автор, метаданные, описание модели](../models/#настроики-класса) |
| <span id="class-cache"></span>`cache` | `{ ttl?: number }` | нет: без `.cache()` чтения не кэшируются | Кэшировать чтения класса без `.cache()` в цепочке: ответ хранится в памяти процесса `ttl` секунд, без `ttl` — срок кэша подключения (по умолчанию 60 с). Действует, только если все классы, которые читает цепочка (с потомками), помечены `cache`; срок — наименьший из них. Наследуется. |
| <span id="class-meta"></span>`meta` | `ClassMeta` | нет | Свободные метаданные для приложения: название, иконка, цвет, порядок в меню. База их хранит, но не толкует; размер — до 64 КБ. Наследуются по ключам, `null` убирает унаследованное значение. Видны всем, у кого есть сессия: в `db.describe()` и `db.registry`. Тип задают расширением интерфейса `ClassMeta`.<br>Примеры: [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) |
| <span id="class-derivedby"></span>`derivedBy` | `string` | нет: строки пишут приложение, сырой SQL и загрузчик | Производный класс: строки пишет только проектор с этим именем; наследуется. Имя — строчные латинские буквы, цифры и `_.:-`, первый знак — буква или цифра, до 64 знаков. Запись, правка и удаление строк такого класса в обход проектора — `derived_class`; на его строки не ссылаются, а его концы — только `cascade` или `unset`. Заводит и меняет производный класс только администратор (право `letopis.projector`), иначе `acl_denied`.<br>Примеры: [Проектор: итоги из журнала, записи не ждут друг друга](../derived/#проектор-из-журнала) |
| <span id="class-aggregate"></span>`aggregate` | `Record<string, AggregateDef>` | нет | Агрегаты в базе: поле — сумма поля (`sum`) или число (`count: true`) живых строк класса `of` того же арендатора, чей одиночный конец `via` ведёт на строку; `where` — JSON Schema над данными строки-источника. Поле считает база, приложение его не пишет. Наследуется, потомок заменяет целиком. Живые строки — не удалённые. Пример: `balance: { sum: 'amount', of: 'Movement', via: 'Wallet' }` — баланс кошелька как сумма операций. Поле должно быть среди полей класса, числовым и не входить в ключ; значение в записи — `aggregate_field`. Класс-источник описывают раньше агрегата: `syncModels()` сам записывает его первым.<br>Примеры: [Агрегат: баланс считает сама база](../derived/#агрегат-в-базе) |

**Возвращает:** `Model<N, DataOf<D['extends'], ShapeOf<D['fields']>>, AllLinks<D['extends'], D['ends'] extends EndsInput ? D['ends'] : Record<never, never>>, AliasOf<D>>` — Модель класса. Её передают в `syncModels()`, в `ends` других классов, в `extends` потомков и в `connect({ models })` для типов цепочек. Тип данных строки — `Infer<typeof Модель>`.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Недопустимое имя класса или роли конца; имя поля начинается с `$`; в ключе необязательное или нестроковое поле, список, необязательный конец или неизвестное имя; `unset` у обязательного конца; агрегат над полем, которого нет среди полей класса, или агрегат не с ровно одним из `sum` и `count: true`.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

### link() {#model-link}

```ts
link<N extends string, S extends z.ZodRawShape>(
  name: N,
  shape: S,
  opts: Omit<ClassDef, 'fields'>,
): Model<N, z.output<z.ZodObject<S>>, Record<never, never>>
link<N extends string, const D extends ClassDef<z.ZodRawShape, EndsInput, AnyModel | undefined>>(
  name: N,
  def?: D,
): Model<N, DataOf<D['extends'], ShapeOf<D['fields']>>, AllLinks<D['extends'], D['ends'] extends EndsInput ? D['ends'] : Record<never, never>>, AliasOf<D>>
```

Связь — отношение между объектами со своими данными (бронь, навык).

Описание и формы вызова — те же, что у `hub()` (таблица свойств — под `hub()`). Связь обычно ссылается концами на два объекта и хранит данные самого отношения: строка заказа связывает заказ и товар и хранит количество и цену. В цепочке шаг от объекта к связи по умолчанию идёт к связям, которые ссылаются на этот объект. Имя связи не может совпадать с именем метода цепочки (`count`, `sort`, `set` и другие): такую связь база не примет при записи модели (`invalid_class`).

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | `N` | обязательный | Имя класса — по тем же правилам, что у `hub()`, и не имя метода цепочки. |
| `def` | `D` | нет: класс без полей, концов и ключа | Описание класса `ClassDef` — как у `hub()`. В короткой форме вторым аргументом идут поля, а описание без `fields` — третьим. |

**Возвращает:** `Model<N, DataOf<D['extends'], ShapeOf<D['fields']>>, AllLinks<D['extends'], D['ends'] extends EndsInput ? D['ends'] : Record<never, never>>, AliasOf<D>>` — Модель класса — как у `hub()`.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — То же, что у `hub()`: недопустимое имя класса или роли, поле на `$`, неверный ключ, `unset` у обязательного конца, неверный агрегат.

**Примеры:** [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

### one() {#model-one}

```ts
one(...targets: Target[]): End<false, true>
```

Одиночный конец; несколько классов — союз: `one(Service, Product)`. По умолчанию обязательный.

Цель — модель или имя класса строкой: `one('Category')` позволяет классу ссылаться на самого себя. Запись `ends: { Shop }` — то же, что `ends: { Shop: one(Shop) }`. В строке ответа одиночный конец — id цели (`row.links.Shop`).

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `...targets` | `Target[]` | обязательный | Классы, на объекты которых может вести ссылка: модели или имена классов. Несколько классов — союз: конец принимает объект любого из них или их потомков. |

**Возвращает:** `End<false, true>` — Конец `End` — одиночный и обязательный. Сделать его необязательным — `.optional()`, задать действие при удалении цели — `.onDelete()`.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Не передан ни один класс цели.

**Примеры:** [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

### many() {#model-many}

```ts
many(
  target: Target | readonly Target[],
  opts?: { min?: number; max?: number; onDelete?: OnDelete },
): End<true, boolean>
```

Множественный конец: список целей в одном конце.

В строке ответа такой конец — список id целей; одна цель в списке не повторяется (`invalid_data`). Конец обязателен, если `min` больше 0: тогда база требует не меньше `min` целей.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `target` | `Target \| readonly Target[]` | обязательный | Класс цели или список классов (союз): модели или имена классов. |
| `opts` | `{ min?: number; max?: number; onDelete?: OnDelete }` | `{}` | Пределы списка и действие при удалении цели. |
| `opts.min` | `number` | нет: список может быть пустым | Наименьшее число целей в списке, целое от 0. Больше 0 — конец обязателен. |
| `opts.max` | `number` | нет: без предела | Наибольшее число целей в списке, целое от 1. |
| `opts.onDelete` | `OnDelete` | `restrict` | Что сделать со строкой, когда удаляют одну из целей: `restrict` — запретить удаление, `cascade` — удалить и эту строку, `unset` — убрать цель из списка (только у списка без `min`). |

**Возвращает:** `End<true, boolean>` — Конец `End` со списком целей.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Передан пустой список классов цели.

**Примеры:** [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

### End {#model-end}

```ts
class End {
  constructor(
    targets: readonly Target[],
    opts: { many: Many; required: Required; min?: number; max?: number; onDelete?: OnDelete; meta?: Record<string, unknown> },
  );
  readonly targets: readonly Target[];
  readonly many: Many;
  readonly required: Required;
  readonly min?: number;
  readonly max?: number;
  readonly onDeleteRule?: OnDelete;
  readonly metaData?: Record<string, unknown>;
}
```

Конец класса: `one(X)`, `one(A, B)`, `many(X, { min, max })`.

Обычно конец создают `one()` и `many()`, а не конструктором. Объект конца не меняется: `optional()`, `onDelete()` и `meta()` возвращают новый конец.

**Параметры конструктора**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `targets` | `readonly Target[]` | обязательный | Классы целей: модели или имена классов, хотя бы один. |
| `opts` | `{ many: Many; required: Required; min?: number; max?: number; onDelete?: OnDelete; meta?: Record<string, unknown> }` | обязательный | Свойства конца. |
| `opts.many` | `Many` | обязательный | `true` — список целей (как у `many()`), `false` — одна цель. |
| `opts.required` | `Required` | обязательный | Обязателен ли конец: `true` — строку без этой ссылки база не примет. |
| `opts.min` | `number` | нет | Наименьшее число целей списка. |
| `opts.max` | `number` | нет | Наибольшее число целей списка. |
| `opts.onDelete` | `OnDelete` | `restrict` | Действие при удалении цели: `restrict`, `cascade` или `unset`. |
| `opts.meta` | `Record<string, unknown>` | нет | Свободные метаданные конца: база их хранит, но не толкует. |

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Список `targets` пуст.

**Примеры:** живого примера пока нет.

### конец.targets {#end-targets}

```ts
readonly targets: readonly Target[]
```

Классы целей в том виде, в каком их передали в `one()` или `many()`: модели или имена классов строкой. Имена всех целей отдаёт `classNames()`.

**Примеры:** живого примера пока нет.

### конец.many {#end-many}

```ts
readonly many: Many
```

`true` — конец-список (`many()`), `false` — одиночный конец (`one()`).

**Примеры:** живого примера пока нет.

### конец.required {#end-required}

```ts
readonly required: Required
```

Обязателен ли конец. У `one()` — `true`, пока не вызван `optional()`; у `many()` — `true`, если `min` больше 0.

**Примеры:** живого примера пока нет.

### конец.min {#end-min}

```ts
readonly min: number
```

Наименьшее число целей списка из `many(X, { min })`; если не задано — `undefined`.

**Примеры:** живого примера пока нет.

### конец.max {#end-max}

```ts
readonly max: number
```

Наибольшее число целей списка из `many(X, { max })`; если не задано — `undefined`, предела нет.

**Примеры:** живого примера пока нет.

### конец.onDeleteRule {#end-ondeleterule}

```ts
readonly onDeleteRule: OnDelete
```

Действие при удалении цели, заданное `onDelete()`, `many(X, { onDelete })` или свойством `onDelete` описания класса. Если не задано — `undefined`, и база действует как при `restrict`.

**Примеры:** живого примера пока нет.

### конец.metaData {#end-metadata}

```ts
readonly metaData: Record<string, unknown>
```

Метаданные, заданные `meta()`; если не заданы — `undefined`.

**Примеры:** живого примера пока нет.

### конец.optional() {#end-optional}

```ts
optional(): End<Many, false>
```

Необязательный конец.

Исходный конец не меняется — возвращается новый. У одиночного конца ссылки теперь может не быть. У списка обязательность задаёт `min`: `optional()` его не снимает, и список с `min` по-прежнему требует не меньше `min` целей.

**Возвращает:** `End<Many, false>` — Новый конец — такой же, но необязательный.

**Ошибки:** собственных кодов нет.

**Примеры:** [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

### конец.onDelete() {#end-ondelete}

```ts
onDelete(rule: OnDelete): End<Many, Required>
```

Правило при удалении цели: restrict (по умолчанию), cascade, unset.

Возвращает новый конец, исходный не меняется. То же задаёт свойство `onDelete` описания класса. `unset` допустим только у необязательного одиночного конца и у списка без `min`, иначе `hub()` и `link()` бросают `invalid_class`. У производного класса (`derivedBy`) база принимает только `cascade` и `unset`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |

**Возвращает:** `End<Many, Required>` — Новый конец с этим действием.

**Ошибки:** собственных кодов нет.

**Примеры:** [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина)

## Модель в базе и типы

### syncModels() {#export-syncmodels}

```ts
syncModels(db: Db, models: readonly AnyModel[], opts?: { apply?: boolean }): Promise<SyncResult>
```

Записывает описания моделей в базу — строками `Class` арендатора текущей сессии — и отвечает, какие классы созданы, изменены и остались прежними. Без `{ apply: true }` — сухой прогон: те же записи идут в транзакции, которая в конце откатывается, поэтому ошибки описания и `tightening_conflict` видны уже в нём.

Трогает только переданные классы и ничего не удаляет. Порядок в списке не важен: предок записывается раньше потомка, класс-источник агрегата — раньше цели. Безопасные правки — новое необязательное поле или конец, метаданные, алиас — применяются сразу. Остальные (правка существующего поля, ключа, предка, условий `anyOf` и `oneOf`, агрегатов) — ужесточение: база проверяет все строки класса и его потомков. Классы арендатора System не меняются — они попадают в `skipped`. После применения реестр классов подключения перечитывается. То же из командной строки — `letopis sync`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `db` | `Db` | обязательный | Подключение `connect()` с сессией: классы пишутся в арендатора этой сессии, и другие арендаторы их не видят. |
| `models` | `readonly AnyModel[]` | обязательный | Модели из `hub()` и `link()` в любом порядке. |
| `opts` | `{ apply?: boolean }` | `{}` | Режим записи. |
| `opts.apply` | `boolean` | `false` | `true` — применить изменения; без него — сухой прогон. |

**Возвращает:** `Promise<SyncResult>` ([SyncResult](./types#type-syncresult)) — Отчёт `{ applied, created, updated, unchanged, skipped, lost }`: применены ли изменения; имена созданных, изменённых и прежних классов; классы System, которые меняет только установка; правила `refine`, `superRefine` и `transform` (путь и вид), которых нет в базе, — их проверяйте в приложении.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Модели зависят друг от друга по кругу через предка или источник агрегата (до записи); поле не выражается в JSON Schema базы (ключевое слово, `format` или шаблон `pattern`); описание отклонила база: нет предка или класса-источника агрегата, имя занято системным классом или алиасом другого класса, роль конца уже ведёт на другой класс, неверная политика `history`, `meta` больше 64 КБ и другие причины — они названы в тексте ошибки.
- `invalid_data` — Описание не проходит проверку формата в базе: например, `min` меньше 0, `max` меньше 1 или недопустимое имя в `derivedBy`.
- `tightening_conflict` — Ужесточению мешают существующие строки; в `detail` — какие строки не подходят.
- `acl_denied` — Нет права записывать классы; для ужесточения, смены предка, алиаса или `history` нет нужных прав без условий на все строки класса и его потомков; производный класс без права `letopis.projector`; агрегат без права `READ` без условий на все строки источника.
- `derived_class` — Конец ведёт на производный класс, или класс становится производным, хотя на него уже ссылаются.

**Примеры:** [Первый объект: создать, изменить, удалить, вернуть](../basics/what-is#пример-жизнь-одного-объекта) · [Модель магазина: классы, концы, ключи](../models/#пример-модель-магазина) · [Проверка данных: база не примет неправильное](../models/#проверка-данных)

### generateTypes() {#export-generatetypes}

```ts
generateTypes(registry: Registry, opts?: { includeSystem?: boolean }): string
```

Объявления `<Класс>Data` и `<Класс>Links` для классов реестра (кроме системных).

Типы строятся по описаниям, которые база уже развернула с учётом предков, поэтому в них есть и классы, созданные не из моделей. Поле в `Data` необязательно (`?`), если его нет в `required`; конец в `Links` обязателен, если он обязательный или у него `min` больше 0, а список — `string[]`. Так работает `letopis types`.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `registry` | `Registry` | обязательный | Реестр классов, обычно `db.registry` подключения: классы арендатора сессии и System. |
| `opts` | `{ includeSystem?: boolean }` | `{}` | Что включить. |
| `opts.includeSystem` | `boolean` | `false` | `true` — выводить и классы арендатора System. |

**Возвращает:** `string` — Текст модуля TypeScript: `export interface <Класс>Data` и `export interface <Класс>Links` для каждого класса по алфавиту; в начале — пометка, что файл сгенерирован и руками его не правят.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Имя класса не годится для идентификатора TypeScript: в нём есть знаки, кроме латинских букв, цифр и `_` (например, русские буквы).

**Примеры:** живого примера пока нет.

### schemaToTs() {#export-schematots}

```ts
schemaToTs(s: JsonSchema | undefined, indent?: string): string
```

Тип TypeScript по JSON Schema подмножества.

Учитывает только форму данных: `type`, `properties`, `required`, `items`, `enum`, `const`, `anyOf`, `oneOf`, `additionalProperties` и `propertyNames` с `enum`. Пределы, `format` и `pattern` в тип не попадают. Пустая схема — `unknown`, объект без свойств — `Record<string, unknown>`.

**Параметры**

**Возвращает:** `string` — Текст типа TypeScript: `string`, `"a" | "b"`, `Array<number>` или объект `{ "name": string; … }` в несколько строк.

**Ошибки:** собственных кодов нет.

## JSON Schema

### normalizeSchema() {#model-normalizeschema}

```ts
normalizeSchema(input: JsonSchema, opts?: NormalizeOptions): JsonSchema
```

Нормализует JSON Schema; бросает LetopisError('invalid_class') с названием поля и ключевого слова.

Приводит JSON Schema (обычно вывод `z.toJSONSchema()`) к подмножеству, которое проверяют база и валидатор: убирает `$schema`, разворачивает ссылки `$ref` на `$defs`, переводит `pattern` функцией `translatePattern()`, а свободные ключи (например, из `.meta()` Zod) переносит в `x-meta`. Ключевое слово вне подмножества (`allOf`, `not`, `if`, `patternProperties` и другие), `format`, кроме `uuid`, `date`, `date-time` и `email`, и рекурсивная ссылка — ошибка: ни одно правило не пропадает молча. Так `syncModels()` готовит поля моделей.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `input` | `JsonSchema` | обязательный | JSON Schema — объект. |
| `opts` | `NormalizeOptions` | `{}` | Необязательные поля: `where` — имя модели или поля для текста ошибок (по умолчанию «модель»); `topLevel: true` — ещё проверить, что имена полей верхнего уровня не начинаются с `$`. |

**Возвращает:** `JsonSchema` ([JsonSchema](./types#type-jsonschema)) — Новая JSON Schema в подмножестве базы; входная схема не меняется.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Ключевое слово или `format` вне подмножества; ссылка не на `#/$defs/…`; рекурсия или ненайденное определение; узел — не объект; шаблон `pattern` несовместим с PostgreSQL; имя поля верхнего уровня начинается с `$` (с `topLevel`). В тексте — `where` и узел, где найдена ошибка.

**Примеры:** живого примера пока нет.

### translatePattern() {#model-translatepattern}

```ts
translatePattern(p: string, where?: string): string
```

Перевод шаблона JavaScript в форму, которую одинаково понимают JavaScript (без флага u) и PostgreSQL: обозначения классов заменяются явными наборами, остальное не трогается.

Заменяет обозначения `\d`, `\w`, `\s` (и `\D`, `\W`, `\S`) явными наборами символов: `\d` → `[0-9]`, `\w` → `[A-Za-z0-9_]`; остальное оставляет как есть. Отклоняет то, что PostgreSQL понимает иначе или не понимает: `\b` и `\B`, `\p{…}`, обратные ссылки, именованные группы, `\D`, `\W` и `\S` внутри `[ ]`, обратную косую черту в конце шаблона.

**Параметры**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `p` | `string` | обязательный | Шаблон регулярного выражения JavaScript — как в `pattern` или `z.string().regex()`. |
| `where` | `string` | `'pattern'` | Где стоит шаблон: с этого начинается текст ошибки. |

**Возвращает:** `string` — Шаблон, который одинаково понимают JavaScript (без флага `u`) и PostgreSQL.

**Ошибки** ([все коды](../errors/)):

- `invalid_class` — Шаблон несовместим с регулярными выражениями PostgreSQL; в тексте — `where`, шаблон и причина.

**Примеры:** живого примера пока нет.
