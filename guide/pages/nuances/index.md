# Все нюансы

Ловушки и неочевидные правила letopis по темам. У каждого — ссылка прямо на живой пример, который его показывает. Десять главных — на странице [«Первые 15 минут»](../first/#десять-главных-нюансов). Отметка **ловит код** — эту ловушку ловит сама библиотека: ошибкой или предупреждением.

## Удаление и восстановление

| Нюанс | Где показан |
|---|---|
| delete() без { confirm: true } ничего не удаляет — возвращает предпросмотр: что удалится и с каким действием ($action). | [1. Что такое letopis: «Первый объект: создать, изменить, удалить, вернуть»](../basics/what-is#ex-basics-01-first-object) |
| Действие при удалении, заданное у конца, решает судьбу концов, ведущих на удаляемую цель: cascade — удалить вместе, unset — очистить конец, restrict — отказ delete_restricted. | [6. Удаление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade) |
| restore() возвращает только цели шага; строки, удалённые каскадом, возвращают отдельно — по надгробиям этого удаления, с restore({ expect }). | [6. Удаление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
| В предпросмотре удаления у строк каскада $action тоже delete: цель от каскада отличает $depth — 0 у самой цели, 1 и дальше у строк каскада; у строк unset и restrict $depth нет. | [6. Удаление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade) |
| Предпросмотр — снимок на момент вызова, а delete({ confirm: true }) удаляет то, что есть при подтверждении. Удалить ровно показанное — delete({ confirm: true, expect: предпросмотр }): в транзакции удаления строки каскада блокируются, предпросмотр строится заново под блокировкой и сравнивается по id, rev и $action; не совпал — conflict (write.preview_changed), ничего не удалено, новый предпросмотр — в err.detail.preview. | [6. Удаление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade) |
| withDeleted().restore() возвращает все удалённые строки шага — и те, что удалили раньше и отдельно. Строки одного удаления отличает причина: надгробия цели и её каскада получают reason этого удаления — отберите их по ней и верните restore({ expect: надгробия }). Причину делайте своей для каждого удаления. | [6. Удаление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
| restore() без expect возвращает последний снимок строки, а не версию, ушедшую конкретным удалением: если выдачу с ключом по вещи после удаления участника пересоздали (вещь выдали другому) и закрыли, restore() оживит чужую закрытую выдачу. restore({ expect: [надгробие] }) вернёт строку, только если её последняя версия — то самое надгробие; иначе отказ и ничего не восстановлено (conflict write.restore_stale; если id занял новый живой объект — not_deleted write.restore_id_taken; err.detail.stale — причина каждой цели), а с partial: true — строка-пропуск. Приложение сообщает «не вернулась».<br>**Ловит код:** `conflict` | [6. Удаление: «Вернуть удалённое»](../delete/#ex-delete-02-restore)<br>[7. Транзакции и деньги: «Одна выдача на вещь: гонка, forUpdate(), { rev }, ключ и возврат удал…»](../money/#ex-money-05-one-open) |
| restore({ expect, partial: true }) возвращает удаление целиком одним вызовом: восстанавливает цели, чья последняя версия — то самое надгробие, а остальные отдаёт в ответе строками-пропусками $action: 'skip' с причиной $why — changed (после удаления строку пересоздавали, правили или удалили снова), reissued (id занял новый живой объект), restored (уже вернули). Без partial одна такая цель роняет весь вызов; partial без expect — invalid_query. | [6. Удаление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade)<br>[7. Транзакции и деньги: «Одна выдача на вещь: гонка, forUpdate(), { rev }, ключ и возврат удал…»](../money/#ex-money-05-one-open) |
| withDeleted() — модификатор своего шага: X(id).withDeleted() — удалённый X, X(id).withDeleted().Y().withDeleted() — удалённые Y удалённого X. withDeleted() только у первого шага (X().withDeleted().Y()) даёт живых Y — letopis один раз предупреждает. Переход идёт по последней версии строки: пересозданную и снова удалённую строку от прежнего родителя не найти — её находят надгробия удаления.<br>**Ловит код:** `предупреждение api.with_deleted_step` | [6. Удаление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
| restore() без фильтра, id и expect (db.line().restore()) восстанавливает всё удалённое шага — это не отказ, letopis один раз предупреждает. Сужайте шаг или передавайте expect.<br>**Ловит код:** `предупреждение write.restore_no_filter` | [6. Удаление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
