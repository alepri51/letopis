# Все нюансы

Ловушки и неочевидные правила letopis по темам. У каждого — ссылка прямо на живой пример, который его показывает. Десять главных — на странице [«Первые 15 минут»](../first/#десять-главных-нюансов). Отметка **ловит код** — эту ловушку ловит сама библиотека: ошибкой или предупреждением.

## Дом и консьерж

| Нюанс | Где показан |
|---|---|
| Повторный setup() безопасен: накатывает функции движка заново, данные не трогает и отдаёт тот же пропуск (created: false). | [Установка и подключение: «Дом, консьерж, квартира и первый жилец»](../install/#ex-install-01-setup-and-connect) |
| setup() отдаёт пропуск консьержа: повторный вызов — тот же пропуск, setup(…, { rotate: true }) — новый, а прежний сразу перестаёт работать (connect по нему — auth_failed). В пропуске — пароль роли консьержа: храните его как секрет; он же лежит в базе и попадает в резервные копии. | [Установка и подключение: «Аварии и конец: новый пропуск и снос дома»](../install/#ex-install-06-rotate-demolish) |
| Режим сигналов хранится в доме: setup() без опции signals его не меняет; после смены — перезапуск процессов. | [Установка и подключение: «Опции setup(): сиды, модели, режим сигналов, правило по умолчанию, жу…»](../install/#ex-install-02-setup-options) |
| demolish() сносит дом целиком: квартиры, данные, историю и роль консьержа. Дом другой ревизии движка setup() не обновляет — его сносят demolish() и строят заново, данные не переносятся. | [Установка и подключение: «Штамп движка: connect() замечает, что дом не обновили»](../install/#ex-install-05-engine-stamp)<br>[Установка и подключение: «Аварии и конец: новый пропуск и снос дома»](../install/#ex-install-06-rotate-demolish) |
| Правило по умолчанию (подходящих правил нет) переключает только мастер-ключ: setup(…, { defaultRule: 'allow' }) или 'deny'; без опции оно не меняется, у свежего дома — deny. Правилом его не изменить и не удалить: acl_denied (sql-access.rule_default_protected).<br>**Ловит код:** `acl_denied` | [Установка и подключение: «Опции setup(): сиды, модели, режим сигналов, правило по умолчанию, жу…»](../install/#ex-install-02-setup-options) |
| Консьерж подключается к PGlite суперпользователем, одним соединением и без LISTEN: права, изоляцию квартир и гонки на нём не проверить — setup({ pglite }) предупреждает об этом в warnings. | [Установка и подключение: «Разработка без PostgreSQL: PGlite»](../install/#ex-install-04-pglite) |
| setup() пишет штамп движка (ревизию и версию пакета) в комментарий схемы дома; connect() предупреждает, если штамп не совпал с пакетом: после обновления пакета не вызвали setup() или дом поставила более новая версия. | [Установка и подключение: «Штамп движка: connect() замечает, что дом не обновили»](../install/#ex-install-05-engine-stamp) |
| С нуля: setup(мастер-ключ, имя, { models }) → connect(pass, { postman }) → db.createTenant(квартира) → (await db.in(квартира)).invite({ email }, ['owner']) → почтальон доставляет ссылку с токеном → db.accept(token, { password }) → данные в корне жильца me. | [Старт с нуля: веб-сервис с пропуском: «С нуля: дом, пропуск, вход по ключу и второй жилец»](../start/#ex-start-01-from-zero) |
| Неизвестная опция setup(), connect(), me.watch() и createMcpServer() — отказ до подключения, с похожими именами в тексте и в err.params.similar: опечатка в опции не проходит молча.<br>**Ловит код:** `invalid_data` | [Ошибки: «Ошибки строгого режима, MCP и квартир»](../errors/#ex-errors-03-strict-mcp-errors) |

## Запись

| Нюанс | Где показан |
|---|---|
| update сливает патч внутри базы: вложенные объекты — рекурсивно, массивы и скаляры заменяются. | [Запись: создать, изменить, заменить: «Создать, изменить, создать-или-заменить»](../write/#ex-write-01-create-update-upsert) |
| update без найденных строк возвращает пустой список без ошибки — проверяйте длину ответа. Фильтр по данным при гонке перепроверяется под блокировкой: из двух одновременных правок одной строки пройдёт одна, вторая получит пустой ответ. Правило «одна открытая запись на объект» так не удержать — его держит ключ; «прочитал — посчитал — записал» — forUpdate() в me.begin() или { rev }. | [Запись: создать, изменить, заменить: «Создать, изменить, создать-или-заменить»](../write/#ex-write-01-create-update-upsert) |
| upsert заменяет данные целиком: поля, которых нет в объекте, пропадают; затирает параллельные приращения. | [Запись: создать, изменить, заменить: «Создать, изменить, создать-или-заменить»](../write/#ex-write-01-create-update-upsert) |
| Концы создаваемой строки берутся из пути цепочки: me.Shop(shop).Product().create() ссылается на shop. | [Запись: создать, изменить, заменить: «Концы: из пути цепочки и вызовами .Роль.set(), .add(), .remove()»](../write/#ex-write-02-ends-and-slots) |
| Шаги концов .Конец.set/unset/add/remove меняют links атомарно, без чтения списка. | [Запись: создать, изменить, заменить: «Концы: из пути цепочки и вызовами .Роль.set(), .add(), .remove()»](../write/#ex-write-02-ends-and-slots) |
| Конец связи не передают полем данных create(): для базы это лишнее поле — invalid_data (в issues — additionalProperties с пустым путём). Конец задают шагом конца после глагола: create({ … }).Конец.set(id). | [Запись: создать, изменить, заменить: «Концы: из пути цепочки и вызовами .Роль.set(), .add(), .remove()»](../write/#ex-write-02-ends-and-slots) |
| inc проверяет ограничение модели (min) для получившегося значения: уход в минус — invalid_data. | [Запись: что внутри: «Счётчики inc и защита от параллельной правки { rev }»](../write/inside#ex-write-03-inc-and-rev) |
| inc по отсутствующему полю — ошибка; inc(n, { start }) начинает с заданного значения. | [Запись: что внутри: «Счётчики inc и защита от параллельной правки { rev }»](../write/inside#ex-write-03-inc-and-rev) |
| Очередь батча своя у каждого корня квартиры и у каждой транзакции me.begin(): план выполняется от имени того корня, через который его поставили в очередь. | [Запись: создать, изменить, заменить: «Батч, теги, владелец и причина изменения»](../write/#ex-write-05-batch-tags-reason) |
| Цели правки сужают limit(), offset() и sort() до глагола. Модификатор сразу после глагола перед rows(), first(), ids(), count() или paths() — ошибка invalid_query, и ничего не записано: глагол уже прошёл по всем целям. В батче так же отказывает run(). | [Запись: создать, изменить, заменить: «Создать, изменить, создать-или-заменить»](../write/#ex-write-01-create-update-upsert)<br>[Запись: создать, изменить, заменить: «Батч, теги, владелец и причина изменения»](../write/#ex-write-05-batch-tags-reason) |
| Перед update() строка или список в .tags(…) и отбирают строки, и заменяют их теги целиком, а оператор (has, hasAny, hasAll) только отбирает — теги остаются прежними. | [Запись: создать, изменить, заменить: «Батч, теги, владелец и причина изменения»](../write/#ex-write-05-batch-tags-reason) |
| hasAll([]) и .tags([]) подходят любой строке (у каждой есть «все теги из пустого списка»), а hasAny([]) и inList([]) — никакой. Пустой список от пользователя перед update() или delete() заденет все строки шага — проверяйте его до запроса. | [Запись: создать, изменить, заменить: «Батч, теги, владелец и причина изменения»](../write/#ex-write-05-batch-tags-reason) |
| Правка многих строк одним оператором пишет их версии в журнал в порядке id, а не в порядке обхода таблицы: журнал одинаков от прогона к прогону. Так же упорядочены пакетная вставка (по порядку входа), загрузка letopis load --existing update и надгробия каскада. | [Запись: что внутри: «Правка многих строк: версии в журнале — в порядке id»](../write/inside#ex-write-07-mass-journal-order) |
| update() и delete({ confirm: true, expect }), у которых ни у одного шага нет фильтра, id, tags(), owner() или limit(), отклоняются до записи: правка прошла бы по всем строкам шага. Все строки — только явно: update(патч, { all: true }), delete({ confirm: true, all: true }); предпросмотр delete() — без условий.<br>**Ловит код:** `invalid_query` | [Ошибки: «Ошибки строгого режима, MCP и квартир»](../errors/#ex-errors-03-strict-mcp-errors) |
| Ключевые поля, класс, id, квартира и владелец строки правкой не меняются — и сырым UPDATE тоже. Объект с другим ключом или классом — новый объект: создать его, перевести на него концы других строк и удалить прежний, одной транзакцией; у нового своя история, у прежнего она остаётся.<br>**Ловит код:** `immutable_key` | [Запись: что внутри: «Ключ и класс неизменны: другой ключ или класс — новый объект»](../write/inside#ex-write-04-key-class-immutable) |

## Удаление и восстановление

| Нюанс | Где показан |
|---|---|
| delete() без { confirm: true } ничего не удаляет — возвращает предпросмотр: что удалится и с каким действием ($action). | [Что такое letopis: «Первый объект: создать, изменить, удалить, вернуть»](../basics/what-is#ex-basics-01-first-object) |
| Действие при удалении, заданное у конца, решает судьбу концов, ведущих на удаляемую цель: cascade — удалить вместе, unset — очистить конец, restrict — отказ delete_restricted. | [Удаление и восстановление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade) |
| restore({ expect }) возвращает только цели шага; строки, удалённые каскадом, возвращают отдельно — по надгробиям этого удаления (ответ delete), с restore({ expect, partial: true }). | [Удаление и восстановление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
| В предпросмотре удаления у строк каскада $action тоже delete: цель от каскада отличает $depth — 0 у самой цели, 1 и дальше у строк каскада; у строк unset и restrict $depth нет. | [Удаление и восстановление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade) |
| Подтверждение удаления — только с предпросмотром, который видел пользователь: delete({ confirm: true }) без expect — отказ invalid_query (write.confirm_without_expect), ничего не удалено; осознанно, без сверки — delete({ confirm: true, all: true }). delete({ confirm: true, expect: предпросмотр }) удаляет ровно показанное: в транзакции удаления строки каскада блокируются, предпросмотр строится заново под блокировкой и сравнивается по id, rev и $action; не совпал — conflict (write.preview_changed), ничего не удалено, новый предпросмотр — в err.detail.preview.<br>**Ловит код:** `invalid_query` | [Удаление и восстановление: «Удаление: предпросмотр, каскад, запрет, очистка конца»](../delete/#ex-delete-01-delete-cascade)<br>[Отмена удаления в веб-сервисе: «Удаление по HTTP: предпросмотр, подтверждение, отмена»](../recipes/undo#ex-delete-03-http-undo)<br>[Первые 15 минут: один процесс: «Прокат: одна выдача на вещь, удаление по предпросмотру и возврат без…»](../first/#ex-first-01-rental) |
| restore({ all: true }) вернул бы все удалённые строки шага — и те, что удалили раньше и отдельно. Строки одного удаления знает ответ delete, а без него их отличает причина: надгробия цели и её каскада получают reason этого удаления — отберите их по ней и верните restore({ expect: надгробия }). Причину делайте своей для каждого удаления. | [Удаление и восстановление: «Вернуть удалённое»](../delete/#ex-delete-02-restore) |
