# Сервисы-примеры

Четыре веб-приложения, построенные на letopis. Каждое запускается на вашей машине — в Docker или без него — и показывает, как библиотека работает в настоящем сервисе. Вместе они охватывают основные возможности letopis.

| Сервис | Что делает | Что из letopis показывает |
|---|---|---|
| [Салон записи](./salon) | салоны, мастера, услуги, расписание, бронь, перенос, отмена | готовая модель из сида, чтение цепочками, запись без двойной брони, перенос брони новой бронью и удалением прежней, живое обновление расписания, история брони |
| [Кошелёк и биллинг](./wallet) | счета, пополнение, списания, переводы, выписка | деньги без двойного списания, транзакции, баланс приращением `inc` в плане операции, обрыв связи на COMMIT, выписка обычным запросом |
| [Helpdesk](./helpdesk) | компании, заявки, агенты и клиенты, ИИ-помощник | квартиры и приглашения, матрица прав по ролям, вход паролем, кодом из письма и с TOTP, ключи API, живое обновление очереди, MCP |
| [Документы с аудитом](./documents) | договоры, версии, подписание, корзина, архив | история и срез на любой момент, подписание — новый объект одной транзакцией, удаление с предпросмотром и восстановление, архив первой заливкой с историей |

## Как устроен каждый сервис

У каждого сервиса свой **дом**. Его строит шаг подготовки `src/setup.mjs` — `setup()` мастер-ключом (строкой подключения администратора PostgreSQL, переменная `ADMIN_DSN`): модель или сид, режим сигналов, у документов — ещё архив. Подготовка отдаёт **пропуск** консьержа, и сервис знает только его (`LETOPIS_PASS`): мастер-ключа у работающего сервиса нет. При старте сервис подключается консьержем — `connect(pass)` — и заводит демо-квартиры и их жильцов: `createTenant`, приглашение, принятие приглашения; повторный запуск ничего не дублирует.

Вход — ключом жильца: `db.open({ email, password })` (в helpdesk — ещё код из письма и TOTP). Демо-жильцов с известными паролями заводит подготовка дома каждого сервиса (`src/setup.mjs`): консьерж зовёт их, почтальон-заглушка получает ссылку, подготовка тут же принимает приглашение. Токен сессии лежит в cookie, и каждый запрос открывает по нему корень квартиры — `db.resume(token)`; все цепочки идут от этого корня и под правами вошедшего. Выход гасит сессию (`me.close()`) и закрывает потоки живого обновления этой вкладки. Общее у четырёх сервисов лежит в `services/shared/`: дом и демо-жильцы (`house.mjs`), веб-сессии по cookie (`sessions.mjs`), подписка → поток SSE (`events.mjs`) и журнал панели «Под капотом» (`trace.mjs`).

## Как запустить {#run}

Сервисы — не часть npm-пакета: их код, `services/compose.yaml` и скрипты запуска лежат в репозитории. Общий первый шаг для всех четырёх — получить исходники и перейти в корень клона:

```sh
git clone https://github.com/alepri51/letopis
cd letopis
```

Дальше — из корня клона:

- **в Docker** (нужен Docker с Compose): `docker compose -f services/compose.yaml up --build <сервис>`, где сервис — `salon`, `wallet`, `helpdesk` или `documents`. Тем же файлом поднимаются база PostgreSQL 18 и шаг подготовки `<сервис>-setup`: он строит дом мастер-ключом и кладёт пропуск в общий том, откуда его читает сервис;
- **руками, без Docker для сервиса** (нужны Node 22 и PostgreSQL 18): база — `docker compose -f services/compose.yaml up -d pg` или своя (её мастер-ключ — в `ADMIN_DSN`), затем `services/<сервис>/run-local.sh`: скрипт соберёт библиотеку, поставит зависимости, соберёт интерфейс, построит дом (`node src/setup.mjs`) и запустит сервис с одним пропуском. Шаги по отдельности и команды для PowerShell — в `services/<сервис>/README.md`.

**Порты и имя стенда.** Все порты открыты только на 127.0.0.1. По умолчанию: база — 15440, сайт с песочницей — 8080, салон — 8081, кошелёк — 8082, helpdesk — 8083, документы — 8084; имя проекта Compose — `letopis-guide`. Если порт занят или такой стенд уже запущен, задайте своё имя проекта (`-p`) и свои порты переменными `PG_PORT`, `GUIDE_PORT`, `SALON_PORT`, `WALLET_PORT`, `HELPDESK_PORT`, `DOCUMENTS_PORT`:

```sh
SALON_PORT=18081 PG_PORT=25440 docker compose -p my-letopis -f services/compose.yaml up --build salon
```

PowerShell:

```powershell
$env:SALON_PORT = '18081'; $env:PG_PORT = '25440'; docker compose -p my-letopis -f services/compose.yaml up --build salon
```

С другим `-p` у стенда свои контейнеры и своя база (том данных), прежний стенд не затрагивается; останавливать — с тем же `-p`: `docker compose -p my-letopis -f services/compose.yaml down`. Адрес сервиса — `http://127.0.0.1:<порт>`; дальше на страницах сервисов он назван «адрес сервиса». Свой пропуск сервису в Docker — переменная `SALON_PASS`, `WALLET_PASS`, `HELPDESK_PASS` или `DOCUMENTS_PASS` (тогда пропуск из шага подготовки не читается).

Адрес по умолчанию, демо-входы и что смотреть — на странице сервиса.
