# Несколько квартир

## Зачем

Один человек может жить в нескольких квартирах: работать в двух компаниях или вести два магазина. Рецепт показывает, как с этим жить приложению: как позвать человека во вторую квартиру, как он выбирает, куда войти, как меняет контакт и как уходит из одной квартиры, оставаясь в другой.

## Что нужно знать заранее

| Что | Сколько | Пояснение |
|---|---|---|
| аккаунт | один на весь дом | человек — один, сколько бы квартир у него ни было |
| контакт | один на аккаунт | почта или телефон; он же **имя для входа** |
| прописка | своя в каждой квартире | со своими **ролями** — метками прописки (`owner`, `staff`) |
| пароль | свой в каждой квартире | пароли одного человека в разных квартирах обязаны различаться |
| код из письма | один на контакт | подходит к любой квартире человека: её выбирают после кода |

```text
 аккаунт «Олег»  ── контакт +79991112233
   ├─ прописка в «Мире»:   роль owner   · пароль «Мир-2026!»
   └─ прописка в «Весне»:  роль owner   · пароля нет — вход кодом
```

Письма в рецепте доставляет **почтальон** — функция приложения; здесь это заглушка, которая складывает письма в массив `mail`. Откуда он берётся — [«Приглашения и почтальон»](../invites/).

## Позвать человека во вторую квартиру

Вызовы те же, что для нового человека. Приглашение уходит на тот же контакт — библиотека сама находит аккаунт.

```ts
await db.createTenant('Весна')
await (await db.in('Весна')).invite({ phone: '+79991112233' }, ['owner'])   // тот же контакт, что в «Мире»

const token = lastLetter('+79991112233', 'invite').token   // в приложении токен приходит из ссылки
console.log((await db.invitation(token)).hasAccount)       // true — у контакта уже есть аккаунт
const olegSpring = await db.accept(token)                  // тот же аккаунт прописан в «Весне»
```

| Вопрос | Ответ |
|---|---|
| нужно ли человеку сначала войти? | нет: хватает ссылки |
| заведётся ли второй аккаунт? | нет, если контакт тот же. Позвали на другой адрес — будет второй аккаунт: библиотека не знает, что это тот же человек |
| можно ли задать пароль? | да: `db.accept(token, { password })`. Он должен отличаться от паролей человека в других квартирах, иначе `invalid_data` (ключ `api.password_reused`); ссылка при этом жива |
| а если пароль не задан? | человек входит в эту квартиру кодом из письма |
| можно ли сразу править ключи? | нет: сессия из `accept` у существующего аккаунта — не «недавний вход». Сначала вход паролем или кодом |

## Вход: в какую квартиру

**Паролем** — квартиру выбирает сам пароль:

```ts
const me = await db.open({ phone: '+79991112233', password: 'Мир-2026!' })
console.log(me.tenantName)   // Мир — пароль от «Мира»
```

**Кодом** — после кода человек видит свои квартиры и выбирает:

```text
 db.requestCode({ phone })            ──▶ почтальон: письмо с кодом
 db.tenantsOf({ phone, code })     ──▶ [ { id, name: 'Весна' }, { id, name: 'Мир' } ]     код не гасится
 db.open({ phone, code, tenant })  ──▶ me в выбранной квартире                            код погашен
```

```ts
await db.requestCode({ phone: '+79991112233' })
const code = lastLetter('+79991112233', 'code').code                 // в приложении код вводит человек

const tenants = await db.tenantsOf({ phone: '+79991112233', code })  // [{ id, name }, …]
// показать список; человек выбрал «Весну»
const spring = await db.open({ phone: '+79991112233', code, tenant: 'Весна' })
```

| Случай | Что будет |
|---|---|
| квартира одна | `tenant` не нужен: `db.open({ phone, code })` |
| квартир несколько, `tenant` не задан | отказ `tenant_required`; список квартир — в `err.detail.tenants`; код не гаснет, можно повторить с `tenant` |
| `tenant` — квартира, где человек не прописан | `auth_failed` (ключ `api.code_failed`) |
| код неверный | `auth_failed` (ключ `api.code_failed`); пять неверных вводов гасят код |

`tenant` — имя квартиры или её id. В форме с выбором надёжнее отправлять id. Тот же путь с пошаговым показом базы — [пример «Вход кодом»](../auth/#ex-auth-05-code-login).

## Перейти из квартиры в квартиру

«Переключения» квартиры нет: каждая сессия открыта в одной квартире. Чтобы человек работал в двух, приложение держит две сессии — два токена.

```ts
console.log((await mir.Note().rows()).map((n) => n.data.text))      // [ 'заметка «Мира»' ]
console.log((await spring.Note().rows()).map((n) => n.data.text))   // [ 'заметка «Весны»' ]
```

- Два корня квартиры живут в одном процессе одновременно и друг другу не мешают.
- В веб-приложении — по токену на квартиру: например, cookie `sid_<id квартиры>` или один список токенов в серверной сессии. Для запроса берут токен нужной квартиры и вызывают `db.resume(токен)`.
- Вторую сессию открывают обычным входом: паролем той квартиры или кодом с `tenant`. Из одной сессии другую не получить — так чужой токен одной квартиры не откроет остальные.

## Сменить контакт

Контакт у аккаунта один, поэтому меняется он сразу для всех квартир. Код приходит на **новый** адрес — так человек доказывает, что адрес его.

```ts
await spring.changeContact({ phone: '+79990001122' })                       // 1. код — на новый номер
const check = lastLetter('+79990001122', 'contact').code                    //    в приложении код вводит человек
const changed = await spring.changeContact({ phone: '+79990001122', code: check })   // 2. подтвердить
console.log(changed.contact)   // { kind: 'phone', address: '+79990001122' }
```

| Что | Как после смены |
|---|---|
| имя для входа | новый контакт — во всех квартирах |
| пароли | прежние: `db.open({ phone: '+79990001122', password: 'Мир-2026!' })` |
| прежний контакт | больше не открывает ничего: `auth_failed` |
| новый контакт занят другим аккаунтом | отказ `exists` (ключ `sql-access.identifier_taken`) на втором шаге |
| кто может | только сам жилец, не позже 10 минут после входа паролем или кодом; иначе `acl_denied` (ключ `sql-access.bind_denied`) |

::: warning После смены зовите на новый адрес
Старый адрес больше не связан с аккаунтом. Приглашение на него заведёт **второй аккаунт** — с тем же человеком, но без его квартир: `db.invitation(token).hasAccount` ответит `false`. Сообщите новый контакт тем, кто зовёт людей, и в своих списках сотрудников храните id аккаунта (`me.account`), а не адрес.
:::

Пошагово, с занятым контактом и отказом без недавнего входа, — [пример «Смена контакта и имени»](../auth/#ex-auth-06-change-contact).

## Выписаться из одной квартиры

```ts
await spring.leave()            // Олег ушёл из «Весны»; «Мир» не тронут
```

| Что | После `leave()` |
|---|---|
| прописка в этой квартире | удалена |
| ключи и сессии этой квартиры | погашены; корень отвечает `no_session` |
| данные, которые он создал | остаются квартире |
| другие квартиры | без изменений: прописки, пароли, сессии |
| аккаунт | остаётся; вернуться в квартиру — по новому приглашению |

**Последний owner уйти не может** — отказ `last_owner`: квартира осталась бы без хозяина. Сначала роль `owner` получает другой жилец (приглашением или `me.acl.roles(аккаунт, ['owner'])`), потом можно уходить.

Выписать другого человека — `me.acl.roles(аккаунт, null)`: нужен жилец, которому матрица разрешает удалять `member` и снимать роли выписываемого; у owner это есть.

## Всё вместе одной программой

Нужны PostgreSQL 18 и пакеты — [как запустить](/#run). Сохраните как `rooms.ts`, запустите `npx tsx rooms.ts`. Программа строит дом `rooms` заново при каждом запуске.

<!-- rooms.ts -->
```ts
import { setup, demolish, connect, LetopisError, type Letter } from 'letopis'
import { hub } from 'letopis/model'
import { z } from 'zod'

const ADMIN_DSN = process.env.ADMIN_DSN ?? 'postgres://postgres:guide@127.0.0.1:15440/letopis'
const HOUSE = 'rooms'
const Note = hub('Note', { text: z.string() })

// Почтальон-заглушка: письма — в массив; из него берём токен приглашения и код.
const mail: Letter[] = []
const postman = async (letter: Letter) => { mail.push(letter) }
const lastLetter = <K extends Letter['message']['kind']>(address: string, kind: K) => {
  const m = mail.findLast((l) => l.to.address === address && l.message.kind === kind)?.message
  if (!m) throw new Error(`письма ${kind} на ${address} нет`)
  return m as Extract<Letter['message'], { kind: K }>
}

await demolish(ADMIN_DSN, HOUSE, { quiet: true })
const { pass } = await setup(ADMIN_DSN, HOUSE, { models: [Note], quiet: true })
const db = await connect(pass, { postman })

console.log('1. Олег — хозяин «Мира»: новый аккаунт, пароль от «Мира»')
await db.createTenant('Мир')
await (await db.in('Мир')).invite({ phone: '+79991112233' }, ['owner'])
const olegMir = await db.accept(lastLetter('+79991112233', 'invite').token, { password: 'Мир-2026!', name: 'Олег' })
await olegMir.Note().create({ text: 'заметка «Мира»' }).rows()

console.log('2. Олега зовут в «Весну»: аккаунт уже есть, пароль не задаём')
await db.createTenant('Весна')
await (await db.in('Весна')).invite({ phone: '+79991112233' }, ['owner'])
const olegSpring = await db.accept(lastLetter('+79991112233', 'invite').token)
await olegSpring.Note().create({ text: 'заметка «Весны»' }).rows()
console.log('   аккаунт один:', olegSpring.account === olegMir.account)

console.log('3. Вход паролем: пароль сам выбирает квартиру')
const mir = await db.open({ phone: '+79991112233', password: 'Мир-2026!' })
console.log('   вошёл в:', mir.tenantName)

console.log('4. Вход кодом: код → список квартир → выбор')
await db.requestCode({ phone: '+79991112233' })
const code = lastLetter('+79991112233', 'code').code
const tenants = await db.tenantsOf({ phone: '+79991112233', code })
console.log('   квартиры:', tenants.map((t) => t.name))
try {
  await db.open({ phone: '+79991112233', code })                        // квартир две, а какая — не сказано
} catch (e) {
  if (!(e instanceof LetopisError) || e.code !== 'tenant_required') throw e
  console.log('   без tenant:', e.code, (e.detail as { tenants: { name: string }[] }).tenants.map((t) => t.name))
}
const spring = await db.open({ phone: '+79991112233', code, tenant: 'Весна' })
console.log('   вошёл в:', spring.tenantName)

console.log('5. Два корня квартиры сразу: у каждого свои данные')
console.log('   Мир:', (await mir.Note().rows()).map((n) => n.data.text))
console.log('   Весна:', (await spring.Note().rows()).map((n) => n.data.text))

console.log('6. Смена контакта: код приходит на новый номер')
await spring.changeContact({ phone: '+79990001122' })
const changed = await spring.changeContact({ phone: '+79990001122', code: lastLetter('+79990001122', 'contact').code })
console.log('   новый контакт:', changed.contact)
const again = await db.open({ phone: '+79990001122', password: 'Мир-2026!' })   // пароль прежний, имя для входа — новое
console.log('   вход по новому номеру:', again.tenantName)
await db.open({ phone: '+79991112233', password: 'Мир-2026!' }).catch((e) => console.log('   старый номер:', e.code))

console.log('7. Выписка из «Весны»: «Мир» остаётся')
await db.createTenant('Лето')                                           // в «Лете» Олег — единственный owner
await (await db.in('Лето')).invite({ phone: '+79990001122' }, ['owner'])
const olegSummer = await db.accept(lastLetter('+79990001122', 'invite').token)
await olegSummer.leave().catch((e) => console.log('   последний owner «Лета»:', e.code))
await (await db.in('Весна')).invite({ email: 'vera@vesna.ru' }, ['owner'])      // в «Весне» появляется вторая хозяйка
await db.accept(lastLetter('vera@vesna.ru', 'invite').token, { name: 'Вера' })
await spring.leave()
await db.requestCode({ phone: '+79990001122' })
console.log('   квартиры после выписки:', (await db.tenantsOf({ phone: '+79990001122', code: lastLetter('+79990001122', 'code').code })).map((t) => t.name))
await spring.Note().rows().catch((e) => console.log('   корень выписанного:', e.code))

await db.close()
process.exit(0)
```

## Подводные камни

- **Один человек — один контакт.** Позвали на другой адрес — получился второй аккаунт. Склеить два аккаунта нельзя: зовите на тот контакт, которым человек уже входит.
- **Один пароль на две квартиры задать нельзя** (`api.password_reused`). Не хотите заставлять человека помнить два пароля — не задавайте пароль во второй квартире: пусть входит кодом.
- **Код без `tenant` при нескольких квартирах — отказ `tenant_required`**, а не вход в случайную. Список для выбора — в `err.detail.tenants` или из `db.tenantsOf`.
- **Список квартир — только после верного кода.** По одному контакту узнать, где человек прописан, нельзя.
- **Сессия — на одну квартиру.** Не храните «текущую квартиру» в параметрах запроса: её помнит сама сессия (`me.tenant`, `me.tenantName`).
- **Смена контакта задевает все квартиры.** Предупредите человека: прежний адрес перестанет работать везде.
- **Последний owner не уходит** (`last_owner`) и не удаляет аккаунт.
- **Удаление аккаунта — это уход из всех квартир сразу**: `me.deleteAccount()`. Из одной — `me.leave()`.
