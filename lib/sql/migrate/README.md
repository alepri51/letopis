# Миграции схемы letopis 2.x

`up({ upgrade: true })` применяет файлы этого каталога к схеме отставшей ревизии 2.x: в транзакции наката, под
блокировкой схемы и от роли владельца, до повторного наката файлов ядра (`lib/src/up.ts`: `install`, `migrationFiles`).

- Имя — `NNNN-описание.sql`: четыре цифры — номер ревизии, к которой ведёт миграция, затем дефис и строчные латинские
  буквы, цифры, точки и дефисы (`^\d{4}-[a-z0-9.-]+\.sql$`). Файлы с другим именем, как этот, установщик пропускает.
- Номер миграции — новая ревизия движка: тот же номер — `DDL_REVISION` в `lib/src/types.ts` и `ddl_revision` в
  `lib/sql/99-revision.sql` (их сверяет `npm run check:docs`).
- Применяются миграции с номером выше ревизии схемы и не выше `DDL_REVISION`, по возрастанию номера. Подстановки — как
  у файлов ядра (`@SCHEMA@`, `@OWNER@` и другие — таблица в `lib/sql/README.md`).
- В миграцию идёт только то, чего не догонит повторный накат: колонка или ограничение существующей таблицы, перенос
  данных. Функции, индексы, триггеры и политики ставят файлы ядра.
- У 2.0 миграций нет: ревизия 8 — первая ревизия 2.x. Схему letopis 1.x (ревизия 7 и ниже) 2.0 не обновляет —
  `up({ fresh: true })` ставит её заново, данные 1.x не переносятся.
