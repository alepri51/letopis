# letopis на живом полигоне: один день сети салонов

Это не референс и не README — это **прогон**. Мы засеяли миллион строк по доменной
схеме сети салонов красоты и провели сквозь неё один рабочий день: открыли салон,
собрали каталог, наняли мастеров, приняли брони, переставили исполнителей, отменили
запись, посчитали отчёты, пустили клиентов по паролю и токену, раздали права. Каждый
вызов API ниже — **реальный**, с ответом прямо из PostgreSQL и временем на живой БД.

Воспроизвести целиком:

```bash
node lib/bench/salon-seed.mjs          # засеять полигон v1.salondemo (~1M строк, ~3 мин)
node lib/bench/salon-article-demo.mjs  # снять все ответы этой статьи
```

Тест-план, по которому построен рассказ, — `lib/TESTPLAN.md` (21 акт, 145 точек API);
исполняемая версия — `lib/test/salon.test.ts`.

## Полигон

`salon-seed.mjs` детерминированным генератором (`mulberry32`) наполняет схему
`v1.salondemo` за год «истории» — 30 салонов, каталоги, мастера, 40 000 клиентов,
240 000 записей с двумя версиями каждая, позиции, занятости. Bulk-INSERT напрямую в
`Entity`; каждая строка проходит серверный триггер целостности `entity_check` — то есть
**весь миллион валиден по схеме `Schema.links` v2** (иначе INSERT бы отклонился).

Распределение классов (`SELECT class, count(*) … GROUP BY class`):

| Класс | Строк | | Класс | Строк |
|---|--:|---|---|--:|
| `Booking` (Запись) | 480 000 | | `Slot` (Окно) | 9 000 |
| `item` (позиция) | 240 000 | | `skill` (навык) | 3 000 |
| `busy` (занятость) | 240 000 | | `shift` (смена) | 1 500 |
| `Customer` (Клиент) | 40 000 | | `Service` (Услуга) | 1 200 |
| … | | | `compo` (состав) | 240 |

**Итого 1 015 630 строк.** `Booking` вдвое больше `item` — потому что у каждой брони
две версии (`created` → `confirmed`/`completed`/`cancelled`/`no_show`): append-only
хранит их обе, актуальная — с максимальным `updated`.

### Доменная схема (`Schema.links` v2)

Связи объявлены не строками, а объектами-концами — с союзами ролей и опциональностью:

```
позиция  [Booking, Service|Complex, Staff?]   ← строка заказа: бронь × (услуга|комплекс) × мастер?
состав   [Complex, Service]                    ← состав комплекса
навык    [Staff, Service|Complex]              ← мастер умеет (услугу|комплекс)
смена    [Schedule, Staff]                      занятость [Staff, Slot, Booking?]
```

`Service|Complex` — «ровно один из»: предмет позиции — либо услуга, либо комплекс,
никогда оба. `Staff?` — исполнитель необязателен (позиция «любой мастер» до назначения).
Триггер БД валидирует это на каждой вставке, даже в обход библиотеки.

### Грамматика в трёх правилах

Весь язык letopis держится на трёх формах свойства-класса:

```ts
Класс(фильтр?)   // ВЫЗОВ — навигация по пути; повтор LINK-класса = возврат к узлу (pivot)
Класс            // СЛОТ  — связь: .Класс.set(x) записать конец, .Класс.delete() снять
set / delete     // ГЛАГОЛ — операция; исполняет ТЕРМИНАЛ (rows/first/count/run/…)
```

Путь всегда подчиняется переходам схемы — и при чтении, и при записи. Дальше — как это
играет на живом дне салона.

## Акт 1. Открытие: создание сущностей и батч

Заводим салон и двух мастериц. `set()` — звено плана; исполняет терминал `.rows()`:

```ts
const [org] = await db.Организация()
  .set({ name: 'Салон «Пример»', phone: '+7 495 0000000', timezone: 'Europe/Moscow' }).rows()
```
```jsonc
// [37.3 ms] → defaults (active, timezone) подставлены из Schema
{ "id": "…0010", "class": "Org",
  "data": { "name": "Салон «Пример»", "phone": "+7 495 0000000", "active": true, "timezone": "Europe/Moscow" },
  "links": {} }
```

Двух мастеров — батчем. `batch` копит планы и шлёт одной транзакцией; чистые INSERT
одного класса склеиваются в multi-VALUES:

```ts
const b = db.batch('setup')
b.Организация(org).Сотрудник().set({ name: 'Ольга', roles: ['owner', 'master'] })
b.Организация(org).Сотрудник().set({ name: 'Ирина', roles: ['master'] })
b.size()            // → 2
await b.run()       // [28.0 ms]
```
```jsonc
[ { "id": "…0011", "class": "Staff", "data": { "name": "Ольга", "roles": ["owner","master"], "active": true },
    "links": { "Org": "…0010" } },
  { "id": "…0012", "class": "Staff", "data": { "name": "Ирина", "roles": ["master"], "active": true },
    "links": { "Org": "…0010" } } ]
```

Владелец `Org` попал в `links` мастера **из пути** — `Организация(org)` первым шагом.
Это ключевой принцип 0.15.0: владельца связки задаёт путь, прочие концы — слотами.

## Акт 2. `up()`: вход одной функцией

Второй способ подключиться — `up()`: на живой БД он пропускает docker и просто
подключается к той же схеме.

```ts
const db = await up({ schema: 'salondemo', version: 1 })   // [101.5 ms]
await db.Организация().count()                              // → 31  (30 полигона + наш «Пример»)
```

## Акт 3. Каталог: дерево папок, услуги, состав комплекса

Папки вложены сами в себя (`Папка→Папка`), услуга живёт под папкой — всё валидным путём:

```ts
const [стрижка] = await db.Организация(org).Папка(волосы).Услуга()
  .set({ name: 'Стрижка', duration: 60, price: { RUB: 1500 } }).rows()
```
```jsonc
// [18.9 ms] — оба конца (Org, Folder) из пути
{ "id": "…0030", "class": "Service",
  "data": { "name": "Стрижка", "price": { "RUB": 1500 }, "active": true, "duration": 60 },
  "links": { "Org": "…0010", "Folder": "…0021" } }
```

Комплекс «Образ» и его состав. Владелец состава (`Комплекс`) — из пути, предмет
(`Услуга`) — **слотом** `.Услуга.set(...)`:

```ts
await db.Комплекс(набор).состав().set({ qty: 1 }).Услуга.set(стрижка).rows()
await db.Комплекс(набор).состав().set({ qty: 1 }).Услуга.set(укладка).rows()

await db.Комплекс(набор).состав().Услуга().rows()   // [6.8 ms] чтение состава
// → ["Стрижка", "Укладка"]

await db.Организация(org).Папка(корень).Папка().deep().rows()   // [10.5 ms] вся ветка
// → ["Волосы"]
```

`deep()` — рекурсивный обход детей того же класса: показывает всю иерархию папок от корня.

## Акт 4. Навыки: слоты, союз-конец и pivot

Мастер умеет услуги и комплексы — `навык` с союзным предметом `Service|Complex`:

```ts
await db.Сотрудник(ольга).навык().set({}).Услуга.set(стрижка).rows()
await db.Сотрудник(ольга).навык().set({}).Комплекс.set(набор).rows()   // тот же слот, другой класс союза

await db.Сотрудник(ольга).навык().Услуга().rows()   // [8.1 ms] → ["Стрижка", "Укладка"]
await db.Сотрудник(ольга).навык().Комплекс().count()                    // → 1
```

А как спросить «умеет ли Ирина бороду», если от навыка до конкретной услуги фильтровать
нужно, а вернуться к навыку — чтобы посчитать? Это **pivot**: повтор LINK-класса
возвращает к тому же узлу.

```ts
await db.Сотрудник(ирина).навык().Услуга(борода).навык().count()   // [8.8 ms] → 1  (умеет)
await db.Сотрудник(ирина).навык().Услуга(укладка).навык().count()  //         → 0  (не умеет)
```

Читается как фраза: «у Ирины — навык — на бороду — этот навык — посчитать». Одна
линейная цепочка описала граф-паттерн «навык, ведущий к конкретной услуге».

## Акт 5. Расписание: окна батчем, ростер

Восемь часовых окон дня — батчем; ростер — смены слотом:

```ts
for (let h = 10; h < 18; h++) wb.Расписание(расп).Окно().set({ start: iso(h), end: iso(h+1) })
await wb.run()                                                     // [65.2 ms] → 8 окон

await db.Расписание(расп).смена().set({}).Сотрудник.set(ольга).rows()
await db.Расписание(расп).смена().Сотрудник().rows()   // [8.1 ms] → ["Ольга", "Ирина"]
```

## Акт 6. Первая бронь: транзакция + advisory-lock

Аня записывается к Ольге на 10:00. Всё в одной транзакции с межпроцессным локом на пару
(мастер, окно) — чтобы двойная бронь была невозможна:

```ts
const tr = await db.begin()
await tr.lock('busy', ольга.id, окно10.id)
const [зап] = await tr.Клиент(аня).Запись().set({ status: 'created', source: 'online', total: { RUB: 1500 } }).rows()
await tr.Запись(зап).позиция().set({ qty: 1, price: { RUB: 1500 } }).Услуга.set(стрижка).Сотрудник.set(ольга).rows()
await tr.Сотрудник(ольга).занятость().set({ kind: 'booking' }).Окно.set(окно10).Запись.set(зап).rows()
await tr.commit()                                                  // [30.9 ms] весь блок
```
```jsonc
// запись:
{ "id": "…0120", "class": "Booking", "data": { "total": { "RUB": 1500 }, "source": "online", "status": "created" },
  "links": { "Customer": "…0110" } }
// позиция собрала три конца — владельца из пути (Booking) + два слота:
// links → { "Staff": "…0011", "Booking": "…0120", "Service": "…0030" }
```

Одна позиция — три связи, и каждая пришла своим путём: `Booking` из шага `Запись(зап)`,
`Service` и `Staff` — слотами. Занятость точно так же: владелец `Staff` из пути, `Slot` и
`Booking` — слотами.

## Акт 8. Комбо-запись: мульти-мастер

«Четыре руки»: одна запись — стрижка у Ольги и борода у Ирины одновременно:

```ts
await db.Запись(зКомбо).позиция().set({ qty: 1, price: { RUB: 1500 } }).Услуга.set(стрижка).Сотрудник.set(ольга).rows()
await db.Запись(зКомбо).позиция().set({ qty: 1, price: { RUB: 800 } }).Услуга.set(борода).Сотрудник.set(ирина).rows()

await db.Запись(зКомбо).позиция().count()               // → 2
await db.Запись(зКомбо).позиция().Сотрудник().rows()    // [6.4 ms] → ["Ольга", "Ирина"]
```

## Акт 9. Операции дня: перевес, союз-замена, снятие связи

Ольга заболела — её позиции в комбо-записи переходят к Ирине. Цель ищется путём с pivot
(«позиции этой записи, где мастер Ольга»), слот пишет нового исполнителя **без участия в
фильтре**:

```ts
await db.Запись(зКомбо).позиция().Сотрудник(ольга).позиция().set({}).Сотрудник.set(ирина).rows()
```
```jsonc
// [18.0 ms] — новая версия позиции, Staff перевешен:
[ { "id": "…0131", "class": "item", "data": { "qty": 1, "price": { "RUB": 1500 } },
    "links": { "Staff": "…0012", "Booking": "…0121", "Service": "…0030" } } ]
// версий позиции → 2  (создание + перевес; история цела)
```

Клиент передумал и берёт вместо стрижки комплекс. Предмет — союзный конец
`Service|Complex`, слот замещает его **целиком** (старый класс снимается сам):

```ts
await db.позиция(поз).Комплекс.set(набор).rows()
// links → { "Staff": "…0011", "Booking": "…0120", "Complex": "…0040" }   (Service снят!)
```

А занятость мастера отвязываем от брони (`Booking?` — optional-конец):

```ts
await db.занятость(bz).set({ kind: 'hold' }).Запись.delete().rows()
// links → { "Slot": "…0090", "Staff": "…0011" }   (Booking убран)
```

## Акт 10. Отмена: сначала превью, потом удаление

`delete()` без подтверждения — **превью**: показывает всё, что уйдёт каскадом, но БД не
трогает. Так можно спросить «что удалится?» до необратимого шага:

```ts
await db.Запись(зКомбо).delete().rows()             // [18.0 ms] — БД НЕ тронута
// → [{ class: "Booking" }, { class: "item" }, { class: "item" }]   $deleted отсутствует

await db.Запись(зКомбо).delete({ confirm: true }).rows()   // [33.2 ms]
// удалено 3 строки (запись + две позиции), каждая с $deleted: true
await db.Запись(зКомбо).count()                     // → 0
```

## Акты 12–13. Отчёты на миллионе строк

Здесь чтения идут по **всему полигону** — 1 200 версий услуг, 480 000 записей. Тайминги
живые.

**Все 18 операторов фильтра** (`count()` на классе `Услуга`, ~600 уникальных):

```ts
db.Услуга({ duration: ne(60) }).count()        // [5.0 ms] → 452
db.Услуга({ duration: between(30, 45) }).count()          // → 302
db.Услуга({ name: ilike('массаж 7') }).count()            // → 30
db.Сотрудник({ roles: hasAll(['owner','master']) }).count()   // → 31
db.Услуга({ description: isNull() }).count()              // → 602
db.Услуга(or({ name: 'Стрижка 0' }, { duration: lt(40) })).count()   // → 152
```

Полный список отработал: `ne` 452, `gt(45)` 301, `gte(45)` 451, `lt(45)` 152,
`between` 302, `inList` 60, `like` 60, `starts('Спа')` 60, `has('owner')` 31,
`hasAny` 91, `not(ilike)` 542. GIN-индексы по `data`/`tags` держат это в единицах
миллисекунд.

**Агрегации** — считает БД, не приложение:

```ts
db.Услуга().count()                    // [3.1 ms] → 603   (уникальные сущности)
db.Услуга().sum('data.price.RUB')      // [4.8 ms] → 1 218 200
db.Услуга().avg('data.duration')       //         → 52.4
db.Услуга().min('data.duration')       // → 30    max → 75
db.Услуга().countBy('data.duration')   // [3.0 ms] → { "30": 152, "45": 150, "60": 151, "75": 150 }
```

Разница `count()` vs `sum(price)`: агрегация берёт **актуальные** версии, старые версии
цен в сумму не попадают — append-only не искажает отчёт.

Самый тяжёлый запрос дня — пересчёт всех записей:

```ts
db.Запись().count()   // [1686.1 ms] → 240 001
```

Полторы секунды на 480 000 версий-строк — честный full-scan класса с вычислением
актуальной версии каждой из 240 000 записей. Точечные пути (акты выше) — единицы
миллисекунд; дорого стоит только «посчитать вообще всё».

**Keyset-пагинация** — страница за страницей по возрастанию цены, без `OFFSET`:

```ts
const p1 = await db.Услуга().sort('data.price.RUB').limit(3).rows()   // [9.7 ms]
// → Борода 800, Стрижка 10 900, Стрижка 0 900
const cur = cursorOf(p1[p1.length - 1], 'data.price.RUB')
const p2 = await db.Услуга().sort('data.price.RUB').after(cur).limit(3).rows()   // [15.2 ms]
// следующая тройка — строго после курсора, без пропусков и дублей на границе
```

## Акт 14. Машина времени

Услуга «Борода» дорожает с 800 до 1000 ₽. Обе цены остаются в истории:

```ts
await db.Услуга(борода).set({ price: { RUB: 1000 } }).rows()
db.Услуга(борода).first()                    // цена сейчас → 1000
db.Услуга(борода).asOf(доПодорожания).first() // цена тогда → 800
db.Услуга(борода).versions()                  // [6.2 ms]
// → [ { RUB: 800, updated: "…14:01:52" }, { RUB: 1000, updated: "…14:01:55" } ]
```

## Акт 16. Приватность (GDPR)

`anonymize()` затирает персональные поля новой версией и метит тегом — но **история
цела**, старая версия хранит настоящее имя (для аудита это важно):

```ts
await db.Клиент(id).anonymize(['name', 'contact']).rows()   // [11.9 ms]
// data → { name: "[erased]", contact: "[erased]", … }, tags → ["anonymized"]
db.Клиент(id).versions()[0].data.name   // → "Пётр Удаляев"  (первая версия нетронута)
```

## Акт 17. Вход: шесть способов аутентификации

Все механики `db.auth` на живых scrypt/sha256/TOTP/OTP:

```ts
await db.auth.setPassword({ account, identifier: 'olga@salon.ru', password: 'Secr3t!' })
await db.auth.verifyPassword({ identifier: 'olga@salon.ru', password: 'Secr3t!' })   // [60.1 ms] → account
await db.auth.verifyPassword({ identifier: 'olga@salon.ru', password: 'x' })         //          → null

const { key } = await db.auth.issueApiKey({ account, name: 'касса' })   // → lts_6f215403…
await db.auth.verifyApiKey(key)                                         // → account (в БД только sha256)

const totp = await db.auth.enrollTotp({ account, issuer: 'Пример' })
db.auth.totpEnabled(account)                              // → false (до первой проверки)
db.auth.verifyTotp({ account, code: totpCode(totp.secret) })   // → true → фактор активирован

const otp = await db.auth.issueOtp({ account, identifier: '+7 900 111' })
db.auth.verifyOtp({ identifier: '+7 900 111', code: otp.code })   // → account
db.auth.verifyOtp({ identifier: '+7 900 111', code: otp.code })   // → null (одноразовый, погашен)
```

scrypt намеренно медленный (~60 мс) — это защита пароля, не тормоз. API-ключ в БД лежит
только хэшем: даже дамп базы не выдаёт ключ.

## Акт 18. Сессии в Redis

```ts
const sessions = db.auth.sessions(redis)
const token = await sessions.start(account, { ttlSec: 3600, meta: { ip: '10.0.0.1' } })   // [1.3 ms]
await sessions.check(token)     // → { account, meta: { ip: "10.0.0.1" }, created: "…" }
await sessions.revoke(token)    // → true;  check после → null
await sessions.revokeAll(account)   // → 2  (погасили обе оставшиеся сессии)
```

Токен отдаётся один раз; в Redis лежит его sha256 — дамп Redis не раскрывает действующие
токены.

## Акт 19. Права доступа (ACL)

Ресурс-субъект (маска категорий) + ресурс-объект + правило между ними:

```ts
await db.resources.set({ alias: 'salonStaff:ACCOUNT', category: 'ACCOUNT', pattern: { categories: '{Staff}' } })
await db.resources.set({ alias: 'salon.book:API', category: 'API', pattern: { endpoint: 'salon.book' } })
await db.rules.set({ account: 'salonStaff:ACCOUNT', resource: 'salon.book:API', permission: 'allow', weight: 50 })

await db.acl.check(account, 'salon.book')   // [21.3 ms]
// → { allow: true, rule: { account: "salonStaff:ACCOUNT", resource: "salon.book:API", permission: "allow", weight: 50 } }
await db.acl.checkData(account, 'Booking', 'READ')   // → true
```

## Акт 20. Изоляция арендатора и наблюдаемость

`enforceAccount` пришпиливает каждое чтение и запись к аккаунту — арендатор видит только
своё среди миллиона чужих строк:

```ts
const iso = await connect({ dsn, schema, account: tenant, owner: tenant, enforceAccount: true })
const [своя] = await iso.Организация().set({ name: 'Частная' }).rows()
своя.account === tenant     // → true
await iso.Организация().count()   // → 1   (только своя, 30 полигонных невидимы)
```

`onQuery` даёт метрику на каждый запрос — здесь порог `slowMs: 0` пометил всё медленным:

```ts
// onQuery → { mode: "count", classes: ["Service"], ms: 14.9, rows: 1, slow: true }
```

## Акт 21. Гарды: чего сделать нельзя

Библиотека ловит ошибки рано и с понятным текстом — многие ещё **при построении
цепочки**, до похода в БД:

```ts
db.Организация(org).Услуга().set({ name: 'X', duration: -1, price: { RUB: 1 } }).rows()
// → validation failed for "Service": duration — The 'duration' field is required.  (на терминале)

db.Запись(зАни).Сотрудник()          // → no path Booking → Staff  (СИНХРОННО, до БД)
db.позиция().навык()                 // → LINK → LINK traversal is not supported
db.Запись(зАни).Сотрудник.set('x')   // → "Staff" is not a link end of "Booking"
db.Сотрудник.set('x')                // → slot "Сотрудник" needs an owner step
db.Услуга().link('X', 'y')           // → .link() removed (0.15.0) — use the link slot: .Класс.set(target)
db.Услуга().execute()                // → execute() renamed to run() (0.11.0)
```

Путь `Запись→Сотрудник` невозможен по схеме (у брони нет прямой связи с мастером — только
через позицию) — и это ошибка сразу, а не пустой результат на терминале.

## Что показал прогон

За один сквозной день салона задействованы **все 145 публичных точек API** — от
`connect`/`up` до `anonymize`, сессий и ACL (полная матрица — в `lib/TESTPLAN.md`).
Три наблюдения, ради которых стоило гонять живой миллион:

1. **Одна грамматика на чтение и запись.** Путь по `Schema.links` работает одинаково; слот
   `.Класс.set()` пишет связь, `pivot` возвращает к узлу. Ни строк-литералов классов, ни
   «магических» словарей — только вызовы, слоты и глаголы.
2. **История бесплатна и честна.** 480 000 версий броней не мешают отчётам: агрегации и
   `count()` берут актуальные версии, `asOf`/`versions` открывают прошлое, `anonymize`
   и `delete` не стирают аудит.
3. **Дорого — только «посчитать всё» (1.7 с на full-scan класса).** Точечные пути,
   фильтры по GIN, keyset-пагинация — единицы-десятки миллисекунд даже на миллионе.

Полигон и оба скрипта в репозитории — числа выше можно перепроверить одной командой.
