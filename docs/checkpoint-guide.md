# Документация для людей: сайт guide/ и сервисы-примеры

План — «документация letopis для людей», утверждён владельцем 29 октября 2026 года. Его решения:
- сайт только на русском и только локально;
- найденный баг библиотеки исправляется сразу, исправление подтверждает пример документации, который без него падает;
- новых тестов в `lib/test` нет;
- сервисы — все четыре, на блоках shadcnblocks, у каждого ручной запуск (bash и PowerShell) и Docker;
- отдельная страница «Старт с нуля».

Работа шла в ветке `dev`, от `e4119ab` (этап 0) до коммитов этого отчёта. Выпуск библиотеки не делался.

## Баги библиотеки — исправлены

Все три — в записи `1.4.1-alpha.0` файла `lib/CHANGELOG.md`. Каждый подтверждает пример, который без исправления падает.

1. **`db.auth.purgeAccount(арендатор)` из сессии, работающей в этом арендаторе,** откатывался с `tenant_denied`: функция стирала членство вызывающего, а дальше перечитывала контекст. Исправление — в `lib/sql/90-time.sql` и `lib/src/auth.ts`. Пример — `guide/examples/auth/02-sessions-tenants.ts`, шаг 8.
2. **`commit()` транзакции, в которой ошибку поймали и проглотили,** бросал сырую `25P02` вместо обещанной README `tx_rolled_back`. Исправление — в `lib/src/tx.ts`. Пример — `guide/examples/errors/01-api-errors.ts`, шаг 7.
3. **Порядок надгробий каскада.** Надгробия одного уровня каскада триггер писал вставкой без `order by`, поэтому их порядок в журнале (`seq`, время `at`) и порядок строк итога `delete({ confirm: true })` зависел от плана запроса. Предпросмотр при этом шёл по id. Теперь надгробия каждого уровня пишутся в порядке id (`lib/sql/60-write.sql`, `trg_entity_ad`), цели классов без журнала — тоже по id (`lib/src/write.ts`). Примеры — `guide/examples/delete/01-delete-cascade.ts` и `02-restore-purge.ts`: без исправления снимок разошёлся в 5 прогонах из 5, с исправлением совпал в 10 из 10. В README (раздел 7, обе версии) — порядок итога.

## Недетерминизм примеров и раннера — исправлен

Сверка снимков в CI годится, только если повторный прогон даёт тот же снимок. Расхождения находились и устранялись:
- время в снимке — метки `t1, t2…`, одна транзакция — один момент. Сначала метка ставилась на каждое различное время версии. Две версии одной транзакции изредка совпадали до микросекунды, и это сдвигало все следующие метки: так в `start/01`, где установка идёт внутри шага — десятки строк одной транзакцией;
- метки строк («Класс·N», «·2» у одноимённых) — по первому появлению в журнале. Сначала я раздавал их по рангу id, но у класса без ключа id случайный: две строки «Пётр» в `models/02` менялись метками в половине прогонов;
- длительности `ms`, ключ пары «ключ + секрет», номер шага TOTP — метки;
- `write/06`: кэш изредка не засчитывал попадание. Сигнал о записи прошлого шага приходил во время первого чтения, и кэш, защищаясь от гонки, ответ не клал. Это верное поведение библиотеки; попадания теперь считаются на свежем подключении, а сама защита описана нюансом `cache-raced`.

Найдено и исправлено на сайте:
- точка с запятой в подписи Mermaid обрывает схему;
- стиль страницы VitePress (высота строки абзаца) обрезал подписи в узлах схем.

## Вычитка понятности

Две вычитки субагентом без смены модели. Страницы глав: 40 правок, у всех 44 кодов ошибок — колонка «Что значит», в глоссарии — 17 новых терминов. Тексты примеров (заголовки, описания, пояснения шагов, комментарии в коде шагов): около 160 правок в 47 файлах из 52. Жаргон заменён терминами глоссария, а тексты сверены со снимками. Попутно поправлены неточности:
- описание `lockRetries`;
- режим сигналов `none`: кэш выключен, а не «только по сроку»;
- состав служебных объектов установки;
- текст нюанса о `no_session`: его бросает и `connect()` с неверным ключом.

Шаг `history/02` теперь показывает в результате, что `moved` новой строки — прежний id: раньше это утверждалось только словами.

## Нюансы, найденные прогонами

Прогоны примеров и сценариев вскрыли поведение, которого не было в документации. Всё описано в главе 17 или на страницах сервисов:
- погашенная сессия на чтении даёт пустой ответ, а не ошибку;
- `refresh` не укорачивает срок сессии;
- свежая сессия работает в личном арендаторе;
- второй фактор letopis не навязывает — его требует сервис;
- `reclass` в класс с ключом даёт новый id;
- прореживание по политике — не разрыв журнала для `verify()`;
- первая заливка — только в пустую схему;
- импорт проверяет всё до записи;
- `reset` уровня `tenant` стирает и членства;
- у цепочки нет `then`: `await db.Класс(…)` ничего не читает;
- `purge()` без `confirm` — только предпросмотр;
- `auth.tenants()` не упорядочен;
- `revokeAll` действует во всех компаниях пользователя;
- `createTenant` находит арендатора по имени, а название закрытой компании занято навсегда;
- ответ, на время чтения которого пришёл сигнал, в кэш не кладётся.

## Как запустить

- Весь стенд: `docker compose -f services/compose.yaml up -d --build`. Сайт с песочницей — http://127.0.0.1:8080, сервисы — 8081–8084.
- Сайт без Docker: `cd lib && npm ci && cd ../guide && npm ci && npm run build && npm run sandbox`. Подробности и меры безопасности — страница «Песочница».
- Примеры: `cd guide && npx tsx scripts/run-examples.ts [фильтр] [--check]`. Нужна тестовая база библиотеки: 127.0.0.1:15433, при наличии Docker поднимается сама.
- Сервисы руками: README в каталоге каждого сервиса.
