# Доработки после выпуска 1.2.0 (letopis 1.3)

План утверждён владельцем 28 октября 2026 года. В него вошли три направления: хвост ревью безопасности №3, автоматический
тест обновления схемы, первая заливка. Решения владельца:
- агрегат над классом, которого ещё нет, отклоняется;
- подписка получает событие удаления, когда строка уходит из класса;
- тест обновления проверяет пути с 1.1.0 и с 1.0.1;
- выпуск 1.3.0 — последний этап плана.

## Тест обновления схемы

`test/upgrade.test.ts` (снят в 2.0.0 вместе с совместимостью с 1.x). Схему ставит прежний пакет: 1.1.0 — dev-зависимость `letopis-11`, 1.0.1 — `letopis-1`.
Данные пишет прежний движок: правки, перенос по концу, удаление, каскад, `purge`, обрезка, креденшал вида `LOCK`.
Затем вызывается `up()` текущей версии. У 1.1.0 ревизия та же, 6, поэтому накат простой; у 1.0.1 — `upgrade: true` и
миграция `0006`.

Проверки:
- версии и хэши прежнего движка на месте, `verify({ data: true })` чист;
- каталог совпадает с чистой установкой: функции с правами и текстом, колонки, индексы, ограничения, триггеры,
  политики;
- строки-замки семейств созданы, строки `LOCK` чужих аккаунтов сняты;
- приложение, подписка и проектор работают по старым данным;
- повторный `up()` ничего не меняет.

Чувствительность проверена мутациями: оставленная перегрузка `watch_read` и отключённая очистка строк `LOCK` валят
тест.

## Хвост ревью безопасности №3

Все 12 кандидатов закрыты (`BACKLOG.md`, «Хвост ревью безопасности №3»). Каждое исправление закрывает тест, который без
исправления падает; это проверено отключением исправления.

| Кандидат | Исправление | Тест |
|---|---|---|
| Текст отказа называет невидимый класс | класс — только для видимых строк (`visible_class`) | `engine-attacks` №47 |
| `class_has_history` у класса System | арендаторы со своим одноимённым классом не в счёт | №48 |
| Надгробие класса | сверка и по `history`; алиас предка не меняется, пока удалённые потомки хранят историю | №49 |
| Производный класс через непроизводного предка | правка предка производного класса — право `letopis.projector` | №50 |
| `family_conflicts` | о невидимой ссылающейся строке — без роли и id | №51 |
| Агрегат над несозданным источником | отказ `invalid_class`; `syncModels` ставит источники раньше | №52, `sync` |
| Прерванная перестройка арендатора | её продвигает любой `run()` | `projector` |
| Нет `lock_timeout` у проектора | опция `lockTimeout`, 55P03 — проход пропущен | `projector` |
| `trimHistory` непрочитанных версий | `projector_pending` | `projector` |
| `as()` арендатора корня | у фасада свой реестр | `impersonation` |
| Пустой реестр `as()` | не кэшируется, контекст читается заново | `impersonation` |
| Подписка и смена класса без смены id | событие удаления в прежнем классе (`watch_leaving`) | `watch` |

Автоматическое ревью коммита `5290be1` нашло обход через удаление пустого класса-источника и создание его заново. Он
закрыт: класс `of` не удаляется, пока его называет агрегат класса того же арендатора (атака №53).

По дороге нашлись и исправлены две ошибки проектора:
- **Взаимная блокировка двух процессов.** После правки «продолжать перестройку в любом `run()`» второй процесс при
  `busy` ждал чекпоинт, пока первый держал пачку. Теперь при `busy` перестройка не трогается.
- **Гонка счётчика перестройки.** Вызов `rebuild({ tenant, chunked: true })` засчитывает перестройку, даже если
  последнюю пачку записал другой процесс.

## Первая заливка: генерируемые колонки

Бенч `lib/bench/gencols.bench.mjs`: 100 тысяч строк формы полигона, медиана трёх кругов
(`lib/bench/results/gencols.json`).

| Функция | Время, мс |
|---|---|
| просмотр таблицы | 14 |
| `link_ids` (SQL-тело с подзапросом) | 206 |
| `link_ids` на plpgsql с быстрым путём для пустых концов | 170 |
| `snapshot` (`jsonb_build_array(...)::text`) | 251 |
| `snapshot` сборкой текста | 471 |
| `version_hash` вместе со `snapshot` | 290 |

Оба кандидата побайтно совпадают с установленными функциями. `snapshot` сборкой текста медленнее и отклонён.
`link_ids` на plpgsql быстрее на 17 %, но тоже отклонён. Его имена разрешались бы по `search_path` сеанса приложения:
колонку `ends` вычисляет роль приложения, и подменённая функция дала бы фальшивые концы (ревью безопасности, ниже).
Выигрыш при этом меньше секунды на первой заливке. Тест `lib/test/engine-write.test.ts` (до 2.0.0 — `test/hash.test.ts`) сторожит тело
`link_ids` от будущих правок.

Вывод. На полном полигоне функции генерируемых колонок стоят около 10 секунд из 73–78:
- `link_ids` — около 4 с (колонка `ends` и индекс `log_ends`);
- `snapshot` и `version_hash` у двух таблиц — около 6 с.

Профиль 1.2 приписывал генерируемым колонкам около 45 % занятости серверного процесса. Замер по функциям показывает
меньше: остальное — разбор входа `COPY` (jsonb, uuid, время), запись страниц и WAL. Решения владельца в силе: потоки и
параллельный `COPY` не делаются, `FREEZE` остаётся.

Бенч `lib/bench/initial-load.mjs`, полный полигон (1 073 580 объектов), три круга
(`lib/bench/results/initial-load-regular-initial.json`):

| | Время, медиана | Круги | WAL |
|---|---|---|---|
| обычный загрузчик | 210,4 с | 192,4–212,9 с | 4 014 МБ |
| первая заливка | 70,8 с (загрузка 61,4 с, остальное 9,4 с) | 65,9–75,0 с | 1 394 МБ |

Отношение — 2,97 раза. Перед этим тот же бенч с вариантом `link_ids` на plpgsql дал 72,8 с против 214,8 с (2,95 раза):
разница вариантов — в пределах разброса кругов.

Цель «втрое быстрее обычного загрузчика» не достигнута: первая заливка быстрее в 2,9–3,0 раза, и отношение колеблется
вместе с обычным загрузчиком. Её предел — запись `COPY` на сервере.

## Ревью безопасности

Ревью диффа `24be7bb..HEAD` делал субагент без смены модели. Обхода прав и межарендаторной утечки он не нашёл. Три
находки с уверенностью от 7 исправлены в `82f58f9`:
1. **Подписка теряла событие.** `watch_read` и `watch_leaving` шли двумя запросами с разными горизонтами, и курсор мог
   перескочить событие, зафиксированное между ними. Теперь это один оператор с общим снимком.
2. **Новый класс узнавался перебором классов подписки.** Это касалось и автора невидимой новой версии. Теперь
   невидимая новая версия даёт надгробие при любых классах подписки и без автора.
3. **`link_ids` на plpgsql разрешал имена по `search_path` сеанса.** Возвращено SQL-тело.

Заодно взято замечание ниже 7: обрезка проверяет курсор по самой поздней по `(tx, seq)` версии у стыка. Остальные
замечания ниже 7 записаны в `BACKLOG.md`, раздел «Хвост ревью безопасности доработок после 1.2.0».

`/security-review` по диффу `main..HEAD` (после исправлений) уязвимостей уровня HIGH и MEDIUM не нашёл. Ниже порога он
назвал ловушку агрегата через потомка источника, созданного позже, и одноимённые классы System и арендатора в плане
прав. Обе — в `BACKLOG.md`.
