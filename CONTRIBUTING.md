# Как участвовать в letopis

## Что где лежит

- `lib/` — npm-пакет `letopis`: код (`src`), движок в базе (`sql`), сценарии проверок (`scripts`), замеры (`bench`),
  документация пакета (`README.md`, памятка для агентов, `CHANGELOG.md`).
- `guide/` — сайт документации с исполняемыми примерами, только локально и на русском.
- `services/` — четыре сервиса-примера на letopis и стенд `services/compose.yaml`.
- `docs/` — отчёты о проверках и атлас кода (`docs/atlas`); `reports/` — планы.
- Карта проекта для людей и агентов — [AGENTS.md](AGENTS.md): модули, процессы, что где менять.

## Что нужно

- Node 22 или новее, Git.
- Docker: PostgreSQL 18 для проверок — контейнер `letopis-pg18`, порт 15433
  (`docker run -d --name letopis-pg18 -e POSTGRES_PASSWORD=<пароль> -e POSTGRES_DB=letopis -p 15433:5432 postgres:18`);
  строку подключения задаёт переменная `ENTITY_DSN`.

## Чем проверяется проект

Unit-тестов в проекте нет. Поведение проверяют программы, которые работают с настоящим PostgreSQL 18 через публичное
API:

| Что | Команда | Что проверяет |
|---|---|---|
| типы | `cd lib && npm run typecheck:all` | исходники `src` и замеры `bench` |
| документы | `cd lib && npm run check:docs` | версия, ссылки и якоря, контракт API, шаг версии, зарезервированные имена, каталог ошибок, таблицы операторов |
| памятка | `cd lib && npm run cheatsheet` | программа из `lib/AGENT-CHEATSHEET.md` идёт дважды подряд в чистом доме |
| примеры сайта | `cd guide && npm ci && npm run examples -- --check` | каждый пример исполняется, вывод сверяется со снимком |
| всё перед выпуском | `cd lib && npm run prerelease` | шаги выше, песочница сайта, сценарии четырёх сервисов, долгий прогон, проверка пакета |

Стенд с сайтом и сервисами — `docker compose -f services/compose.yaml up --build` (127.0.0.1:8080–8084).

## Перед пулл-реквестом

В CI идут только проверка типов, сверка документов и проверка пакета. Всё, что проверяет поведение, запускается
локально одной командой:

```sh
cd lib && npm run prerelease
```

Шаги идут по очереди, первый красный останавливает прогон.

## Правила

- **Исправление.** К исправлению прилагается программа, которая без него падает: пример сайта со снимком, шаг
  сценария сервиса или блок программы памятки. Она проверяет поведение через публичное API на настоящем PostgreSQL, а
  не внутренности. Unit-тесты не пишутся.
- **Документация пакета.** Только на русском и только о нынешней версии: `lib/README.md`, памятка
  `lib/AGENT-CHEATSHEET.md` и `lib/llms.txt`. Приглашения, вход и права описаны один раз — в README; памятка даёт
  рабочую выжимку, `llms.txt` — указатель.
  Сверку с кодом делает `cd lib && npm run check:docs`.
- **Контракт API.** Изменились экспорты, методы или тексты ошибок — `cd lib && npm run api:contract`.
- **Версии.** Правила — раздел «Версии и совместимость» в `lib/README.md`; шаг версии проверяет `npm run check:semver`.
- **CHANGELOG.** У правки ядра (библиотеки и SQL) в конце пункта — источник находки: пример, сервис, ревью,
  soak или внедрение.
- **Ветки.** Работа идёт в ветке `dev`, в `main` — только пулл-реквест из `dev`. Выпускает владелец.

## Сообщить об ошибке или о внедрении

- Ошибка — issue по шаблону: версии letopis, PostgreSQL и Node, минимальная цепочка, `err.code` и текст ошибки.
- Внедрение — issue с описанием задачи, версий и того, что мешало.
