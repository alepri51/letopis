# Как участвовать в letopis

## Что где лежит

- `lib/` — npm-пакет `letopis`: код (`src`), движок в базе (`sql`), тесты (`test`), замеры (`bench`), документация пакета
  (`README.md`, шпаргалка для агентов, `CHANGELOG.md`).
- `guide/` — сайт документации с исполняемыми примерами, только локально и на русском.
- `services/` — четыре сервиса-примера на letopis и стенд `services/compose.yaml`.
- `docs/` — отчёты о проверках и атлас кода (`docs/atlas`); `reports/` — планы.
- Карта проекта для людей и агентов — [AGENTS.md](AGENTS.md): модули, процессы, что где менять.

## Что нужно

- Node 22 или новее, Git.
- Docker: тесты сами поднимают контейнер PostgreSQL 18 (`letopis-pg18`, порт 15433).

## Как запустить

```sh
cd lib && npm ci && npm test                         # тесты библиотеки
cd guide && npm ci && npm run examples -- --check    # примеры сайта против снимков
docker compose -f services/compose.yaml up --build   # сайт и сервисы на 127.0.0.1:8080–8084
```

## Перед пулл-реквестом

В CI тестов нет: всё, что проверяет поведение, запускается локально одной командой.

```sh
cd lib && npm run prerelease
```

Шаги идут по очереди, первый красный останавливает прогон.

## Правила

- **Исправление.** Тест на исправление называется пунктом тест-плана (например, «план 2.0, 7.3 №1») и без исправления
  падает. Тест проверяет поведение через публичное API на настоящем PostgreSQL, а не внутренности.
- **Документация пакета.** Только на русском: `lib/README.md`, шпаргалка `lib/AGENT-CHEATSHEET.md` и `lib/llms.txt`.
  Сверку с кодом делает `cd lib && npm run check:docs`.
- **Контракт API.** Изменились экспорты, методы или тексты ошибок — `cd lib && npm run api:contract`.
- **Версии.** Правила — раздел «Версии и совместимость» в `lib/README.md`; шаг версии проверяет `npm run check:semver`.
- **CHANGELOG.** У правки ядра (библиотеки и SQL) в конце пункта — источник находки: тест, пример, сервис, ревью,
  soak или внедрение.
- **Ветки.** Работа идёт в ветке `dev`, в `main` — только пулл-реквест из `dev`. Выпускает владелец.

## Сообщить об ошибке или о внедрении

- Ошибка — issue по шаблону: версии letopis, PostgreSQL и Node, минимальная цепочка, `err.code` и текст ошибки.
- Внедрение — отчёт по форме [docs/adoption/TEMPLATE.md](docs/adoption/TEMPLATE.md).
